# hnsw-approximate-nearest-neighbor-search

## Summary

Fast approximate nearest-neighbor search over large spectral embedding libraries using hnswlib's hierarchical navigable small-world (HNSW) graphs, as used by FastEI to match EI mass spectra against a million-scale in-silico library (~2.15M molecules) in milliseconds instead of exact-search seconds.

## When to use

Use when searching a large library (millions) of spectral embeddings for nearest neighbors where exact search (e.g., weighted cosine similarity via faiss.IndexFlatL2) is too slow and approximate search accuracy loss is acceptable.

## When NOT to use

- Library is small enough that exact nearest-neighbor search (e.g., weighted cosine similarity via faiss.IndexFlatL2) is tractable and maximum accuracy is required — HNSW trades a small accuracy cost for speed
- Query spectra are not transformed into the same Word2vec embedding space as the index (e.g., raw peak intensities or weighted-binned spectra), which would make HNSW neighbors meaningless for accuracy (BH-style runs stay at WCS-level accuracy)

## Inputs

- Spectral embeddings of library molecules (generated by summing peak embeddings from references_word2vec.model via gensim)
- Query spectral embeddings (e.g., over ten thousand measured NIST 2017 test-set spectra)
- Prebuilt HNSW index file references_index.bin (from Zenodo record 7293922)
- Expanded-library spectra for incremental index updates (106,526 predicted spectra from f-HMDB and extra test set)

## Outputs

- Top-k neighbor lists (candidate compound IDs and ranks) per query spectrum
- recall@1, recall@10, recall@20 and per-query matching time metrics
- Benchmark result files such as benchmark_results.csv and hybrid_matching_results.csv
- Persisted HNSW index files (references_index.bin)

## How to apply

Transform each spectrum into a low-dimensional embedding by summing Word2vec peak embeddings (model trained with gensim on 2,123,695 predicted spectra). Build an HNSW index over the library embeddings with hnswlib using M = 64, efConstruction = 600, and ef = 300, then query it with test-set embeddings and record recall@1/recall@10 and per-query matching time. The index supports incremental updates (add_items with new labels), which is how the 106,526-spectra expansion from f-HMDB and the extra test set was accommodated. For ablation, contrast BH (weighted spectral binning + HNSW) against EC (Word2vec embeddings + cosine similarity via faiss.IndexFlatL2) to show HNSW contributes speed while embeddings contribute accuracy. Save query results and benchmark metrics (e.g., hybrid_matching_results.csv, benchmark_results.csv) for validation against reported values.

## Related tools

- **hnswlib** (Builds and queries the HNSW approximate nearest-neighbor index (M = 64, efConstruction = 600, ef = 300) over spectral embeddings; supports incremental index updates) — https://github.com/nmslib/hnswlib
- **gensim** (Trains/loads the Word2vec model used to produce the embeddings that populate and query the HNSW index)
- **FastEI** (Pipeline embedding HNSW search for ultra-fast spectral matching against the million-scale in-silico library (test.py harness)) — https://github.com/Qiong-Yang/FastEI
- **faiss.IndexFlatL2** (Exact Euclidean-distance baseline (weighted cosine similarity / EC ablation) used to quantify HNSW's speed advantage)

## Examples

```
import hnswlib; idx = hnswlib.Index(space='l2', dim=dim); idx.load_index('data/references_index.bin'); idx.set_ef(300); labels, dists = idx.knn_query(query_embeddings, k=10)
```

## Evaluation signals

- Full-pipeline FastEI on the test set reaches recall@1 of 36.7% (36.4% on the expanded 2,253,216-molecule library) and recall@10 near 80.4% (~79.9% expanded), with matching time ~0.0046 s per spectrum
- BH ablation (weighted binning + HNSW) should show speed improvement but WCS-level accuracy, while EC (embeddings + exact cosine) should match FastEI accuracy only at WCS-like speed — confirming HNSW's role is speed, not accuracy
- HNSW speed contrast: ~0.0046 s (FastEI) vs ~2.6368 s (exact WCS via faiss.IndexFlatL2) per query, roughly two orders of magnitude
- Index parameters must be M = 64, efConstruction = 600, ef = 300, consistent with hnswlib defaults being overridden in the paper
- On the 10-compound extra test set, FastEI over the million-scale library gives 50% recall@1, 70% recall@10, 90% recall@20

## Limitations

- Approximate search yields slightly lower recall than exact search; on the expanded library recall@1 drops from 36.7% to 36.4% and matching time increases slightly
- ef parameter is not persisted in the saved index — it must be reset manually (set_ef) after loading references_index.bin
- FastEI standalone install version only supports Windows 64-bit (tested on Windows 7 and 10)
