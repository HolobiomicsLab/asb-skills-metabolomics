# restful-api-implementation-for-bgc-metadata

## Summary

Implements the REST-like web API layer that serves MIBiG BGC annotation metadata from a PostgreSQL relational database, replacing static HTML page storage and feeding the AngularJS single-page repository UI.

## When to use

Use when building or extending a REST-like API that serves structured BGC annotation metadata from a relational database backend for a repository-style web front end.

## When NOT to use

- When only consuming MIBiG data programmatically (e.g. downloading entries for homology searches as in Bahram et al.) rather than implementing or hosting the API server itself
- When the goal is generating individual BGC detail pages — that is handled by the customised antiSMASH 5 sideload module, not the API layer
- When the metadata source is not a relational database backend (the API is built specifically around PostgreSQL access)

## Inputs

- Curated MIBiG 2.0 BGC entries (2021 entries, JSON-formatted data standard validated against the JSON schema)
- SQL schema for the MIBiG Repository published in the mibig-secmet GitHub organisation
- MIBiG annotation files (JSON) to be sideloaded by the antiSMASH 5 module for BGC page generation

## Outputs

- REST-like web API server (Go, mibig-api) exposing MIBiG annotation metadata
- PostgreSQL relational database populated with MIBiG 2.0 entries
- API-served metadata consumed by the AngularJS single-page repository UI for filtering, sorting and Boolean queries

## How to apply

Load the curated MIBiG entries into a PostgreSQL relational database using the SQL schema published in the mibig-secmet GitHub organisation, replacing the previous static HTML page storage. Implement the REST-like web API (mibig-api) in Go — the README requires a recent Go 1.11.x or later toolchain for its dependency handling — so it handles access to the underlying PostgreSQL database and serves annotation metadata for the repository rows. Expose the API endpoints consumed by the single-page AngularJS application, which supports filtering and sorting of repository rows by annotation metadata (compound names, taxonomic identifiers, biosynthetic classes) and building of Boolean queries such as 'find all complete RiPP BGCs from the genus Streptomyces'. Wire the front end's link-outs to the BGC detail pages generated by the customised antiSMASH 5 sideload module and to chemical structure databases added in MIBiG 2.0. Success is judged by the components matching the article's described architecture — relational database backend, REST-like API, AngularJS UI with filtering/sorting — rather than a numeric metric.

- All four architectural components are present and functional: PostgreSQL backend, REST-like API, AngularJS single-page UI, and antiSMASH 5 sideload-generated BGC pages
- Rows on the 'Repository' page can be filtered and sorted based on annotation metadata such as compound names, taxonomic identifiers and biosynthetic classes
- A representative Boolean query ('find all complete RiPP BGCs from the genus Streptomyces') executes against the API-served data
- The API server builds under Go 1.11.x or later, per the README dependency-handling requirement
- Served data matches the entries loaded into PostgreSQL via the published SQL schema from the mibig-secmet GitHub organisation

## Limitations

- The mibig-api README is minimal — it only specifies the Go 1.11.x toolchain requirement and Apache License 2.0, so endpoint details must be inferred from the codebase itself
- The MIBiG entry submission workflow (accession request, staff approval, extended entry form) is a curation-side process and is not part of the API implementation
- No changelog is available for the mibig-api repository, so version-to-version behaviour of the API cannot be tracked from the provided context
