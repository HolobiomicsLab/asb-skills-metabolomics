# Cross-dataset MS alignment benchmarking

## Summary

Benchmark a candidate LC-MS dataset alignment tool (e.g. metabCombiner) against a reference aligner (Eclipse MSAligner) on the same multi-dataset set, quantifying recovered overlapping annotations and spurious annotation-mismatch hits, and testing order dependence when datasets are combined sequentially.

## When to use

Use when you must reproduce or extend a head-to-head comparison of LC-MS alignment tools (e.g. metabCombiner vs Eclipse) on multiple same-method datasets and report overlap and spurious-match counts.

## When NOT to use

- Input data has not yet been conformed to the shared feature/injection schema and lacks Annotation_ID labels for cross-referencing alignments
- You have only two datasets and no reference alignment to benchmark against — a direct alignment, not a benchmarking comparison, is what is needed
- Datasets were generated by different LC-MS methods; both Eclipse and this comparison target same-method nontargeted LCMS datasets

## Inputs

- Feature tables for the datasets to be aligned (e.g. DS1–DS4), conformed to the bmxp shared schema (Feature Metadata indexed on Compound_ID; Injection Metadata on injection_id)
- Merged Feature Metadata + Feature Abundances tables (Compound_ID x injection_id pivot), as required by Eclipse/Blueshift
- Reference alignment output from Eclipse MSAligner clique mode on the same datasets
- Supplementary Code scripts specifying tool parameters (e.g. S5/S6 for metabCombiner)

## Outputs

- Comparison CSV (e.g. metabcombiner_vs_eclipse_comparison.csv) with per-tool match counts, spurious annotation-mismatch hit counts, and order-dependence outcomes
- Tallies of overlapping annotations matched (e.g. 362 of 381) and spurious hits per tool (e.g. metabCombiner 26 vs Eclipse 3)

## How to apply

First conform the feature tables to the bmxp shared schema — Feature Metadata indexed on Compound_ID, Injection Metadata on injection_id — merging Feature Metadata with Feature Abundances as required by alignment modules like Eclipse. Run the candidate tool (metabCombiner) on the datasets (DS1–DS4) in intersection mode, combining them through a fixed dataset sequence per the Supplementary Code S5/S6 scripts. Run the reference aligner (Eclipse MSAligner, a graph-based approach for n > 2 datasets) on the same datasets to produce the reference alignment. Cross-reference aligned features via Annotation_ID and tally overlapping annotations recovered versus spurious annotation-mismatch hits. Finally, re-run the candidate with permuted dataset orders to expose order dependence in sequential combination.

## Related tools

- **metabCombiner** (Candidate alignment tool run on DS1–DS4 in intersection mode with permuted dataset orders to test order dependence)
- **Eclipse** (Reference aligner (MSAligner clique mode) providing the ground-truth alignment for cross-referencing via Annotation_ID) — https://github.com/broadinstitute/bmxp
- **bmxp** (Provides the shared schema (FMDATA/IMDATA) and Feature Metadata + Feature Abundances merge format the datasets must be conformed to before alignment) — https://github.com/broadinstitute/bmxp
- **Python** (Implementation environment for running the tools, computing the cross-reference tallies, and writing the comparison CSV) — https://github.com/broadinstitute/bmxp

## Examples

```
from bmxp.eclipse import MSAligner; aligner = MSAligner(); aligned = aligner.align(merged_fmd_and_abundances)
```

## Evaluation signals

- Candidate tool recovers the same number of overlapping annotations as the reference (e.g. 362 of 381, matching Eclipse clique mode)
- Spurious annotation-mismatch hit counts are tallied per tool and differ as expected (metabCombiner 26 vs Eclipse 3)
- Permuting the dataset combination order changes the candidate's results, reproducing the reported order dependence
- All aligned features cross-reference cleanly against the Eclipse reference via Annotation_ID with no unmatched keys
- Output CSV contains per-tool match counts, spurious-hit counts, and order-dependence outcomes with no missing rows

## Limitations

- metabCombiner produced many more spurious hits than Eclipse (26 vs 3) and its results depended on the order in which datasets were combined
- No version numbers are specified for bmxp or its modules, complicating exact reproduction
- The shared schema's column labels are mutable (bmxp.FMDATA/IMDATA dictionaries can be changed globally), so schema mismatches must be checked before alignment
