# gev-extreme-value-pvalue-calibration

## Summary

In mPLAGE (PALS implementation of PLAGE), p-values for metabolite sets are calibrated by fitting a generalised extreme value (GEV) distribution, with parameters estimated by maximum likelihood, to the extreme t-statistics generated under a sample-label permutation null.

## When to use

Use when ranking metabolite sets by activity-level significance after SVD decomposition, and an empirically calibrated p-value is needed for the extreme t-statistics produced by a permutation test.

## When NOT to use

- The ranking method is ORA or GSEA rather than mPLAGE/PLAGE — the GEV calibration of extreme permuted t-statistics is specific to the mPLAGE workflow
- Peak features lack compound annotations (KEGG or ChEBI IDs) — unannotated peaks are not used for pathway analysis, so SVD and the resulting p-value would be unreliable
- A permutation null cannot be generated (e.g. insufficient samples to shuffle group labels for the case/control comparison)

## Inputs

- Standardised (zero mean, unit variance) log2-transformed intensity matrix of annotated peak features, e.g. notebooks/test_data/HAT/int_df.csv
- Peak-to-compound annotation table mapping feature IDs to KEGG or ChEBI IDs, e.g. notebooks/test_data/HAT/annotation_df.csv
- Permutation null of t-statistics on the first metacompound, generated by shuffling sample group labels per comparison

## Outputs

- GEV-calibrated p-value per metabolite set (pathway), per comparison
- Pathway ranking table (e.g. test_output.csv) with p-value columns plus unq_pw_F, tot_ds_F and F_coverage coverage columns

## How to apply

First derive activity levels: for each metabolite set in the pathway database (e.g. PiMP_KEGG), extract the standardised intensity matrix of its annotated features and compute its singular value decomposition, taking the first metacompound (leading singular vector) as the set's activity levels. Compute two-sample t-statistics on the first metacompound for each specified comparison (e.g. Stage_1/Control and Stage_2/Control). Build a permutation null by repeatedly shuffling sample group labels and recomputing the t-statistics per comparison. mPLAGE then models the minimum and maximum t-statistics from each permutation test using the generalised extreme value (GEV) distribution, with parameters fitted by maximum-likelihood estimation, and uses the fitted GEV to calibrate the final p-value for each pathway. Finally rank pathways by the calibrated p-value columns, retaining coverage columns (unq_pw_F, tot_ds_F, F_coverage) in the output table.

## Examples

```
python pals/run.py PLAGE notebooks/test_data/HAT/int_df.csv notebooks/test_data/HAT/annotation_df.csv test_output.csv --db PiMP_KEGG --comparisons Stage_1/Control Stage_2/Control
```

## Evaluation signals

- The final pathway table can be sorted by the GEV-calibrated p-value columns, as documented in the README output
- Coverage columns unq_pw_F, tot_ds_F and F_coverage are present alongside the p-value columns in the ranking output
- GEV parameters are fitted by maximum-likelihood estimation to the extreme (minimum and maximum) permuted t-statistics, not to raw permutation draws
- Permutation null is reproducible: t-statistics recomputed on the first metacompound after each shuffle of sample group labels
- Run completes for the HAT example data with the comparisons Stage_1/Control and Stage_2/Control written to test_output.csv

## Limitations

- mPLAGE is claimed to be more robust to missing features and noisy data than ORA and GSEA, but it still relies on annotated features only; unannotated peaks are excluded
- The permutation-based calibration requires repeated label shuffling per comparison, so runtime scales with the number of permutations and the number of pathways queried
- No software version numbers or changelog were stated for the PALS release used, so exact behaviour of the GEV fit may vary across versions
