# median-rank-statistic-computation

## Summary

Computes the median rank of a candidate molecular formula across individual peak lists from an IDSL.IPA workflow on untargeted LC/HRMS data, then aggregates ranks into an aligned annotated peak table so annotation quality (e.g. median rank ≤ 2 or ≤ 5) can be reported sample-wise.

## When to use

Use when you have IDSL.IPA-generated individual peak lists plus an aligned peak table and need to summarize which molecular formula hits from IDSL.UFA are reproducibly ranked near the top across samples before downstream reporting or MS/MS cross-checking.

## When NOT to use

- You only have a single MS2 spectrum or DDA/DIA fragment spectrum to annotate — use IDSL.CSA or a spectral-library search instead; this skill summarizes MS1-derived formula ranks across samples.
- The input is already a curated feature table with structural identifications and no IDSL.IPA/UFA pipeline output — re-deriving median ranks adds no information.
- You need exhaustive elemental-composition enumeration rather than ranking of candidate formulas against an IPDB — use IDSL.UFAx.

## Inputs

- Individual peak lists (m/z–RT per sample) generated by the IDSL.IPA workflow
- Aligned peak table from IDSL.IPA peak_alignment directory
- IDSL.UFA parameter spreadsheet (UFA_parameters.xlsx) with PARAM0005 and PARAM0006 set to YES
- Isotopic Profile DataBase (IPDB, .Rdata) such as RefMet from IDSL.ExposomeDB (209,592 positive / 129,122 negative ion formulas)
- MS1 raw files (mzXML, mzML, netCDF)

## Outputs

- Aligned annotated peak table with per-peak molecular formula hits, ranks, detection frequency, and median rank
- Summary statistics of formula rank and frequency usable for reporting or downstream filtering

## How to apply

Run the IDSL.IPA workflow on each raw file to obtain individual peak lists and an aligned peak table, then annotate with IDSL.UFA using an isotopic-profile database (IPDB, e.g. RefMet from IDSL.ExposomeDB) so each peak's formula hits are ranked per data file. For each formula hit on the aligned table, collect its rank in each individual sample's peak list and compute the median of those ranks, alongside the detection frequency. Report or filter hits using these statistics — the paper uses a median rank ≤ 5 to report annotated aligned peaks, and a stricter median rank ≤ 2 to define the top-hit subset validated against MS/MS-confirmed formulas (e.g. 78.75% of 73 MS/MS-confirmed hits in ST002044 had median rank ≤ 2). Set PARAM0006 in the UFA parameter spreadsheet to YES to enable this aligned-table aggregation; median rank is reported on the aligned annotated table.


## Evaluation signals

- Aligned table rows show a numeric median-rank column consistent with per-sample ranks (median of individual ranks, not a re-ranked aggregate).
- Setting PARAM0005/PARAM0006 to YES must populate the aligned annotated peak table; leaving it NO should yield no aligned annotation output.
- MS/MS-validated subset check: with an aligned table from IDSL.ExposomeDB IPDB on ST002044, ~78.75% of the 73 MS/MS-confirmed formula hits should carry median rank ≤ 2.
- Detection frequency per formula should be reported alongside median rank and should be ≥ 1 only for formulas detected in at least one sample.
- Cross-check reported hits against a median-rank ≤ 5 cutoff; formulas above this threshold should be excluded from the reported annotated aligned table.

## Limitations

- Median rank is a MS1-based statistic; it cannot by itself confirm structural identity and should be complemented by MS/MS or isotopic-profile match figures.
- Results depend on the IPDB chemical space used (e.g. IDSL.ExposomeDB vs other formula sources); a different IPDB changes ranks and coverage.
- Large-sample studies require parallel processing (PARAM0008) and adequate compute; the paper reports performance at population scale (n > 500).
- The MS/MS cross-validation fraction reported (78.75%) is study- and IPDB-specific and may not transfer to other datasets.
