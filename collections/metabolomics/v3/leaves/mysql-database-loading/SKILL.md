# mysql-database-loading

## Summary

Loads the RaMP MySQL relational database — built from HMDB, KEGG, Reactome, and WikiPathways analyte-pathway relations — onto a local MySQL server so it can be queried with the RaMP R package. This is the step that turns generated SQL files into a queryable pathway-annotation database.

## When to use

Reference for recreating the RaMP MySQL schema locally: you have parsed HMDB/KEGG/Reactome/WikiPathways source data into SQL files and need a populated MySQL instance queryable via RMySQL.

## When NOT to use

- You only need to query RaMP annotations, not rebuild the database — use the pre-built mysql dump or RaMP-DB 3.0 SQLite download instead of re-running the ingestion pipeline
- Your workflow targets RaMP-DB 3.0, which ships an SQLite database downloaded via BiocFileCache rather than a MySQL server import

## Inputs

- SQL files generated by RaMP-BackEnd main.py in misc/sql folder (unified analyte, pathway, and analyte-pathway relations)
- Pre-built mysql dump file from github.com/Mathelab/RaMP-DB/tree/master/inst/extdata
- Empty MySQL database instance on a local server (e.g. named 'ramp')

## Outputs

- Populated MySQL relational database containing RaMP IDs, synonyms, pathways, and analyte-pathway mappings from HMDB, KEGG, Reactome, and WikiPathways
- MySQL instance queryable via the RaMP R package (connectToRaMP with dbname, username, conpass, host)

## How to apply

Clone the RaMP-BackEnd repository and run main.py, which generates the SQL files in the misc/sql folder from the parsed source downloads (HMDB XML, KEGG REST responses, Reactome mapping files, WikiPathways GPML). Create an empty database on the local MySQL server (e.g. named 'ramp'), then bulk-import the SQL files using Program.cs from the mySQLBulkCsharp folder. The unified analyte, pathway, and analyte-pathway relations — including synonyms merged into common RaMP IDs across the four sources — land in the MySQL relational schema. Alternatively, load the pre-built mysql dump from Mathelab/RaMP-DB inst/extdata directly into MySQL, then connect with connectToRaMP(dbname, username, conpass, host) using the RMySQL-backed RaMP R package.

## Related tools

- **RaMP-BackEnd** (Python pipeline (main.py) that generates the SQL files imported into MySQL) — https://github.com/Mathelab/RaMP-BackEnd
- **MySQL** (Local relational database server holding the populated RaMP schema)

## Examples

```
git clone github.com/Mathelab/RaMP-BackEnd; python main.py; # then import misc/sql files via mySQLBulkCsharp/Program.cs into empty MySQL db 'ramp'
```

## Evaluation signals

- main.py completes successfully and produces SQL files in the misc/sql folder before import
- The empty MySQL database (e.g. 'ramp') accepts all SQL files imported via mySQLBulkCsharp's Program.cs without import errors
- The mysql dump file reloads into a MySQL instance
- After loading, batch RaMP queries listing pathway memberships for genes and metabolites return results via connectToRaMP(dbname, username, conpass, host)
- Identifiers linked to common IDs resolve to the same internal RaMP ID across source databases

## Limitations

- The RaMP-BackEnd scripts are the database-creation code only — 'the files here are NOT RaMP but merely the scripts used to create RaMP'
- Python 3.5 is required; on MacOS both python 2.7 (system-dependent) and 3.5 must run simultaneously
- The Mathelab/RaMP-DB repository is no longer maintained; users are directed to https://github.com/ncats/RaMP-DB/
- Source databases are checked for updates multiple times a year, so a locally loaded snapshot can become stale
