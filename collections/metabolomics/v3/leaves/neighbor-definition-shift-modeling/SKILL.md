# neighbor-definition-shift-modeling

## Summary

Defines k nearest neighbors among candidate matched feature pairs to model the expected inter-dataset shift in retention time (and optionally m/z and feature intensity) between two LC–MS metabolomics feature tables, distinguishing the 'cross' (per-dimension neighbors, one shift per RTref) and 'circle' (normalized Euclidean RT+MZ distance, multiple shifts at the same RTref) mechanisms.

## When to use

Use when two peak-picked LC–MS feature tables (RT, m/z, FI per feature) must be matched across datasets and you need a robustly determined expected shift at each reference feature's RT before applying residual-threshold matching.

## When NOT to use

- When only a single retention-time drift function is expected across the whole m/z range and no co-eluting features with divergent drift exist — a simple global RT alignment suffices, e.g. metabCombiner's robust RT shift model.
- When candidate matches have not yet been generated by threshold-based RT/MZ/FI screening — applying neighbor modeling directly to raw peak lists without prior candidate filtering will be dominated by spurious neighbors.
- When features lack reliable retention-time information (e.g. direct-infusion MS), since both 'cross' and 'circle' definitions key on RTref neighborhoods.

## Inputs

- Two peak-picked LC–MS feature tables (reference and target), each with columns RT, m/z, and FI (e.g. exported from XCMS)
- Initial candidate match list of feature pairs within user-defined RT, MZ, and log10FI thresholds
- Neighbor count k and per-dimension distance-normalization settings

## Outputs

- Smoothed expected inter-dataset shift curve over RTref (per method: 'cross' vs 'circle')
- Residuals of each candidate match's observed RT/MZ/FI relative to the modeled shift
- Per-match assignment distinguishing one shift per RTref ('cross') vs multiple coexisting shifts at the same RTref ('circle')

## How to apply

After initial candidate matching with user-defined RT, MZ, and log10FI thresholds (e.g. RT within 1 min, MZ within 0.025 Da), collect candidate feature pairs and fit the shift model using one of two neighbor definitions. In the 'cross' method, k nearest neighbors are found separately per dimension (RT, then MZ, then FI), smoothed, and combined so that all matches sharing an RTref receive a single robustly determined inter-dataset shift (the row-2 behavior in Figure 3). In the 'circle' method, neighbors are chosen by normalized Euclidean distance over RT and MZ (not FI), allowing features at the same RTref but different MZref to have distinct shifts, which handles co-eluting features whose MZ-dependent drift differs. Decision point: choose 'cross' when shift behavior is uniform across m/z at a given RT, and 'circle' when multiple shifts can coexist at the same RTref. Residuals between observed and modeled shifts then feed the unique-correspondence step, and the two methods' shift curves should be compared before committing.

## Evaluation signals

- The 'cross' method must yield a single, smoothly varying shift value shared by all candidate matches at a given RTref (row 2 of Figure 3), while the 'circle' method must show multiple distinct shift values at the same RTref when MZref differs.
- Residuals (observed minus modeled shift) for true matches should cluster tightly around zero in both RT and MZ dimensions; systematic residual trends indicate the wrong neighbor definition or a missing dimension.
- Downstream unique-correspondence output should reproduce the reported match statistics when the full M2S pipeline (e.g. MESA as reference, Rotterdam as target) is followed — e.g. 4953 uniquely matched features with 96.8% of 604 annotated features correct in the main example.
- Comparison with metabCombiner on three other dataset pairs should show the advantages of the neighbor-based approach, not worse matching.
- Changing k or switching between 'cross' and 'circle' should visibly alter the smoothness of the shift curve and the residual distribution; results should be insensitive to reasonable k changes, otherwise the model is under- or over-fitting.

## Limitations

- Both neighbor definitions depend on well-populated candidate match lists; if the initial RT, MZ, and log10FI thresholds are too tight, too few neighbors exist and the shift model becomes unstable.
- Most missed annotated matches are between features that behave very differently from the modeled inter-dataset shifts of RT, MZ, and FI — features with atypical drift are systematically dropped.
- Threshold selection is subjective and guided by visual inspection of the distance plots resulting from the initial matching.
- Optional poor-match deletion (step 3) may inadvertently delete some correct matches.
- M2S was demonstrated on extensively annotated cohorts (MESA as reference with 2656 samples, Rotterdam as target with 1057 samples) and has no stated software version.
