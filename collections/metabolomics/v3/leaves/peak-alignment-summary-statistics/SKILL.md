# peak-alignment-summary-statistics

## Summary

Aggregates per-sample molecular formula annotation lists from IDSL.UFA into an aligned annotated peak table, summarizing each candidate formula per aligned peak by detection frequency (number of samples annotated) and median rank across samples, then re-ranking formulas by these statistics.

## When to use

Use when you have per-file IDSL.UFA formula annotation peaklists plus an IDSL.IPA aligned peak table and need one summarized, ranked formula annotation per peak across all samples.

## When NOT to use

- Input is already an aligned annotated peak table — re-running aggregation would double-count statistics
- Only a single-sample peaklist exists (no cross-sample aggregation is meaningful; use the individual peaklist ranking instead)
- You need peak detection/alignment itself — that is IDSL.IPA's role, upstream of this summarization step

## Inputs

- Per-file formula annotation peaklists generated by IDSL.UFA from individual HRMS data files (mzXML/mzML/netCDF processed via IDSL.IPA)
- IDSL.IPA aligned peak table (peak_alignment directory output)
- UFA parameter spreadsheet (UFA_parameters.xlsx) with PARAM0006 set to YES

## Outputs

- Aligned annotated peak table (csv) with per-peak formula hits ranked by detection frequency and median rank
- Summary statistics per formula per peak: detection frequency and median rank across samples

## How to apply

Load the individual per-file formula annotation peaklists produced by IDSL.UFA (which requires MS1 only and consumes IDSL.IPA `peaklists` and `peak_alignment` directories) for each HRMS data file. For each aligned peak in the peak alignment table, count in how many samples each candidate molecular formula was annotated (detection frequency) and compute the median rank of each formula across those samples. Re-rank formulas per peak by detection frequency and median rank, then export the aligned annotated peak table as a csv retaining the top formula hits (article reporting used a median rank ≤ 5 threshold, and unique-formula reporting used top rank ≤ 30 with number of hits ≤ 30). This aggregation is enabled by setting PARAM0006 to YES in the UFA parameter spreadsheet (30 parameters in 4 sections) supplied to `UFA_workflow`.

## Related tools

- **IDSL.UFA** (Performs the formula annotation and the aligned-table aggregation using detection frequency and median rank statistics (PARAM0006)) — https://cran.r-project.org/package=IDSL.UFA
- **IDSL.IPA** (Upstream peak picking and peak alignment that produces the individual peaklists and peak_alignment directory consumed by this step) — https://github.com/idslme/IDSL.IPA
- **R** (Runtime environment; IDSL.UFA is an R package invoked via UFA_workflow)

## Examples

```
library(IDSL.UFA); UFA_workflow("Address of the UFA parameter spreadsheet")  # with PARAM0006 = YES to aggregate formulas on the aligned peak table
```

## Evaluation signals

- Each aligned peak row carries per-formula detection frequency and median rank columns, and the sort order follows formula frequency/median rank
- Reported annotations meet the article threshold of at least one molecular formula with median rank ≤ 5 per aligned peak
- Retention of top formula hits per peak matches the configured cutoff (article reported unique formulas with top rank ≤ 30 and number of hits ≤ 30)
- Output csv row count matches the number of peaks in the IDSL.IPA aligned peak table (no peaks lost in aggregation)
- Sanity-check against benchmark: IDSL.UFA placed the true-positive formula as top hit for 54.31–85.51% of standards and within the top five hits for 90.58–100%

## Limitations

- Aggregation inherits errors from upstream peak alignment; alignment must come from IDSL.IPA peaklists/peak_alignment directories
- Ranking is based on MS1-only isotopic profile matching, so formula confidence depends on the chosen IPDB formula source and matching thresholds
- Version of IDSL.UFA and reproducibility parameters are not stated in the discussion section of the article
