# labeled-chromatographic-peak-classification

## Summary

Trains a supervised peak-reporting classifier for LC-QQQ-MS (MRM) data by combining peak-picking quality scores from automRm's qslog.tsv with expert labels in manual_peakcheck.xlsx, using a random forest tuned via the caret package in R.

## When to use

Use when automRm quality scores for metabolite-sample pairs (qslog.tsv) exist and expert labels (0 = do not report, 1 = exclude from training, 2 = report) are available in manual_peakcheck.xlsx, and a peak-reporting ML model must be trained.

## When NOT to use

- No expert-labeled manual_peakcheck.xlsx exists yet — the classifier requires labeled metabolite-sample pairs, not raw unlabeled quality scores.
- The goal is initial peak picking rather than peak reporting; peak picking is handled by the peak-picking ML model inside process_batch(), not by the reporting classifier.
- Input data are not MRM-mode LC-QQQ-MS batches processed by automRm (e.g. data lacking the automRm quality scores).

## Inputs

- qslog.tsv with peak-picking classification scores for every metabolite in every sample (output of process_batch())
- manual_peakcheck.xlsx with expert labels 0 (do not report), 1 (exclude from training), or 2 (report) per metabolite-sample pair
- manual_peakcheck_template.xlsx template generated by process_batch()

## Outputs

- Serialized (on-disk) random forest peak-reporting ML model for later use by process_batch()
- Training-summary metrics, e.g. F1 score on the 20% validation subset

## How to apply

First run automRm's process_batch() with the newly trained peak-picking ML model to generate qslog.tsv, which contains the peak-picking classification scores for every metabolite in every sample, and the manual_peakcheck_template.xlsx template. An expert then fills in manual_peakcheck.xlsx, assigning each metabolite-sample pair a score of 0 (do not report), 1 (exclude from training), or 2 (report). In R, invoke train_model(), which combines the quality scores from qslog.tsv with the labels in manual_peakcheck.xlsx, automatically splitting the data into 80% training and 20% validation subsets. Hyperparameter tuning and random forest training are performed via the caret package (a declared automRm dependency alongside openxlsx for xlsx I/O). Finally, serialize the trained peak-reporting model to disk for use by process_batch(), and record training-summary metrics such as the F1 score on the validation subset. The peak-reporting model uses the same quality scores that were previously used by the peak-picking ML model.

## Related tools

- **automRm** (R package whose train_model() trains the peak-reporting ML models used in process_batch()) — https://gitlab.gwdg.de/joerg.buescher/automrm
- **caret** (Performs hyperparameter tuning and random forest training for the peak-reporting model)
- **openxlsx** (Reads and writes the manual_peakcheck.xlsx / manual_peakcheck_template.xlsx label files)
- **R** (Language environment for train_model() and the caret-based training workflow (tested in R 3.6.0 and 4.0.2))

## Evaluation signals

- Report the F1 score of the trained model on the 20% validation subset; acceptance is consistent with the paper's reported F1 > 0.98 for combined models trained on combined data sets.
- Every label in manual_peakcheck.xlsx is one of {0, 1, 2} (do not report, exclude from training, report).
- The trained model is serialized to disk and successfully consumed by a subsequent process_batch() run.
- The feature space matches the peak-picking quality scores — the peak-reporting model uses the same quality scores previously used by the peak-picking ML model.
- Training split is 80% training / 20% validation as applied automatically by train_model().

## Limitations

- AutomRm requires the use of at least one qualifier in addition to the quantifier for optimal performance, and adding qualifiers reduces the number of analytes detectable simultaneously in MRM mode.
- Results only reach quality similar to manual peak review with sufficient training on relevant raw data; retreat to manual peak review is still needed for excessively dirty samples, very-low-input samples, or new LC methods.
- The choice of training data set and applied ML algorithm materially affects correct peak reporting, so trained models may not transfer across LC methods or data sets.
