# recursive-mass-correction

## Summary

A second-pass peak-cleaning step of the IDSL.IPA LC/HRMS pipeline in which detected peak m/z values are refined to the intensity-weighted average mass (m/z-bar) and re-checked against the chromatogram trace at that refined m/z, discarding peaks that fail the m/z-bar-trace criterion as false positives.

## When to use

Use when processing raw LC/HRMS files (e.g. Thermo 003.d, mzXML/mzML/netCDF) with IDSL.IPA and you need to quantify or prune false-positive chromatographic peaks produced by the initial peak-detection pass.

## When NOT to use

- Input is already an aligned peak/feature table rather than raw MS1 LC/HRMS data — recursive mass correction operates during peak detection on raw chromatograms
- The goal is molecular formula annotation of existing IDSL.IPA peaklists — use IDSL.UFA or IDSL.UFAx instead
- You need MS2-based structural annotation — recursive mass correction works only on MS1-level chromatographic peak data

## Inputs

- Single-sample LC/HRMS raw file (e.g. 003.d from MTBLS1684; mzXML, mzML, or netCDF MS1 data)
- IDSL.IPA parameter spreadsheet with PARAM0007 (data location), PARAM0010 (output location), and recursive mass correction parameters PARAM0019–PARAM0020
- Pre-recursion individual peaklist generated by IPA_workflow (~23,740 peaks for 003.d)

## Outputs

- Post-recursion individual peaklist in the 'peaklists' directory with false-positive peaks removed
- Removed-peak records plus before/after counts (e.g. recursive_mass_correction_003d.csv; 2,679 of 23,740 peaks, ~11%)
- Distribution of m/z changes induced by the intensity-weighted average mass correction

## How to apply

Run the initial IPA_workflow with the IDSL.IPA parameter spreadsheet (PARAM0007 pointing to the raw LC/HRMS data location, PARAM0010 to the output location) to generate the pre-recursion individual peaklist in the 'peaklists' directory. Then enable the recursive mass correction parameters (PARAM0019–PARAM0020) so that each detected peak's m/z is refined using the intensity-weighted average mass (m/z-bar), and the peak is re-checked via the m/z-bar-trace criterion against the chromatogram at the refined m/z; peaks failing this re-check are removed. Rationale: the initial pass detects only the most abundant monoisotopic 12C isotopologues, and re-scoring peaks against the m/z-bar trace eliminates signals inconsistent with a real carbon-containing species. Compare pre- and post-correction peak counts to quantify the removed fraction, and write the before/after counts and removed-peak records to a CSV (e.g. recursive_mass_correction_003d.csv).

## Related tools

- **IDSL.IPA** (R package implementing the recursive mass correction step (m/z-bar refinement and m/z-bar-trace re-check) within IPA_workflow; enabled via parameters PARAM0019–PARAM0020) — https://github.com/idslme/IDSL.IPA
- **R** (Runtime environment: IDSL.IPA is installed from CRAN and IPA_workflow is invoked with the parameter spreadsheet in R/RStudio) — https://cran.r-project.org/package=IDSL.IPA

## Examples

```
install.packages("IDSL.IPA"); library(IDSL.IPA); IPA_workflow("path/to/IPA_parameters.xlsx")  # with PARAM0019-PARAM0020 enabled for recursive mass correction
```

## Evaluation signals

- Removed fraction must equal 2,679 of 23,740 detected peaks (~11%) on test file 003.d from MTBLS1684
- The m/z changes of removed peaks must match the reported distribution of m/z changes for the intensity-weighted average mass on file 003.d
- Pre-correction peaklist row count should be ~23,740 for 003.d before enabling PARAM0019–PARAM0020
- Post-correction peaklist should retain only peaks consistent with the m/z-bar trace criterion; removed-peak records must be a strict subset of the pre-correction peaklist

## Limitations

- The removed-peak fraction (~11%) was validated on a single test file (003.d) from one study (MTBLS1684); per-dataset fractions will vary
- Only peaks detectable as most-abundant monoisotopic 12C isotopologues are considered; non-carbon-containing signals are not the target of the pipeline
- IDSL.IPA aligned data matrices still need additional downstream processing for adducts/fragments, statistical filtering, and molecular formula annotation
