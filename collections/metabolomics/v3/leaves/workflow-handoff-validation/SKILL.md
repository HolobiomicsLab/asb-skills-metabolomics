# workflow-handoff-validation

## Summary

Verifies that an upstream Nextflow process (e.g. MS-DIAL peak-table generation) automatically hands its output to a downstream process (MS-FLO) without manual copying, and validates the downstream output against expected peak counts.

## When to use

Use when running a containerized multi-process workflow (e.g. MS-DIAL → MS-FLO) and you must confirm the automatic transfer of intermediate outputs between processes and validate the downstream result.

## When NOT to use

- When the workflow is being run with a graphical user interface or web service rather than Nextflow — Nextflow4MS-DIAL is command-line-based and there is no GUI for automated handoff verification.
- When the upstream tool writes output to a location outside the workflow's `results` folder and requires manual copying — Nextflow handles the transfer; manual intervention indicates a misconfigured profile.
- When only a single process (MS-DIAL alone) is to be validated — no MS-FLO downstream step exists to verify a handoff against.

## Inputs

- MS-DIAL peak table (`.msdial`/`.tsv`) produced from `.mzML` LC-MS files in `data/raw_data/`
- `msdial_params.txt` and `msflo_params.ini` configuration files in `data/`
- Docker container encapsulating MS-DIAL (v4.48) and MS-FLO

## Outputs

- MS-FLO output peak table with flagged/filtered peaks (expected 25,414 peaks vs 25,447 from MS-DIAL)
- `execution_report.html` and `execution_timeline.html` summarizing runtime and resource usage
- `logs/execution.log` recording successful completion of both MS-DIAL and MS-FLO processes

## How to apply

Run the containerized workflow with `nextflow run main.nf -profile docker > logs/execution.log`, which encapsulates MS-DIAL (version 4.48) and MS-FLO in a Docker container. Confirm that Nextflow automatically transfers the peak table generated by MS-DIAL to MS-FLO with no manual copying or intervention; then let MS-FLO perform duplicate peak flagging, adduct and isotope flagging, peak alignment, and contaminant ion removal. Check that MS-FLO's output is a valid peak table whose peak count matches the known difference from MS-DIAL's output (25,414 versus 25,447 peaks for the MTBLS733 test dataset), and inspect `execution_report.html` and `logs/execution.log` to confirm successful completion of both processes.

## Related tools

- **Nextflow4MS-DIAL** (The containerized workflow that wires MS-DIAL output automatically to MS-FLO, using Docker profiles and process-level logging to make the handoff observable and reproducible.) — https://github.com/Nextflow4Metabolomics/nextflow4ms-dial
- **MS-FLO** (Downstream processor that consumes the transferred MS-DIAL peak table and performs duplicate peak flagging, adduct/isotope flagging, peak alignment, and contaminant ion removal.)
- **MS-DIAL** (Upstream process that generates the peak table (25,447 peaks on MTBLS733) whose automatic transfer to MS-FLO is being validated.)

## Examples

```
nextflow run main.nf -profile docker > logs/execution.log
```

## Evaluation signals

- MS-FLO output is a valid peak table with exactly 25,414 peaks (versus 25,447 from MS-DIAL) for the MTBLS733 test dataset.
- `logs/execution.log` records successful completion of both the MS-DIAL and MS-FLO processes with no manual copying steps.
- `execution_report.html` and `execution_timeline.html` are present and record runtime/resource usage for both processes.
- File extensions of produced `.msdial` files have been changed to `.tsv` so they open in spreadsheet software (per README example outputs).
- Five repeated executions produce identical results, demonstrating consistent reproducibility of the handoff.

## Limitations

- Only 10 samples were tested (five per group), so scalability of the handoff is unverified.
- MS-FLO must be downloaded from the Internet rather than being bundled with the workflow.
- Software updates such as MS-DIAL are monitored manually, with no efficient maintenance plan for the workflow and container.
- The workflow is command-line-based; users with limited computational experience may find handoff verification difficult without a GUI.
