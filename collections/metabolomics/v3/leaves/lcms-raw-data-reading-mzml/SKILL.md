# lcms-raw-data-reading-mzml

## Summary

This skill covers reading raw LC-MS data from an input mzML file using the pyopenms library into TidyMS MSData objects, the entry point of the TidyMS preprocessing pipeline for untargeted metabolomics QC.

## When to use

Use when you have raw LC-MS mzML files (e.g., pooled/intrastudy QC, blanks, and study plasma samples) that must be ingested by TidyMS to extract spectral features for a quality-control or data-curation pipeline.

## When NOT to use

- Input is already an extracted data matrix or feature table produced by MZmine2, XCMS, MSDIAL, or workflow4metabolomics — this skill is for raw mzML ingestion, not for downstream matrix curation.
- Raw vendor files are not in an open format convertible to mzML; TidyMS ingestion in this article is described specifically for mzML via pyopenms.

## Inputs

- Raw LC-MS mzML file(s) exported from vendor formats (e.g., generated by msConvert)
- Sample mapping table assigning each run to a sample type (pooled/intrastudy QC, solvent/zero-volume/process blanks, study samples) for filter behavior

## Outputs

- TidyMS MSData objects for each mzML run, ready for peak-picking and feature-detection steps
- After downstream extraction: a TidyMS DataContainer with the data matrix and feature/sample descriptors as Pandas DataFrames (serializable to disk)

## How to apply

TidyMS reads raw LC-MS data from input mzML files using the pyopenms library into MSData objects that represent chromatographic runs; these objects are the entry point of the TidyMS Pipeline architecture. A typical reading step precedes CWT-based peak picking with parameters optimized for chromatographic data, plus chromatogram building and centWave feature detection, which together produce a DataContainer holding the extracted data matrix and its feature and sample descriptors in Pandas DataFrames. The DataContainer's sample-mapping attribute associates each sample to its type (pooled/intrastudy QC, blanks, study samples), which is required later for RSD, prevalence, and D-ratio filters. In the NIST RM 8231/SRM 1950 example, 31 raw files were ingested and analyzed in 66 s, about 2 s per sample for feature detection, so the reading step is lightweight relative to downstream processing.

## Related tools

- **TidyMS** (Package whose MSData class wraps the pyopenms reading of mzML files; it is the entry point of the TidyMS pipeline architecture) — https://github.com/griquelme/tidyms
- **pyopenms** (Library used by TidyMS to read the raw LC-MS data from the input mzML file into MSData objects)
- **Pandas** (Backend for the DataContainer's feature and sample descriptors produced after reading and downstream feature extraction)
- **Numpy** (Array backend for spectral and chromatographic data held by MSData objects)
- **Scipy** (Used in downstream CWT-based peak picking applied after the reading step)

## Examples

```
import tidyms as ms; data = ms.MSData.from_mzml('run01.mzml')
```

## Evaluation signals

- Each input mzML file yields exactly one non-empty MSData object with chromatogram and spectrum axes consistent with the LC-MS run.
- The sample-mapping attribute of the resulting DataContainer assigns every run to a sample type (pooled/intrastudy QC, blanks, study) — no run may be left unmapped or filters will misbehave.
- Timing sanity check: in the article's example, 31 raw files were analyzed in 66 s with feature detection about 2 s per sample; substantially longer times per run on a comparable instrument suggest misconfiguration.
- The downstream DataContainer exposes per-feature and per-sample descriptors in Pandas DataFrames matching the ingested mzML runs.
- Serializing the processed DataContainer to disk succeeds and re-reads with the same feature/sample dimensions.

## Limitations

- Reading is mzML-specific in this article; no vendor-format ingestion path is described.
- The DataContainer requires a sample-mapping attribute (sample type per run); if omitted, pooled/intrastudy QC, blank-based, RSD, prevalence, and D-ratio filters cannot behave correctly downstream.
- Feature annotation is not covered — downstream of reading, TidyMS lacks feature annotation capability.
- No TidyMS or pyopenms version is stated in the article.
