# metabolomics-qc-based-feature-retention

## Summary

Retain LC-MS/MS metabolomic features by computing the coefficient-of-variation ratio between biological samples and QC samples and keeping features whose CV ratio exceeds a threshold (default 1), as implemented in the margheRita R package. This removes low-quality signals whose technical variability is not lower than biological variability.

## When to use

Use when a tab-delimited feature abundance table (e.g. MS-DIAL output) has matched sample annotations with class labels distinguishing QC from biological samples, and low-quality features must be filtered before imputation, normalization, or statistics.

## When NOT to use

- The input is not a preprocessed feature abundance table but raw instrument data — margheRita expects MS-Dial-generated tab-delimited output, not vendor files
- No QC injections are present in the sample annotation, since the CV ratio is defined as CV(no-QC samples) divided by CV(QC samples) and cannot be computed
- The goal is drift correction or imputation rather than quality-based feature removal — margheRita provides separate imputation (NA replacement with 10%–25% of the feature minimum) and normalization steps

## Inputs

- Tab-delimited feature data file (feature identifiers, m/z, retention times, MS/MS spectra, abundances), typically generated by MS-Dial
- Tab-delimited sample annotation file with columns id, injection_order, batch, class, biological_rep, technical_rep, where 'class' distinguishes QC samples from biological samples

## Outputs

- Filtered feature abundance table retaining only features whose CV ratio exceeds the threshold (e.g. cv_filtered_features.tsv)
- Summary of kept/removed feature counts (e.g. cv_filter_summary.txt), expected as 303/539 on the Urine demonstration dataset at the default threshold

## How to apply

Load the feature abundance table and the sample annotation file (columns id, injection_order, batch, class, biological_rep, technical_rep) into R via margheRita utilities. For each feature, compute CV = standard deviation / mean separately across the no-QC (biological) samples and across the QC samples, then take the ratio CV(no-QC)/CV(QC). Apply the margheRita CV filtering step keeping only features with a CV ratio higher than the threshold (default 1); the QC-samples-with-appropriate-CV logic is part of margheRita's pre-processing pipeline that also includes m/z filtering and NA-based filtering. Write the retained feature table (e.g. cv_filtered_features.tsv) and a kept/removed summary (e.g. cv_filter_summary.txt). Validate by comparing retained counts against documented runs: on the margheRita 'Urine' demonstration dataset, the CV filter retains 303 out of 539 metabolites at the default threshold.

## Related tools

- **margheRita** (Provides the pre-processing functions implementing CV filtering (samples vs QCs) on the mRList object, alongside m/z and NA filtering) — https://github.com/emosca-cnr/margheRita
- **R** (Runtime environment in which the margheRita CV filtering functions are executed)
- **MS-Dial** (Upstream peak-picking software whose tab-delimited output is the expected input for the CV filter)

## Examples

```
mRList <- margheRita::cv_filtering(mRList, cv_threshold = 1)  # retains 303/539 features on the Urine demo dataset
```

## Evaluation signals

- On the margheRita Urine demonstration dataset, the CV ratio filter at the default threshold of 1 must retain exactly 303 of 539 metabolites
- The retained count must not include features whose CV(no-QC)/CV(QC) is below the threshold; spot-check CV ratios per feature
- The output summary must report both kept and removed counts and the sum must equal the input feature count
- QC samples must be excluded from the 'sample' CV computation (they enter only the denominator), verifiable by re-deriving CVs from the annotation class column
- Features removed by CV filtering should be a subset of the input features; no new rows or changed identifiers in the filtered table

## Limitations

- The default CV-ratio threshold of 1 may be inappropriate for datasets with different QC regimes; the documentation example is tied to the Urine dataset
- The article notes cases where 'imputation not performed' after filtering; if too many NAs remain, downstream imputation steps may not apply as documented
- Web-based solutions include only part of the workflow, so combining filters from different platforms may not reproduce margheRita's filter counts
