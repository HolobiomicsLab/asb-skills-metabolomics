# Aggregated-feature-run detection in randomized sequences

## Summary

Scans a randomized injection sequence for runs of consecutively repeated sample categories (treatment, gender, age group) and tallies aggregation events per category per dimension, as used in the InjectionDesign case study to expose clustering that block randomization avoids.

## When to use

Use when auditing a randomized or complete-randomized LC/GC-MS injection sequence for clustered features, e.g. consecutive same-group runs in treatment/gender/age strata.

## When NOT to use

- The sequence was generated by stratified block randomization with block size 2, where three consecutive same-group runs are theoretically absent — the metric is only informative for unbalanced or complete-randomized outputs.
- The goal is inter-batch balancing rather than auditing aggregation within a single randomized sequence.

## Inputs

- Randomized injection sequence (ordered list of samples with treatment, gender, age-group labels)
- Cohort table (e.g. 1300 samples: 650 treatment / 650 placebo, 615 Male / 434 Female / 251 Unknown, 169 Kids / 351 Teenager / 481 Middle-Aged / 299 Older)

## Outputs

- Tallied aggregated feature-occurrence counts per category per dimension (CSV, e.g. complete_randomization_feature_aggregation.csv)

## How to apply

Take a randomized sequence (e.g. InjectionDesign's complete randomization output applied to a cohort such as 1300 samples with two-category treatment, three-category gender, and four-category age group) and treat it as an ordered list. For each stratification dimension, scan the sequence for runs of consecutive samples that share the same category value, and tally these aggregation events per category per dimension. Write the tallied counts to a CSV such as complete_randomization_feature_aggregation.csv. Validate by comparing to the expected behavior reported for complete randomization — many aggregated features generated with high probability, corresponding to the clustered regions highlighted in Figure 5b — against the no-three-consecutive-same-group control achievable with block randomization of block size 2. Rationale: this metric directly exposes the machine drift / batch-effect risk that unmitigated randomization introduces, quantifying the aggregation the stratified block randomization algorithm is designed to prevent.

## Examples

```
python scan_aggregation.py --sequence randomized_sequence.csv --dims treatment,gender,age_group --out complete_randomization_feature_aggregation.csv
```

## Evaluation signals

- Output CSV contains a count of aggregation events for every category of every stratification dimension (treatment, gender, age group).
- For a block-randomized (block size 2) baseline, the scan must yield no three consecutive samples of the same group in the treatment/placebo dimension.
- For the complete-randomization sequence, the tally must exhibit the paper-reported behavior: many aggregated features generated with high probability, matching the red-boxed clustered regions of Figure 5b.
- Category tallies are consistent with the input cohort table's per-dimension sample counts (e.g. 650/650 treatment, 615/434/251 gender).

## Limitations

- The paper notes the complete randomization algorithm is not a perfect solution for scenarios where block randomization averages out the natural numerical characteristics of the sample distribution.
- When there are too many groups in one dimension, the optimized block randomization's averaging step can lead to local aggregation under some special numerical distributions, complicating interpretation of run counts.
- Detection is limited to the stratification dimensions explicitly encoded in the sample table; unrecognized confounders will not be counted.
