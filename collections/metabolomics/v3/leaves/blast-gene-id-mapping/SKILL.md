# blast-gene-id-mapping

## Summary

A skill for reconciling gene identifiers across draft metabolic reconstructions produced by different annotation pipelines (KBase, CarveMe, RAVEN 2.0, AuReMe/Pathway Tools), using one-to-one BLAST mapping so that gene-protein-reaction (GPR) rules can be combined and compared when building consensus models.

## When to use

Use when merging or comparing genome-scale metabolic reconstructions generated by different pipelines whose draft models use different gene ID namespaces, and GPR rules must be aligned.

## When NOT to use

- When only metabolite or reaction identifiers differ across models — use MNXref cross-reference tables (reac_prop.tsv, reac_xref.tsv) instead of BLAST
- When all input reconstructions come from a single pipeline sharing one gene ID namespace, so no cross-pipeline mapping is needed
- When the target models lack gene-GPR information entirely (e.g. reaction-only networks), since translation operates on gene identifiers in GPR rules

## Inputs

- Draft genome-scale metabolic reconstructions in SBML format from KBase, CarveMe, RAVEN 2.0, and AuReMe/Pathway Tools (read via COBRA readCbModel)
- Protein/CDS sequences per isolate genome for BLAST database construction
- Per-isolate GPR rules referencing pipeline-specific gene identifiers

## Outputs

- One-to-one gene ID translation map linking each pipeline's gene namespace to a common namespace
- Translated COBRA models with reconciled GPRs, stored as .mat workspaces under data/models/<habitat>/<method>
- Per-isolate consensus models written to data/models/consensus with combined GPR rules

## How to apply

When draft reconstructions from the four automated approaches (KBase, CarveMe, RAVEN 2.0, AuReMe/Pathway Tools) assign different gene IDs to the same genome, first build BLAST databases for each pipeline's protein/CDS set with batch-makeblastdb.sh, then run all-against-one searches with batch-blastp.sh (proteins) or batch-blastx.sh (transcripts) using bedtools to manage intervals. Extract best one-to-one hits to construct a gene ID translation map, and apply it with translateGeneIDs.m so that GPR rules from all four drafts refer to a common gene namespace before consensus model merging (merge_metabolic_models.m). Metabolite and reaction identifiers should be handled separately via MNXref cross-reference tables (reac_prop.tsv, reac_xref.tsv, chem_prop.tsv, chem_xref.tsv); BLAST mapping is specifically for gene-level reconciliation. The translated models are then saved as Matlab workspaces (.mat) per habitat and method under data/models/<habitat>/<method>.

## Examples

```
bash batch-makeblastdb.sh data/sequences/<pipeline>/ && bash batch-blastp.sh && matlab -r "translateGeneIDs; merge_metabolic_models"
```

## Evaluation signals

- After translation, GPR rules from all four pipelines (KBase, CarveMe, RAVEN 2.0, AuReMe/Pathway Tools) parse against a single gene namespace without unmapped identifiers
- The consensus model is considerably smaller than the sum of reactions, metabolites, and genes of the underlying drafts
- Translated models load cleanly with readCbModel as .mat workspaces organized per habitat and method under data/models/<habitat>/<method>
- Sensitivity of the consensus relative to curated references iMZ1055 (B. megaterium) and iRP911 (M. extorquens) is higher than for individual drafts, confirming that combined GPRs preserve gene content

## Limitations

- Comparison against reference models was hampered by the lack of reaction cross-references to name spaces other than self-defined identifiers; translations were only done 'whenever possible'
- Since true negatives could not be determined, only sensitivity and precision could be computed to assess model quality after merging
- BLAST mapping is one-to-one; genes without a clear single best hit across annotation pipelines may remain unmapped
