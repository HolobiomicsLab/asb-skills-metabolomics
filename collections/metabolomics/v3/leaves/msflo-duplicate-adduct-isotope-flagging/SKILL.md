# msflo-duplicate-adduct-isotope-flagging

## Summary

MS-FLO filter stage that flags duplicate peaks, adducts and isotopes, aligns peaks across samples, and removes contaminant ions from MS-DIAL peak tables to enhance LC-MS metabolomics data quality and accuracy.

## When to use

Use when MS-DIAL peak tables (from .mzML LC-HRMS runs) must be cleaned and optimized before downstream analysis — specifically for duplicate/adduct/isotope flagging, alignment and contaminant ion removal via MS-FLO.

## When NOT to use

- When raw data has not yet been processed by MS-DIAL — this skill operates on peak tables generated by MS-DIAL, not on .mzML raw files directly
- When the user expects a graphical interface — Nextflow4MS-DIAL is currently command-line based with no GUI for users with limited computational experience

## Inputs

- MS-DIAL peak table automatically transferred by the Nextflow4MS-DIAL workflow
- msflo_params.ini MS-FLO parameter file placed in the data/ folder
- MS1 and MS2 metabolite libraries (ms1_lib.txt, ms2_lib.msp) for optional metabolite identification

## Outputs

- Cleaned MS-FLO peak table (e.g. 25,414 peaks vs. 25,447 from MS-DIAL on MTBLS733)
- execution_report.html and logs/execution.log recording successful completion of the MS-FLO process

## How to apply

After MS-DIAL generates a peak table, Nextflow automatically transfers it to MS-FLO with no manual copying or intervention. Provide MS-FLO parameters via msflo_params.ini placed in the data/ folder (examples in functional_test/sample_data/), then let MS-FLO perform duplicate peak flagging, adduct and isotope flagging, peak alignment, and contaminant ion removal to enhance data quality and accuracy. The pipeline is run with 'nextflow run main.nf -profile docker' (or -profile singularity on HPC), which encapsulates MS-DIAL (version 4.48) and MS-FLO in a Docker container. MS-FLO must be downloaded from the Internet rather than bundled with the workflow, so ensure it is reachable at container build time. Validate that the output is a valid peak table with the expected peak count — e.g. 25,414 peaks versus 25,447 from MS-DIAL on the MTBLS733 test data.

## Related tools

- **MS-FLO** (Performs duplicate peak flagging, adduct and isotope flagging, peak alignment, and contaminant ion removal on MS-DIAL peak tables)
- **Nextflow4MS-DIAL** (Encapsulates MS-FLO in a Docker container and automatically transfers MS-DIAL peak tables to it via Nextflow) — https://github.com/Nextflow4Metabolomics/nextflow4ms-dial
- **MS-DIAL** (Upstream tool that generates the peak tables handed off to MS-FLO; used at version 4.48 in the containerized workflow)

## Examples

```
nextflow run main.nf -profile docker > logs/execution.log
```

## Evaluation signals

- MS-FLO output is a valid peak table with 25,414 peaks (versus 25,447 from MS-DIAL) on the MTBLS733 dataset
- logs/execution.log records successful completion of both MS-DIAL and MS-FLO processes
- No manual copying or intervention was needed to transfer the MS-DIAL peak table to MS-FLO
- Duplicate, adduct, and isotope flags and contaminant-ion removals are recorded in the MS-FLO output
- execution_report.html summarizes workflow runtime and resource usage without failed processes

## Limitations

- Few LC-MS metabolomics datasets had been processed with both MS-DIAL and MS-FLO under transparent parameter settings, limiting reproduction of steps
- MS-FLO must be downloaded from the Internet rather than bundled with the workflow
- Software updates (e.g. MS-DIAL) are monitored manually, with no efficient maintenance plan for workflow and container
