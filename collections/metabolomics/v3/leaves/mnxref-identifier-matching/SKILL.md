# mnxref-identifier-matching

## Summary

Translates metabolite, reaction, and gene identifiers from draft metabolic reconstructions (generated by tools such as KBase, RAVEN 2.0, CarveMe, AuReMe/Pathway Tools) into MNXref identifiers via the MNXref reference files, so that models can be merged into a consensus and compared against a common gap-filling database (Universal-model-MNXref-balanced.mat).

## When to use

Use when merging or comparing draft genome-scale metabolic reconstructions from different tools (KBase, CarveMe, RAVEN 2.0, AuReMe) whose self-defined identifiers differ, before consensus generation or MNXref-based gap filling.

## When NOT to use

- Reconstructions whose entries already come from the MetaNetX database and are already structurally matched between various databases — re-translation adds no information
- Cross-reference-based model comparison when source models lack reaction cross-references to namespaces other than self-defined identifiers (translations only possible 'whenever possible')

## Inputs

- Draft genome-scale metabolic reconstructions with tool-specific (self-defined or KEGG-based) identifiers from KBase, RAVEN 2.0, CarveMe, or AuReMe/Pathway Tools
- MNXref reference files for metabolites and reactions
- Optional: PubChem-sourced molecular properties keyed by InChI keys (for downstream permeability classification)

## Outputs

- Reconstructions with metabolite, reaction, and gene identifiers translated to MNXref namespace
- Consensus reconstruction built by matching MNXref identifiers
- MNXref-consistent input for the gap-filling database Universal-model-MNXref-balanced.mat

## How to apply

Match metabolite, reaction, and gene identifiers by translating each draft reconstruction's native identifiers to MNXref using the MNXref reference files for metabolites and reactions. Apply technical adaptations during the translation: replace the metabolite ID 'MNXM01' with 'MNXM1' since both encode H+, and ignore generic compartments. Handle protons carefully because MetaNetX-matched entries are already structurally matched between databases, but cross-references to other namespaces exist only 'whenever possible', so translations may be incomplete. The resulting MNXref-consistent models enable consensus generation by identifier matching and use of the MNXref-based gap-filling database (Universal-model-MNXref-balanced.mat) in the COMMIT workflow.

## Related tools

- **RAVEN 2.0** (Source of KEGG-based draft reconstructions whose identifiers are translated to MNXref before consensus building) — https://github.com/SysBioChalmers/RAVEN
- **COBRA toolbox v3.0** (MATLAB environment in which the MNXref-based gap-filling database (Universal-model-MNXref-balanced.mat) is loaded and used) — https://github.com/opencobra/cobratoolbox
- **COMMIT** (Downstream community-dependent gap filling that operates on MNXref-consistent reconstructions) — https://github.com/pwendering/COMMIT

## Examples

```
matlab -r "initCobraToolbox; load('Universal-model-MNXref-balanced.mat')"
```

## Evaluation signals

- No residual 'MNXM01' identifiers in the translated models — all proton IDs replaced by 'MNXM1'
- Consensus reconstruction size is considerably smaller than the sum of the number of reactions, metabolites, and genes across the underlying drafts (merging succeeded via matched identifiers)
- Translated models load into the COBRA toolbox together with Universal-model-MNXref-balanced.mat without unknown-identifier errors during gap filling
- Translation coverage should be audited: only 26% of InChI keys translated to PubChem CIDs and 11% had XLogP3 values in the reference pipeline, so unmatched entries are expected and must be logged

## Limitations

- Comparison against reference models is hampered by lack of reaction cross-references to name spaces other than self-defined identifiers; translations were only done whenever possible
- Metabolite properties keyed by InChI keys are patchy (only 26% of InChI keys translated to PubChem CIDs, 11% with XLogP3), which propagates identifier-matching gaps into downstream permeability classification
- Both MNXM01 and MNXM1 encode H+; failure to apply the replacement rule causes duplicated proton metabolites in merged models
