# metabolomic-workflow-scan-optimization

## Summary

An R-based NOREVA protocol that scans thousands of combinatorially generated metabolomic peak-table processing workflows (stages S1 data filtering/imputation, S2 QCS correction, S3 transformation, S4 normalization) and ranks them by multi-criteria performance assessment (S5), because the optimal workflow is dataset- and study-specific.

## When to use

Use when a raw or unnormalized metabolomic peak table (case-control, multi-class, or time-course, e.g. MetaboLights MTBLS403) needs an objectively optimal combination of filtering, imputation, QCS correction, transformation, and normalization methods.

## When NOT to use

- Datasets with fewer than 6 samples per class or timepoint, since criterion Cc is unsuitable
- Datasets with no reference metabolites (e.g. spike-ins) available, since criterion Ce (LogFC) cannot be applied
- Peak tables whose columns are internal-standard/QCS columns the user cannot identify — normulticlassisall requires explicitly listing IS column numbers

## Inputs

- Metabolomic peak table (e.g. from MetaboLights MTBLS403 raw data files) manually standardized to NOREVA's unified format with rows = samples (by name) and preserved columns
- Label file for time-course/multi-class sample annotation
- Specification of study design: multi-class vs. time-course, presence/absence of QCS and internal standards, and study assumptions alpha/beta/gamma

## Outputs

- Scores for every combinatorially generated workflow (thousands, e.g. 5,904 for PMID28528106) from S5 multi-criteria performance assessment
- Overall ranking of all evaluated workflows (e.g. ranking_table.csv reproducing Figure 4 ordering)

## How to apply

Standardize the peak table to NOREVA's unified format, preserving rows (samples by name) and columns, then load it via PrepareInuputFiles (dataformat='1' for the standardized format or '2' for output of 12 supported tools). Run the full scan so all thousands of workflows generated by combining methods across S1–S4 are executed, choosing the NOREVA assessment function that matches the data design (e.g. normulticlassqcall for multi-class with QCS but no internal standard; specify study assumptions SAalpha/SAbeta/SAgamma as 'Y' or 'N', where gamma means the majority of metabolites are unchanged). If internal standards are present instead of QCS, use normulticlassisall and give the column numbers of the ISs. In S5, each workflow is scored against multiple criteria (Cc requires ≥6 samples per class/timepoint; criterion Ce/LogFC requires reference metabolites such as spike-ins), and workflows are ranked. Validate by comparing the ranking against published expectations — for PMID28528106, HAM+LLR+NON+[SUM-LEV] should rank first and KNN+NWE+LOG+[PAR-LIN] last among 5,904 workflows.

## Examples

```
library(NOREVA); result <- normulticlassqcall("peaktable", SAalpha="Y", SAbeta="Y", SAgamma="Y")
```

## Evaluation signals

- The produced ranking_table.csv reproduces the published ordering: HAM+LLR+NON+[SUM-LEV] at rank 1 and KNN+NWE+LOG+[PAR-LIN] at last rank for benchmark PMID28528106
- The total number of scanned workflows matches the combinatorial expectation (5,904 for the PMID28528106 benchmark)
- The standardized peak table preserves rows (samples by name) and columns as required by NOREVA's unified format
- Each workflow's output corresponds to one combination of S1 filtering/imputation, S2 QCS correction, S3 transformation, and S4 normalization methods, scored under S5's five distinct criteria
- Output files from partial assessment commands are checked against Step-10 outputs because identical file names can overwrite earlier results

## Limitations

- The protocol covers only commonly applied processing methods and cannot be extended automatically; new methods must be manually added by bioinformaticians
- Assessing thousands of workflows is very time-consuming: hundreds to thousands of minutes, and >200 min even with parallel computing and memory management for large datasets like PMID28528106
- Manual peak-table standardization is time-consuming because raw data file organizations are diverse, making row/column preservation challenging
- Successful application depends on upfront experimental design adopting both QCSs and ISs, which the tool does not enforce; preliminary R programming experience is required, and modifying the protocol requires R mastery
