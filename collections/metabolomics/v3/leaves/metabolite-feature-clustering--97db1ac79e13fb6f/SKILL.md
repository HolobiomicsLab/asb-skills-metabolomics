# metabolite-feature-clustering

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

mWISE's feature-clustering step groups untargeted LC-MS peaks that are likely to originate from the same metabolite, using intensity similarity (Equation 1) and retention-time similarity (Equation 2) as clustering objectives. It feeds a cluster-based filter that cuts false-positive KEGG candidates before diffusion-based prioritization.

## When to use

Use when an untargeted LC-MS peak list has already been matched to KEGG (e.g. with mWISE matchingStage over a set of adducts and fragments) and multiple peaks need to be grouped as candidates of a single metabolite before candidate filtering or diffusion scoring.

## When NOT to use

- Input peak list has not yet been matched to KEGG — run matchingStage first, since featuresClustering operates on candidates generated by the matching stage
- Annotation against non-KEGG databases such as HMDB, Lipid Maps or T3DB is required — mWISE only offers KEGG data and this is stated as a limitation relative to xMSannotator
- The goal is a standalone clustering of features without an annotation objective — the clustering is tuned to maximize candidate-filtering quality (f3 - (f2 + f1)) rather than general cluster discovery

## Inputs

- LC-MS peak list already matched to KEGG by mWISE matchingStage (built on GenomicRanges) considering a set of adducts and fragments
- Peak intensity matrix and retention-time values (filtered input: features without signal removed and the 80% rule applied where intensity equals 0)

## Outputs

- Clusters of LC-MS features likely to originate from the same metabolite
- Filtered candidate list per peak after clusterBased.filter, reduced in false positives before diffusion
- Prioritized list of the top three KEGG candidates per peak after diffusion (set.diffusion)

## How to apply

After the matching stage links LC-MS peaks to KEGG compounds, apply mWISE featuresClustering, which applies spectral clustering, plus DBSCAN and k-means over principal components, to group peaks more likely to come from the same metabolite. Optimize the number of principal components and the epsilon parameter, and vary k in k-means, maximizing the objective f3 - (f2 + f1) built from intensity similarity (Equation 1) and retention-time similarity (Equation 2). Then run clusterBased.filter to reduce false positives introduced before the diffusion step, and select the top three candidates per peak as the final prioritized proposal. Evaluate the end-to-end output with mWISE performanceEvaluation against a benchmark reference data frame.

## Related tools

- **mWISE** (R package providing the featuresClustering and clusterBased.filter functions that implement this clustering/filtering step within the annotation pipeline) — https://dev.b2s.club/b2slab/mWISE
- **Genomic Ranges** (R package used upstream by matchingStage to match LC-MS peaks to KEGG before clustering)
- **Diffu Stats** (R package used downstream by set.diffusion to diffuse label vectors over the chosen biochemical/biological network after the cluster-based filter)

## Examples

```
R: mWISE::featuresClustering(matchingStage(peaks, kegg, adducts), method='dbscan'); mWISE::clusterBased.filter(...) | top 3 candidates per peak
```

## Evaluation signals

- Cluster-based filter measurably reduces false positives before diffusion (e.g. Assay 2: FP from 17598 to 1671, specificity 0.91)
- Clustering objective f3 - (f2 + f1), computed from intensity similarity (Equation 1) and retention-time similarity (Equation 2), is maximized when optimizing epsilon and the number of clusters
- End-to-end annotation performance measured by performanceEvaluation: sensitivity mean 0.63 (SD 0.07) across datasets vs 0.55 (0.19) for xMSannotator using the FELLA network plus raw scores configuration
- Final output contains at most the top three KEGG candidates per peak
- Input peak list conforms to the mWISE filtering rules: no-signal features removed and the 80% rule applied where intensity equals 0

## Limitations

- mWISE lacks support for databases other than KEGG (limitation relative to xMSannotator)
- mWISE matching sensitivity was 0.92 on Assay 1 (144 TP, 13 FN, 157 references), so unmatched peaks will not be clustered or filtered
- Clustering quality depends on optimized DBSCAN epsilon and principal-component count; the article describes no sensitivity analysis for mis-specified values
- Only the top three candidates per peak are retained as the final prioritized proposal
