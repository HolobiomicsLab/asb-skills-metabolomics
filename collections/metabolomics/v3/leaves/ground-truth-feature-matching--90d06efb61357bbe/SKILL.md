# ground-truth-feature-matching

## Summary

Match features detected from synthetic LC-MS maps against the ground-truth feature list generated by MSSimulator and compute recall, precision, and F-score per noise regime. This is the benchmarking core used to quantify FeatureFinderMetabo's robustness to detector noise, mass error, and chromatographic distortion.

## When to use

Use when you have an LC-MS feature-detection result on simulated data whose ground truth is known (e.g. from MSSimulator) and you need recall/precision/F-score per noise setting.

## When NOT to use

- Input data is real experimental LC-MS (no ground truth exists), so precision/recall against truth cannot be computed — use spike-in or replicate-based validation instead.
- Input is already a scored feature table; only the plotting/rendering step applies.
- Data comes from a proteomics or other large-molecule workflow outside the small-molecule/metabolite scope of FeatureFinderMetabo's isotope-pattern SVM.

## Inputs

- Simulated LC-MS map (e.g. mzML) produced by MSSimulator with known parameter configuration
- Ground-truth feature list emitted by MSSimulator for that map
- Detected feature list (featureXML) from FeatureFinderMetabo run on the same map
- Simulator/feature-finder parameter values for the sweep (supplemental Table S5)

## Outputs

- Per-condition recall, precision, and F-score values matched against ground truth
- Table of scores versus simulator/feature-finder parameters and noise regime
- Plotted benchmark figure (benchmark_scores.png)

## How to apply

Simulate plant-metabolite LC-MS maps with MSSimulator using the supplemental Table S5 configurations (500 metabolites, 100–1000 m/z, 25 min gradient, detector noise sigma_det, mass error sigma_m/z of 10 and 40 ppm, ideal vs heavily distorted elution profiles); MSSimulator simultaneously yields the ground-truth feature list. Run FeatureFinderMetabo (OpenMS 1.10) on each simulated map across the parameter sweep. Match the detected features against the MSSimulator ground truth and compute recall, precision, and F-score using the article's F-score definition for each simulator/feature-finder parameter setting and noise regime. Tabulate the scores versus parameters, then render the table as a plotted figure (benchmark_scores.png). On the article's setup this reproduced precision of 97% and recall of 96%, with F-scores staying between 0.97 and 0.9 under increased mass error and chromatographic distortion.

## Related tools

## Examples

```
FeatureFinderMetabo -in simulated_map.mzML -out features.featureXML; # then match features.featureXML against MSSimulator ground-truth feature list to compute recall/precision/F-score per noise regime
```

## Evaluation signals

- Precision and recall values reproduce the article's reported ~97% precision and ~96% recall on the reference configuration.
- F-scores remain between 0.97 and 0.9 as mass error and chromatographic distortion increase across the parameter sweep.
- Every detected feature is either matched to a ground-truth feature or counted as a false positive — no unmatched entries left in the score computation.
- Scores are reported separately for each noise regime (detector noise, mass error, profile distortion) so the robustness curve can be traced.
- Rendered benchmark_scores.png visually matches the trend of the tabulated scores versus simulator/feature-finder parameters.

## Limitations

- Ground truth exists only for simulated data; on real plasma or plant samples precision/recall cannot be computed this way.
- Results depend on matching the simulator configuration (e.g. 10 vs 40 ppm mass error, ideal vs heavily distorted profiles) to the intended noise regime; misconfiguration silently skews scores.
- The benchmark was configured for plant metabolites (500 metabolites, 100–1000 m/z, 25 min gradient); extrapolating to other matrices or gradients is unvalidated.
- OpenMS version matters: the article used version 1.10, and the OpenMS README notes the current codebase uses modern C++23 — behavior may differ across versions.
