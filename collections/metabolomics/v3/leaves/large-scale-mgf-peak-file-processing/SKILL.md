# large-scale-mgf-peak-file-processing

## Summary

Convert very large collections of MS/MS spectra (tens of millions, delivered as MGF/mzML peak-list files) into 32-dimensional GLEAMS embeddings and cluster them to group spectra generated by the same peptide, enabling joint analysis at a scale that defeats per-spectrum search tools.

## When to use

Use when millions of MS/MS spectra in peak-list files (MGF or mzML) must be jointly processed and grouped by precursor peptide — e.g. reproducing the 84M-spectrum GLEAMS vs. falcon/MaRaCluster/MS-Cluster/spectra-cluster benchmark.

## When NOT to use

- Embeddings already exist as a GLEAMS .npy/.parquet pair — run only `gleams cluster`, not `gleams embed`
- The task is standard peptide identification of a small dataset, where a direct database search (e.g. MSGF+) is more appropriate than clustering millions of spectra
- The environment lacks a CUDA-enabled GPU, Linux, or Python 3.8, which GLEAMS requires

## Inputs

- MGF peak-list files containing MS/MS spectra (e.g. the three ~28M-spectrum test-set folds)
- mzML peak files accepted directly by `gleams embed`
- MassIVE-KB metadata TSV with 'filename' and 'scan' columns for targeted spectrum retrieval
- GLEAMS model weights file gleams_82c0124b.hdf5 (placed in the repo's data/ directory)

## Outputs

- GLEAMS_embed.npy: n x 32 NumPy array of spectrum embeddings
- GLEAMS_embed.parquet: tabular metadata for the embedded spectra
- GLEAMS_cluster.npy: cluster label per embedding (-1 = noise, minimum cluster size 2)
- GLEAMS_cluster_medoids.npy: indexes of cluster representative (medoid) spectra

## How to apply

Split the spectra (e.g. the ~84 million test-set spectra from 24 MassIVE-KB datasets, in three randomly generated folds of ~28 million each exported to MGF) into processable batches. Run `gleams embed` over the peak files, which reads MS/MS spectra and writes a two-dimensional NumPy array of dimension n x 32 (GLEAMS_embed.npy) plus a GLEAMS_embed.parquet metadata table keyed to the embedded spectra. Then run `gleams cluster` with `--distance_threshold 0.3` to perform hierarchical clustering on the embeddings; cluster labels are written to GLEAMS_cluster.npy with -1 marking noise and a minimum cluster size of 2, and GLEAMS_cluster_medoids.npy holds indexes of cluster representative spectra (medoids). When source spectra must be recovered rather than downloaded wholesale, use the MassIVE-KB metadata TSV's 'filename' column to retrieve spectra from the MassIVE FTP server and extract them by 'scan' number. Ground-truth peptide labels for evaluating cluster quality come from the 185 million PSMs at 1% FDR obtained with MSGF+ during MassIVE-KB compilation.

## Examples

```
gleams embed *.mzML --embed_name GLEAMS_embed && gleams cluster --embed_name GLEAMS_embed --cluster_name GLEAMS_cluster --distance_threshold 0.3
```

## Evaluation signals

- GLEAMS_embed.npy has shape (n, 32) with n equal to the number of MS/MS spectra read from the peak files, and GLEAMS_embed.parquet has matching rows
- All entries in GLEAMS_cluster.npy are either integer cluster labels or -1 (noise), with no cluster smaller than size 2
- Indexes in GLEAMS_cluster_medoids.npy are valid row indices into the embedding array and one per non-noise cluster
- Clustering used the paper's distance threshold of 0.3 on the embedding distance metric
- Per-tool clustered-spectra fraction, incorrectly-clustered fraction, and completeness (vs. MassIVE-KB peptide labels) reproduce the reported cluster-quality comparison

## Limitations

- GLEAMS requires Python 3.8, a Linux operating system, and a CUDA-enabled GPU; deep-learning-based clustering cannot run on CPU-only hosts
- Git LFS bandwidth limits can break installation; work around by cloning with GIT_LFS_SKIP_SMUDGE=1 and manually downloading gleams_82c0124b.hdf5 into data/
- MassIVE-KB spectra are not available as a single download — they must be retrieved per-task from MassIVE FTP using the metadata TSV filename/scan columns
- Full neural-network configuration lives in gleams/config.py; defaults tuned on 30M MassIVE-KB PSMs may not transfer to non-human or non-HCD data
