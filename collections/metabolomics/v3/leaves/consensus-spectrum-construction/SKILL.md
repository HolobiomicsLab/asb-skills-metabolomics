# consensus-spectrum-construction

## Summary

Constructs a per-molecule consensus MS/MS spectrum from multiple replicate spectra (e.g., different collision energies) so it can be used as an aggregate-then-rank query view in MVP's joint embedding, which outperforms rank aggregation of individual spectra.

## When to use

Use when a molecule has multiple constituent MS/MS spectra (e.g., several collision energies in MassSpecGym) and you need one aggregate query view for candidate ranking instead of rank-then-aggregate scoring.

## When NOT to use

- When each molecule has only a single spectrum (e.g., the rank-aggregation subset excludes molecules without exactly three spectra), there is nothing to aggregate into a consensus
- When the goal is rank-then-aggregate scoring of individual spectra rather than an aggregated query view
- When spectra lack representative-spectrum selection/feature extraction (e.g., no MZmine3 feature handling) so constituent spectra are not directly mergeable

## Inputs

- MS/MS spectra table (MassSpecGym data.tsv format) with multiple constituent spectra per molecule across collision energy levels
- Candidate molecules file (candidates_mass.json)
- Subformula label directory produced by assign_subformulae.py (formSpec path only)

## Outputs

- Per-molecule consensus spectra file (as generated by data_preprocess.py)
- Fingerprint training files (Morgan fingerprints via RDKit) produced alongside consensus spectra
- Consensus-view embeddings from the trained MVP encoder used for aggregate-then-rank candidate ranking

## How to apply

Collect the multiple constituent spectra per molecule and merge them into a single consensus spectrum during MVP preprocessing: run `data_preprocess.py` (after `assign_subformulae.py --max-formulae 60` if using the formSpec path), which emits the consensus-spectrum and fingerprint files consumed by training/inference. The consensus spectrum becomes one of MVP's four views (molecular graph Zmol, fingerprint Zfp, spectrum Zs, consensus spectrum Zcs) aligned by the pairwise mutual-information contrastive objective. At retrieval time, embed the consensus spectrum and rank candidates directly (aggregate-then-rank); compare this against the rank-then-aggregate baseline that ranks candidates per individual spectrum and aggregates rankings. On MassSpecGym the consensus view reaches 35.99% rank@1 by mass and 13.96% by formula, versus 26.37% and 11.10% for individual spectra, and the fair rank-aggregation comparison is limited to test molecules with exactly three spectra (1,531 cases).

## Evaluation signals

- Consensus-view retrieval on MassSpecGym should reach approximately 35.99% rank@1 by mass and 13.96% rank@1 by formula
- Aggregate-then-rank with the consensus spectrum should outperform rank-then-aggregate over constituent spectra (which yields 26.37%/11.10% rank@1 by mass/formula)
- data_preprocess.py must emit consensus-spectrum and fingerprint files loadable by the MVP pipeline for both formSpec and binnedSpec paths
- Per-epoch four-view contrastive training loss logged by Lightning should decrease and saved encoder weights should embed all four views consistently

## Limitations

- The README's preprocessed MassSpecGym download URLs are empty, so consensus spectra must be generated locally via data_preprocess.py rather than downloaded
- The rank-aggregation comparison is restricted to the test subset where a molecule has exactly three spectra (1,531 cases), limiting generalization of consensus-vs-individual claims
- Representation quality could benefit from more accurate peak labeling and additional views, per the authors' stated future directions
