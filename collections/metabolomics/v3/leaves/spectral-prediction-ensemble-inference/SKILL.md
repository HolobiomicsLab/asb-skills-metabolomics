# spectral-prediction-ensemble-inference

## Summary

Run the pretrained Ensemble Spectral Prediction (ESP) model — a weighted-average ensemble of MLP and GNN spectral predictors — on molecular candidate sets to rank candidates for metabolite annotation, reporting average rank and Rank@K metrics.

## When to use

Use when you have a pretrained ESP/MLP/GNN checkpoint, preprocessed NPLIB1 test data, and PubChem-derived candidate sets and need candidate ranking or Rank@K evaluation.

## When NOT to use

- You need to train new MLP/GNN base models rather than run saved models — then --te_cand_dataset_suffix should be left empty per the README training instructions.
- Your data is EI/GC-MS rather than ESI/LC-MS: the published model and datasets cover NPLIB1 (ESI/LC-MS) and NIST-20 training data cannot be redistributed.
- Input is raw spectra rather than the preprocessed 1000-bin torchgeometric candidate files that data_tecand.py generates.

## Inputs

- Pretrained model checkpoints: pretrained_models/ESP_can.pt (or best_model_ens_can.pt), best_model_mlp_can.pt, best_model_gnn_can.pt
- Preprocessed NPLIB1 test data (torch_trvate_1000bin.pkl generated by data_trvate.py)
- Test candidate torchgeometric pickle file, e.g. torch_tecand_1000bin_te_cand100_torchgeometric.pkl, generated by data_tecand.py
- mol_dict.pkl mapping InChiKeys to rdkit mol objects (Zenodo record 10929354)

## Outputs

- Average rank with standard deviation over the test spectra (e.g. 279.557 +- 1170.300 on the full NPLIB1 candidate set)
- Rank@1 through Rank@20 fractions (e.g. Rank at 1 0.187, Rank at 20 0.592)
- Per-candidate ESP spectral predictions used for candidate ranking

## How to apply

Clone HassounLab/ESP and prepare the environment (python 3.8, dgl 0.6.1, pytorch 1.7.1, rdkit, pytorch-geometric 1.7.2), then generate the test-candidate torchgeometric file with data_tecand.py at the fixed 1000-bin resolution (file named torch_tecand_1000bin_te_cand<cand_size>_torchgeometric.pkl). Load the pretrained checkpoints best_model_mlp_can.pt, best_model_gnn_can.pt and ESP_can.pt from /pretrained_models. Run ens_train_canopus.py in 'canopus' mode with --te_cand_dataset_suffix pointing at the desired candidate file and --mlp_model_file_suffix/--gnn_model_file_suffix set to the base models, using the flags --disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology --correlation_mat_rank 100 that reproduce the published configuration. The script scores each candidate against the target spectrum and reports the average rank (with standard deviation) and Rank@1..Rank@20 over the test spectra; ranking quality degrades as candidate-set size grows (average rank 3.194 for 50-molecule sets vs 213.597 on the full set) and as candidates become more similar to the target (rank 4.488 least-similar vs 13.491 most-similar by MACCS fingerprint).

## Evaluation signals

- Namespace echo printed by the script matches the published configuration (lr=0.001, hidden_dims=1024, num_hidden_layers=3, correlation_mat_rank=100, ensemble_hidden_dim=256, mode='canopus', full_dataset=True).
- Average rank falls in the plausible range reported for the setup, e.g. 279.557 +- 1170.300 for ESP on the full NPLIB1 candidate set, and decreases toward ~3.194 as candidate-set size shrinks to 50.
- Rank@1..Rank@20 output is monotonically non-decreasing and ends near 0.592 at Rank@20 for the full-candidate-set ESP run.
- The test-candidate file name follows the pattern torch_tecand_<bins>bin_te_cand<cand_size>_torchgeometric.pkl and matches the --te_cand_dataset_suffix argument.
- For candidate-similarity comparisons, least-similar 100-candidate sets yield lower average rank (~4.488) than most-similar sets (~13.491).

## Limitations

- NIST-20 training data cannot be published due to NIST license regulations; only models pretrained on NPLIB1 are distributed in /pretrained_models.
- mol_dict.pkl and pos_train.csv must be downloaded separately from Zenodo because they are too large for the git repository.
- Annotation performance is dependent on the training dataset, the number of molecules in the candidate set and candidate similarity to the target molecule, so results do not transfer unchanged across candidate-set configurations.
- The GNN demo expected output in the README is shown under a command whose model_file_suffix reads 'gnn_can' but the Namespace prints 'mlp_can', an inconsistency in the documentation.
