# formula-encoder-dimensionality-verification

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Verifies the sinusoidal counts-based formula embedding (Equation 5) used by MIST-CF: each of the 18 considered elements gets an 8-dimensional integer encoding (log2(256)), flattened to a 144-dimensional, strictly non-negative vector Enc(F). This check guards the interface between formula candidate parsing and the Chemical Formula Transformer.

## When to use

Use when reimplementing, porting, or regression-testing the MIST-CF counts-based formula encoder, or when feeding formula candidates into the Chemical Formula Transformer and you must confirm the encoding is exactly 144-dimensional and non-negative before training or inference.

## When NOT to use

- Input is raw MS/MS spectra or peak lists — this skill validates the formula-count encoder only, not the spectrum/subformula encodings
- Formulas contain elements outside the fixed 18-element set considered by MIST-CF, so counts cannot be mapped to the 144-dim layout
- A quantitative accuracy benchmark of the encoder is required — the paper validates it only qualitatively (shape and non-negativity)

## Inputs

- Chemical formula candidate strings (e.g., precursor formula candidates generated by SIRIUS 'SIRIUS decomp' in the MIST-CF pipeline)
- Per-element integer counts over the 18 supported elements (including count 0 for absent elements)

## Outputs

- 144-dimensional formula encoding Enc(F) ∈ R144 (all entries >= 0)
- encoder_verification_report.txt with dimensionality and non-negativity check results
- Encoder module (saveable/reloadable) consumed by the Formula Transformer

## How to apply

Parse each chemical formula candidate string into per-element integer counts using a formula parser that covers the 18 supported elements. For each count v, compute an 8-dimensional sinusoidal embedding with features at periods 1, 2, 4, ..., 256 (powers of two up to 256, i.e. log2(256) = 8 dimensions), then apply an absolute-value transformation so every component is >= 0. Concatenate the 8-dim embeddings across all 18 elements to assemble Enc(F) with 144 dimensions (the '+1' mass/charge token accounts for the article's '144+' notation). Run unit checks with a small NumPy script on example formulas, explicitly including edge cases of count 0 and large counts, asserting output shape (144,) and minimum entry >= 0. Save the encoder module and write the dimensionality and non-negativity results to encoder_verification_report.txt; acceptance is qualitative — shape and non-negativity must hold for all test formulas, since the paper reports no separate quantitative metric for this encoder.

## Examples

```
python -c "import numpy as np; enc=np.abs(np.concatenate([np.array([np.sin(np.pi*c/2**k),np.cos(np.pi*c/2**k)]) for c in [6,12,6] for k in range(8)])); assert enc.min()>=0; print('OK', enc.shape)"
```

## Evaluation signals

- Encoded vector Enc(F) has exactly 144 dimensions for every test formula (18 elements × 8 sinusoidal dimensions)
- Minimum entry of Enc(F) is >= 0 for all test formulas after the absolute-value transformation
- Edge-case formulas with element count 0 and large counts encode without errors or negative values
- Per-element embedding is exactly 8-dimensional, matching log2(256) sinusoidal periods 1, 2, 4, ..., 256
- encoder_verification_report.txt exists and records passing shape/non-negativity assertions

## Limitations

- Validation is qualitative only — the paper reports no separate quantitative evaluation metric for this encoder, so passing checks do not guarantee downstream ranking quality
- The encoding is fixed to 18 elements and 8 sinusoidal dimensions (periods up to 256); counts exceeding these design choices are uncharacterized
- MIST-CF models are trained only for positive-mode data, and the paper relies on SIRIUS for candidate decomposition, so this encoder is only one component of the formula-assignment pipeline
