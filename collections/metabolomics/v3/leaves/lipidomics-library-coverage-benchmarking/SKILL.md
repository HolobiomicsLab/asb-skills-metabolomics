# lipidomics-library-coverage-benchmarking

## Summary

Quantifies the compositional coverage of a lipidomics software's in silico fragmentation libraries — total lipid species, distinct lipid types, and fatty acid combination lists — and benchmarks coverage against comparable open-source tools. Used to establish the diversity claims (e.g. 250,000+ species, 56 lipid types) that underpin software comparisons.

## When to use

Use when reproducing or verifying library-composition claims for a lipid identification tool, or comparing the number of lipid types/species covered across open-source lipidomics software.

## When NOT to use

- The goal is validating identification accuracy on experimental MS/MS data rather than enumerating library composition — use the rule-based identification filter steps instead
- The README reports a newer distribution with different totals (over 500,000 species across over 60 lipid types), so the 2017 paper's exact-match counts (250,000+ species, 56 types) should not be expected against the current GitHub release

## Inputs

- LipidMatch_Distribution.zip (Additional file 1) containing lipid libraries in .csv format
- In silico fragmentation library .csv files (one or more per lipid type)
- Fatty acid combination lists generated by the R script (endogenous and oxidized)
- Library class labels and adduct annotations

## Outputs

- library_composition_report.csv with total species count, per-type counts, fatty acid list sizes, and unique-class presence flags
- Counted totals: species count (lower bound), lipid type count, endogenous fatty acid count, oxidized fatty acid count (split into long-chain O/OH/OOH and short-chain CHO/COOH groups)
- Benchmark comparison of lipid type coverage vs MS-DIAL and Greazy

## How to apply

Extract the software distribution (e.g. 2017_6_14_LipidMatch_Distribution.zip, Additional file 1 or http://secim.ufl.edu/secim-tools/) and enumerate the lipid library .csv files. In R, load each library .csv, tally unique lipid species entries per file, and sum across libraries to get the total species count (for the 2017 LipidMatch paper this is a lower bound of over 250,000). Count distinct lipid types across the collection with explicit counting conventions — for LipidMatch, each plasmenyl/plasmanyl ether pair counts as two types and oxidized lipids across classes count as one type — requiring an exact match to 56. Verify the fatty acid combination lists generated by the R script: 39 endogenous fatty acids and 214 potential oxidized fatty acids (126 long-chain O/OH/OOH additions plus 88 short-chain CHO/COOH cleavage products from LIPID MAPS fatty acids, excluding redundant permutations like 18:0_20:0 vs 20:0_18:0). Scan class labels and adduct annotations to confirm presence of unique libraries (oxidized lipids, bile acids, sphingosines, ammoniated cardiolipins), then benchmark type coverage against comparators (MS-DIAL 34 types, Greazy 24). Write the tallies to a report table such as library_composition_report.csv.

## Evaluation signals

- Total summed unique species count across all library .csv files must exceed 250,000 (lower bound)
- Distinct lipid type count must equal exactly 56 under the stated conventions (plasmenyl/plasmanyl pairs counted as two; oxidized lipids across classes counted as one)
- Endogenous fatty acid list must contain exactly 39 entries
- Oxidized fatty acid list must contain exactly 214 entries: 126 long-chain (O/OH/OOH additions) plus 88 short-chain (CHO/COOH cleavage), with redundant permutations excluded
- Presence flags for oxidized lipids, bile acids, sphingosines, and ammonium-adduct cardiolipins must all be TRUE in the library class/adduct scan

## Limitations

- The over-250,000 species figure is evaluated as a lower bound, not an exact census
- Coverage totals are version-pinned: the paper's counts come from the 2017_6_14_LipidMatch_Distribution.zip, while the current README cites over 500,000 species across over 60 lipid types
- Counting conventions matter — ether (plasmenyl/plasmanyl) pairs and oxidized lipids across classes are counted differently than a naive unique-label count would produce
- Key artifacts are only provided as additional files, not archived in a public repository, so the exact zip used may be hard to retrieve later
