# smiles-structure-to-molecular-graph-conversion

## Summary

Converts an anchor molecule or a generated biotransformation-derivative, represented as a SMILES string, into an RDKit molecular graph so that the GNN-SOM site-of-metabolism predictor can score each atom's likelihood of being a reaction center within the BAM annotation pipeline.

## When to use

Use when BAM has applied biotransformation rules to an anchor molecule via PROXIMAL2 and you need each anchor and candidate derivative structure (SMILES or mol block) converted to a graph for GNN-SOM atom-likelihood scoring.

## When NOT to use

- When the query molecule is only known by an MS/MS spectrum and no SMILES or InChI is available — without a structure there is no graph to build; obtain an anchor structure first
- When a PROXIMAL2 predicted product json reports a SMILES that 'may be not generated' because RDKit found no chemical sense in the prediction — forcing a parse will produce an invalid graph
- When the downstream model is not GNN-SOM or a graph-neural-network predictor — other scoring tools may accept different input formats (e.g. SDF with explicit conformers)

## Inputs

- SMILES string of the anchor molecule (from the molecules_of_interest csv in the BAM input)
- SMILES or mol text of candidate derivative structures in PROXIMAL2 product json files (fields: GeneratedProduct.smiles, GeneratedProduct.mol)
- RDKit molecular graph representation required by GNN-SOM (PyTorch Geometric data objects)

## Outputs

- RDKit-parsed molecular graph per candidate derivative, with atoms and bonds consumable by GNN-SOM
- Per-atom site-of-metabolism likelihood scores (after GNN-SOM inference) used for ranking

## How to apply

In the BAM workflow (Python 3.9, run via runBAM.sh with the 'proximal2' and 'som' conda environments), take the SMILES representation of the anchor molecule from the molecules_of_interest input file and the candidate derivative structures generated by PROXIMAL2, and parse them with RDKit into molecular graph objects containing atoms as nodes and bonds as edges. These graphs are the input format required by GNN-SOM, which uses PyTorch Geometric to predict, for each atom in the molecule, the likelihood that it is the site of metabolism targeted by the biotransformation rule. If a PROXIMAL2 product json contains a SMILES marked as not generated (because RDKit found no chemical sense in the prediction), skip that candidate rather than force a parse. On failure, fall back to the mol text ('mol') stored alongside the SMILES in the product json. The conversion is a prerequisite for ranking: GNN-SOM scores feed directly into the derivative ranking step, where correct candidates are defined by a match on the first 14 InChIKey characters.

## Examples

```
from rdkit import Chem; mol = Chem.MolFromSmiles(anchor_smiles); graph = mol_to_pyg_graph(mol)
```

## Evaluation signals

- Every candidate derivative SMILES in the PROXIMAL2 product folder parses without an RDKit error; products with 'smiles: may be not generated' are excluded from ranking
- Graph node count equals the RDKit atom count and edge count equals the bond count of the parsed molecule
- Sanitization succeeds: no implicit-valence or valence errors on the parsed molecule
- GNN-SOM returns a finite likelihood for at least one atom per valid graph; NaN outputs indicate a malformed graph
- Downstream check: the true suspect structure (matched on first 14 InChIKey characters) appears within the top-5 ranked candidates when the correct graph was converted and scored

## Limitations

- RDKit may refuse to generate a SMILES for a PROXIMAL2 prediction ('the algorithm can apply the modifications but RDKit do not find chemical sense about the prediction'), leaving only raw mol text
- Some PROXIMAL2 reactions take a couple of minutes to build operators, so the derivative set feeding this conversion step can be large
- The conversion is only meaningful for structures representable in SMILES; PROXIMAL2 queries given as InChI are internally converted to SMILES first
