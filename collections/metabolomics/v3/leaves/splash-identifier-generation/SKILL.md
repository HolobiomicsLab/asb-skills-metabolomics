# splash-identifier-generation

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Generates SPLASH (SPectraL hASH) identifiers — unambiguous, database-independent identifiers for mass spectra — from ion-intensity pairs using the reference Java implementation, so identical spectra across MassBank, MoNA, GNPS, HMDB and other libraries can be recognized as the same spectrum.

## When to use

Use when a mass spectrum (ion-intensity pairs, e.g. m/z 138.0641:71.59 195.0815:261.7) must be assigned a canonical, database-independent identifier, or when spectra from different libraries must be matched or deduplicated by identifier.

## When NOT to use

- The input is not a mass spectrum (e.g. chemical structures — use InChIKey instead, which SPLASH is modeled after for structures)
- You need a human-readable or database-native record identifier (MassBank PR100026, HMDB 5464, GNPS CCMSLIB00000222858) rather than a content-derived spectral hash
- NIST library entries must be included in an openly redistributable output — only all-but-NIST spectra are publicly available on MoNA

## Inputs

- Mass spectrum as a list of ion-intensity pairs (m/z, intensity) for SpectraType.MS
- Single-line spectrum string in 'ion:intensity ion:intensity ...' format (e.g. '138.0641:71.59 195.0815:261.7')
- CSV spectrum files for the validation tool (columns for generated SPLASH, spectrum ID/origin, and single-line spectrum, selectable via -k, -o, -s flags with delimiter -T)

## Outputs

- SPLASH string with four dash-separated blocks: identifier, two summary blocks, and SHA256-derived hash block (e.g. splash10-0002-0900000000-b112e4e059e1ecf98c5f)
- Validation tool report comparing SPLASHes generated by alternative implementations against the reference implementation
- Per-spectrum second-block values usable as search-prefilter keys (per-query candidate counts and recall metrics such as splash_second_block_evaluation.csv, splash_collision_groups.csv)

## How to apply

Build a Spectrum object from a list of ion-intensity pairs (Ion(m/z, intensity)) with SpectraType.MS and call SplashFactory.splashIt, or pass a single-line spectrum string 'ion:intensity ion:intensity ...' to SplashUtil.splash. The resulting SPLASH has four dash-separated blocks: the SPLASH identifier, two spectral summary blocks, and a SHA256-derived unique hash block (e.g. splash10-0002-0900000000-b112e4e059e1ecf98c5f for the caffeine spectrum PR100026). Build the project with 'mvn clean install' to install the SPLASH jar files in the local Maven repository, and cross-check outputs with the validation tool (java -jar validation/target/validation-1.8.jar -c -s 2 -t ms ...) against the reference implementation. When using identifiers for search-space reduction, retain only the second summary block: on the 563,902-spectrum dataset (MassBank, GNPS, HMDB, ReSpect, FiehnLib, NIST 14) the chosen second block — selected from 136 candidate block formats — reduced the candidate space by 94% or above (36,107 spectra or fewer) while returning 87% of true matches within a NIST cosine similarity score of 700. Treat fourth-block hash equality as evidence of identity only after checking that colliding spectra are single-ion spectra of the same mass; collision testing on 53.25 million spectra found no other collisions, consistent with the ~10^-31 theoretical collision probability for 10^9 spectra.

```
String splash = SplashUtil.splash("138.0641:71.59 195.0815:261.7", SpectraType.MS);
```

## Evaluation signals

- SPLASH string matches the four-block format (splash10-...-...-<40-char SHA256-derived hash>) and the caffeine example yields splash10-0002-0900000000-b112e4e059e1ecf98c5f for ions 138.0641:71.59 195.0815:261.7
- Validation tool (validation/target/validation-1.8.jar with -c -s 2 -t ms flags) reports agreement between generated SPLASHes and the Java reference implementation
- Identical spectra across libraries receive identical SPLASHes: PR100026 (MassBank/MoNA), 5464 (HMDB) and CCMSLIB00000222858 (GNPS) hash identically for caffeine
- Second-block prefilter achieves ≥94% search-space reduction (≤36,107 remaining candidates) with ~87% recall at NIST cosine similarity score 700
- Fourth-block collisions occur only among single-ion spectra of the same mass; zero non-trivial collisions, consistent with ~10^-31 collision probability at 10^9 spectra

## Limitations

- Not all spectra in the validation set are annotated with structures, limiting compound-level interpretation of SPLASH groups
- NIST spectra cannot be released publicly; SPLASH evaluations on the deposited subset exclude NIST entries
- Fourth-block hash equality alone does not guarantee identical spectra — collisions (identical SPLASHes) can arise from distinct single-ion spectra of the same mass after intensity normalization
- The full hash-collision behavior was validated on the 53.25-million-spectrum dataset; the theoretical ~10^-31 probability applies to ~10^9 spectra and does not eliminate collisions outright
