# blank-background-feature-filtering

## Summary

Removes LC-MS features that originate from background contaminants by comparing sample intensities against BLANK-labelled control runs inside the Optimus (KNIME/OpenMS) workflow, using a minimum sample-to-blank intensity ratio (default 3.0) in the 'Filter features' node.

## When to use

Use when processing spatially mapped LC-MS runs (e.g. swab or tissue-extract mzML/mzXML in Optimus) where blank or control runs are present and background features must be removed before mz-RT annotation and 'ili mapping.

## When NOT to use

- The dataset contains no BLANK-labelled control runs, so no sample-to-blank ratio can be computed
- Input is already a filtered feature table (e.g. a published features_quantification_matrix.csv), so re-filtering against blanks would be redundant
- The goal is to characterize background/contaminant chemistry itself rather than remove it

## Inputs

- Consensus feature table (features_quantification_matrix.csv) from Optimus 'Align and quantify features' node
- optimus_experimental_design.csv with LC-run type column labelling blank runs as BLANK
- Centroided mzML (or mzXML internally converted to mzML) LC-MS runs including blank/control swabs

## Outputs

- Filtered feature table with background (blank-derived) features excluded
- features_quantification_matrix.csv restricted to non-background features for downstream mz-RT annotation and 'ili input generation

## How to apply

Label blank/control runs as BLANK in the optimus_experimental_design.csv file generated by Optimus's 'Generate template of experimental design' node. After OpenMS-based feature detection ('Detect LC-MS features', e.g. 20 p.p.m. m/z tolerance and noise threshold 5,000 for QTOF data) and cross-run alignment ('Align and quantify features', RT tolerance ~30 s for a 10-min UHPLC gradient), enable the 'Filter features' node to exclude features caused by background signals present in the BLANK-labelled runs. The key decision point is the 'Minimum intensity ratio as compared to blanks' parameter, kept at its default 3.0 in the protocol's rosemary, ATM keypad, phone, and skin reproductions; features whose sample intensity does not exceed 3x the blank intensity are discarded. Rationale: removing background features before annotation and normalization prevents contaminant m/z-RT entries (e.g. from swab media or solvents) from appearing as false molecular hotspots in the final 'ili spatial maps.

## Related tools

- **Optimus** (Hosts the 'Filter features' KNIME node that applies the blank intensity-ratio cutoff (default 3.0) to the aligned consensus feature table) — https://github.com/MolecularCartography/Optimus
- **KNIME** (Workflow management platform in which the filtering step is configured and executed)
- **OpenMS** (Provides the upstream feature detection and alignment algorithms whose output features are filtered against blanks)

## Evaluation signals

- optimus_experimental_design.csv assigns the LC-run type BLANK to every blank/control run before execution
- 'Filter features' node is enabled and 'Minimum intensity ratio as compared to blanks' records 3.0 in Optimus_settings.ini
- No retained feature has a mean sample intensity below 3x its intensity in the BLANK-labelled runs
- Known blank-only contaminants (e.g. row A wells in the phone 96-well plate map) show no signal for the annotated molecules in the final maps
- Workflow completes without the ValueError 'Input list of LC-MS features is empty'

## Limitations

- Blank filtering is optional in Optimus; if blank runs are mislabelled or absent, background features pass through into the molecular maps
- The 3.0 intensity-ratio default is tuned for the protocol's swab/extraction maps; datasets with heavy carryover or very low-abundance endogenous signals may need the threshold adjusted or rarely observed features handled by other optional filters (rare-feature, QC-reproducibility, replicate-reproducibility filters)
- Filtering removes features but does not provide MS/MS validation of the retained annotations
