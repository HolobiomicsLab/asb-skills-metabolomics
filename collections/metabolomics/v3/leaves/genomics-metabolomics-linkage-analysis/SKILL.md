# genomics-metabolomics-linkage-analysis

## Summary

Computes and validates strain-correlation (Metcalf) links between gene cluster families (GCFs) and molecular families (MFs) using NPLinker, standardising raw scores against a hypergeometric null so that links are comparable across GCF and MF sizes.

## When to use

Use when paired microbial genomics (AntiSMASH/BiG-SCAPE GCFs) and metabolomics (GNPS molecular networking MFs) data must be linked and scored per strain co-occurrence, especially when raw scores must be compared across GCFs/MFs of different sizes.

## When NOT to use

- When no strain_mappings.json exists — NPLinker cannot build strain co-occurrence vectors without mapping strains to genomics and metabolomics data
- When ranking links with the Input-Output Kernel Regression (IOKR) score rather than the standardised strain correlation score
- When the genomics or metabolomics side is not in NPLinker's expected input format (GNPS molecular networking data + AntiSMASH BGCs)

## Inputs

- GNPS molecular networking data (GNPS1 or GNPS2 workflow output)
- AntiSMASH BGC regions in the `antismash` subdirectory
- BiG-SCAPE GCF clustering output (auto-generated by NPLinker if not provided)
- strain_mappings.json file mapping strains to genomics and metabolomics data
- MIBiG metadata (auto-downloaded by NPLinker)
- NPLinker TOML config file

## Outputs

- Link graph of GCF–MF pairs with raw Metcalf scores
- Standardised Metcalf scores per link (null-standardised z-scores)
- Per-link raw and standardised scores written to crusemann_link_scores.csv
- Group means for all-links and PoDP-validated link sets (Table 1 / Fig 5 values)

## How to apply

Load the Crüsemann-style dataset into NPLinker via load_config and load_data: an `antismash` directory of AntiSMASH BGC regions, BiG-SCAPE GCF clustering (auto-run by NPLinker if absent), GNPS molecular networking files, and `strain_mappings.json` to map BGC and spectrum identifiers to strains. Build strain co-occurrence vectors for each GCF and MF, then call npl.get_links over all GCFs with the "metcalf" method to obtain raw strain correlation scores for every hypothetical GCF–MF link. Standardise each raw score against its hypergeometric null expectation (expected score and standard deviation from random strain assignment), because raw scores depend on GCF and MF sizes and otherwise cannot be compared. Separately aggregate scores for the PoDP-validated link set and the all-links set: on the Crüsemann data the standardisation reverses the raw-score failure mode (all links mean -0.006 vs raw 83.514; validated links mean 3.672 vs raw 14.667), so validated links score higher than all links on average.

## Examples

```
config = load_config('path/to/nplinker.toml'); npl.load_data(); link_graph = npl.get_links(npl.gcfs, "metcalf")
```

## Evaluation signals

- Mean raw score over all links ≈ 83.514 and mean standardised score over all links ≈ -0.006 (Table 1 / Fig 5 on the Crüsemann data set)
- Mean raw score over PoDP-validated links ≈ 14.667 and mean standardised score ≈ 3.672
- Standardised validated-link mean exceeds the all-links mean (validated > background after standardisation, reversing the raw-score ordering)
- Per-link raw and standardised scores present in crusemann_link_scores.csv for every GCF–MF pair scored
- Standardised scores are null-normalised: expected score and standard deviation derive from random strain assignment, so scores are comparable across GCF and MF sizes

## Limitations

- The raw strain correlation score depends on GCF and MF sizes and therefore fails to reliably compare potential GCF–MF links before standardisation
- Validation is demonstrated on publicly available data sets that include validated links; behaviour on datasets lacking PoDP-validated links cannot be checked this way
- The article's discussion section (as captured) contains only an auto-generated changelog and no discussion of limitations or reproducibility gaps, so caveats beyond the raw-score size dependence must be assessed empirically
