# spectral-identifier-canonicalization

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Generates the SPLASH (SPectraL hASH) — an unambiguous, database-independent identifier for mass spectra composed of a splash10 identifier block, two summary blocks, and a SHA-256 hash block — from a single-line 'ion:intensity' peak-list string, enabling cross-database identity checks (e.g. the same caffeine spectrum in MassBank, HMDB, and GNPS).

## When to use

Use when two or more spectral library entries (e.g. MassBank PR100026, HMDB 5464, GNPS CCMSLIB00000222858) must be tested for being the same mass spectrum, or when a portable, hashable spectrum identifier must be computed from an ion:intensity peak list.

## When NOT to use

- The input is not a mass spectrum peak list but a chemical structure identifier — SPLASH is deliberately scoped to spectra, with InChIKey serving the analogous role for structures
- Only the second block is needed for high-precision database subsetting and a full hash is overkill; the paper positions block 2 as the search-space reducer (94% or above) rather than a unique ID
- Spectra contain a single ion only — collision testing showed identical SPLASHes arise exactly from mass spectra containing a single ion of the same mass, so hash uniqueness is not guaranteed in that edge case

## Inputs

- Single-line mass spectrum string in 'ion:intensity ion:intensity ...' format (e.g. '138.0641:71.59 195.0815:261.7')
- Spectrum type flag (SpectraType.MS; default MS)
- Optional CSV validation file with columns for spectrum string, generated SPLASH, and spectrum ID/origin

## Outputs

- Four-block SPLASH identifier string (identifier block, two summary blocks, SHA-256 hash block), e.g. splash10-0002-0900000000-b112e4e059e1ecf98c5f
- Per-block intermediate values (inspectable via a SplashListener before hashing)
- Validation-tool pass/fail report when comparing implementations

## How to apply

Parse the spectrum into the single-line format 'ion:intensity ion:intensity ...' (e.g. '138.0641:71.59 195.0815:261.7' for the MassBank caffeine record PR100026), then apply the SPLASH canonicalization: build block 1 (the SPLASH identifier, splash10), construct the second block from the summary-bin scheme selected from 136 candidate formats as the best short, web-search-compatible way to reduce the mass spectral search space, emit the third summary block, and derive block 4 via SHA-256 over the canonicalized peak representation. In Java, build a Spectrum object of Ion(m/z, intensity) pairs and pass it through SplashFactory; alternatively call SplashUtil.splash on the spectrum string directly with SpectraType.MS. Reference implementations exist in Java, C++, Python, C#, R, Ruby, and Scala, and a REST service is available. Validate by comparing the computed four-block string byte-for-byte against a known SPLASH such as splash10-0002-0900000000-b112e4e059e1ecf98c5f, or run the provided validation jar to check cross-implementation consistency.

## Evaluation signals

- Exact-match check: the computed SPLASH for the caffeine peak list 138.0641:71.59 195.0815:261.7 must equal splash10-0002-0900000000-b112e4e059e1ecf98c5f byte-for-byte
- Block-structure invariant: the output string must contain exactly four dash-separated blocks, with block 1 equal to splash10 and block 4 a SHA-256-derived hash
- Cross-implementation consistency: run java -jar validation/target/validation-1.8.jar -c -s 2 -t ms against the base-dataset test files and require zero mismatches
- Search-space behavior: block 2 should reduce the candidate search space by at least 94% (36,107 spectra or fewer out of the 563,902-spectrum dataset)
- Collision expectation: on the 53.25-million-spectrum test set, identical SPLASHes should occur only for single-ion spectra of the same mass

## Limitations

- Hash collisions occur for single-ion spectra of identical mass, even though the theoretical collision probability is roughly 10-31 for a database of 10^9 spectra
- The validation set is not fully annotated with structures, limiting compound-level checking of SPLASHes
- Implementations must agree exactly on canonicalization and hashing rules — any deviation in the canonical peak representation changes the SHA-256 block and breaks cross-tool identity
