# feature-abundance-matrix-processing

## Summary

Pre-processing of an MS-DIAL-derived feature abundance table through margheRita's filtering() chain: quality control, m/z and CV-based filtering, sample/feature thresholds, and seeded random NA imputation before statistical analysis of LC-MS/MS metabolomics data.

## When to use

Use when a tab-delimited feature abundance table (e.g. from MS-DIAL) requires pre-processing — m/z defect filtering, CV ratio filtering vs QCs, sample/feature quality thresholds, or NA imputation — prior to normalization and statistics in margheRita.

## When NOT to use

- The input is still raw instrument data or a peak table that has not yet been generated by peak-picking software (MS-DIAL) — this skill operates on an already-produced tab-delimited feature abundance table
- The analysis calls for multivariate imputation such as random-forest imputation (recommended for missing values in the notame workflow per Kokla et al.), rather than margheRita's random draw between 10%-25% of the feature minimum
- The dataset contains no NA values — imputation is skipped by design and the message 'No NAs: imputation not performed.' is reported instead

## Inputs

- Tab-delimited feature data file (feature identifiers, m/z, retention times, MS/MS spectra, abundances) generated by MS-DIAL
- Tab-delimited sample annotation file with columns id, injection_order, batch, class, biological_rep, technical_rep
- Random seed for reproducible imputation
- Parameters a and b bounding the imputation range (default 10% and 25% of the feature minimum)

## Outputs

- Filtered and imputed feature abundance matrix (e.g. written to imputed_feature_abundances.csv)
- Updated mRList object carrying filtered features and samples
- Console/log messages such as 'No NAs: imputation not performed.' and counts of removed features/samples

## How to apply

Load the tab-delimited feature data file (feature identifiers, m/z, retention times, MS/MS spectra, abundances) together with the sample annotation file (columns id, injection_order, batch, class, biological_rep, technical_rep) into an mRList object in R. Run margheRita's filtering() chain: m_z_filtering() removes features whose m/z decimal value falls within [4, 8] by default; sample filtering keeps samples with >= 100 metabolites and feature filtering keeps features occurring in >= 3 samples; the CV ratio filter retains only features whose coefficient of variation ratio between no-QC samples and QC samples exceeds a threshold (default 1). For imputation, imputation(mRList, seed, a, b) replaces each NA abundance with a seeded random number drawn between a=10% and b=25% of the minimum observed value of the corresponding feature; when the table contains no NAs the step is skipped and the message 'No NAs: imputation not performed.' is reported. Downstream, the chain supports log normalization, reference normalization and probabilistic quotient normalization, and technical replicates can be collapsed over samples sharing the same concatenation of class and biological_rep values. The rationale is that metabolomics-specific thresholds (mass defects, sample-vs-QC CV) remove low-quality features before statistical testing while small random fraction-of-minimum values keep sparse NA structure from dominating downstream tests.

## Examples

```
R: imputed <- imputation(mRList, seed = 123, a = 0.10, b = 0.25)
```

## Evaluation signals

- After imputation, the output abundance matrix contains no NA values (verified in imputed_feature_abundances.csv)
- When the input table has no NAs, the console reports 'No NAs: imputation not performed.' and the matrix is unchanged by the imputation step
- No retained feature has an m/z decimal value within [4, 8]
- Every retained sample has >= 100 metabolites and every retained feature occurs in >= 3 samples
- Re-running with the same seed reproduces identical imputed values (imputed abundances lie between 10% and 25% of the corresponding feature minimum)

## Limitations

- Imputation is a simple seeded random draw between 10%-25% of the feature minimum, not a model-based (e.g. random forest) approach; notame's README notes random forest imputation is recommended for missing values per Kokla et al.
- Default thresholds (m/z decimal window [4, 8], >= 100 metabolites per sample, >= 3 samples per feature, CV ratio threshold 1) are dataset-dependent and may need adjustment
- If the table contains no NAs the imputation step is skipped entirely, so downstream statistics must not assume imputation was applied
