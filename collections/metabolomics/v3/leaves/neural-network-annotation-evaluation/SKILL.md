# neural-network-annotation-evaluation

## Summary

Evaluate neural-network metabolite annotation models (MLP, GNN, ensemble ESP) using average rank and Rank@K metrics on candidate sets, and compute relative percentage improvements between models to verify claimed performance gains.

## When to use

Use when comparing annotation models (e.g. ESP vs MLP/GNN baselines) on mass spectra candidate sets and you must reproduce or verify reported average-rank improvements such as 23.7%/37.2%.

## When NOT to use

- Comparing models on top-five hit rate only, where the paper notes MLP approaches remain strong contenders and average rank may mislead
- Evaluating on NIST-20-trained models where the data cannot be published due to NIST license regulations and cannot be retrained locally
- Candidate sets whose size or candidate-similarity-to-target differs from the evaluation configuration, since annotation performance depends on these factors

## Inputs

- Test candidate set file (torch_tecand_1000bin_te_cand100...torchgeometric.pkl) generated by data_tecand.py
- Pretrained model checkpoints (e.g. best_model_mlp_can.pt, best_model_gnn_can.pt, ESP_can.pt)
- Reported average rank values from paper results tables or printed model output

## Outputs

- Average rank with standard deviation per model (e.g. 'Average rank 279.557 +- 1170.300')
- Rank at 1 through Rank at 20 curves per model
- Relative improvement percentages vs each baseline, e.g. (rank_MLP - rank_ESP)/rank_MLP*100 = 23.7%

## How to apply

Run each pretrained model (MLP, GNN via train.py; ESP via ens_train_canopus.py) over a test candidate set generated by data_tecand.py (e.g. torch_tecand_1000bin_te_cand100), which prints the 'Average rank' with standard deviation and Rank at 1..20. Extract the average rank per model for the same trained-on/evaluated-on configuration (e.g. NIST-20-trained models on PubChem candidate sets). Compute relative improvement with numpy as (rank_baseline - rank_model) / rank_baseline * 100 for each baseline. Compare computed percentages against claimed values (23.7% vs MLP, 37.2% vs GNN) within rounding tolerance, and inspect Rank@1..20 since MLP approaches remain strong contenders at top-five ranks even when average rank favors the ensemble.

- **train.py** (Trains/restores saved GNN and MLP models and prints Average rank and Rank@K on the test candidate set) — https://github.com/HassounLab/ESP

## Examples

```
python train.py --cuda 0 --model gnn --disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology --correlation_mat_rank 100 --model_file_suffix gnn_can --full_dataset
```

## Evaluation signals

- Computed relative improvement of ESP over MLP equals 23.7% (within rounding tolerance)
- Computed relative improvement of ESP over GNN equals 37.2% (within rounding tolerance)
- Model output prints the 'Average rank <value> +- <std>' line with a Rank at 1..20 series, e.g. 'Average rank 279.557 +- 1170.300' for ESP on NPLIB1
- All compared models are evaluated on the identical test candidate suffix (e.g. --te_cand_dataset_suffix torch_tecand_1000bin_te_cand100)
- Rank@K values are monotone non-decreasing from Rank at 1 to Rank at 20 for every model

## Limitations

- NIST-20 training data cannot be published alongside NIST-20-trained models due to NIST license regulations; published pretrained models and datasets are for NPLIB1 only
- Annotation performance depends on the training dataset, the number of molecules in the candidate set, and candidate similarity to the target molecule, so improvement percentages are configuration-specific
- The 23.7%/37.2% claims are for average rank; MLP approaches remain strong contenders when considering top five ranks
- README demo command for the pretrained MLP passes --model gnn with model_file_suffix mlp_can, an apparent copy-paste inconsistency to watch for when reproducing
