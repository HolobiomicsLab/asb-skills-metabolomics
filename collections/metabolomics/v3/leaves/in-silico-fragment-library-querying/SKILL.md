# in-silico-fragment-library-querying

## Summary

Querying experimental MS/MS fragments against in silico lipid fragmentation libraries (e.g. LipidBlast-derived .csv libraries covering >250,000 lipid species across 56 lipid types) to match observed fragment m/z values within a ppm tolerance and assign binary fragment-presence flags used for rule-based lipid identification.

## When to use

Use when you have ddMS2-topN or AIF high-resolution tandem MS spectra (.ms2 files) and candidate lipid precursors from exact-mass MS1 matching, and need to match experimental fragment m/z values against simulated in silico fragmentation library values to assign lipid identifications.

## When NOT to use

- Data acquired on Waters instruments - the README states the software 'does not currently support Waters files'
- When you only have precursor m/z without tandem MS data - the identification would fall to level 4 (precursor m/z only) and the fragment-matching step adds no value beyond the MS1 exact-mass matching stage
- When the in silico library lacks the necessary structural fragments for the lipid type of interest - users must develop their own fragmentation libraries in Excel for full customization, and without the required fragments no identification is possible

## Inputs

- Feature-lipid candidate pairs from MS1 exact-mass matching
- Peak-picked MS/MS data in .ms2 file format (generated by MSConvert from ddMS2-topN or AIF acquisitions)
- In silico fragmentation library in .csv format (e.g. LipidBlast-derived libraries covering >250,000 lipid species across 56 lipid types)
- User-defined m/z tolerance (Da) for precursor matching
- User-defined ppm tolerance for fragment matching
- User-defined minimum intensity and minimum scan-count thresholds
- Retention-time window defining which MS/MS scans are associated with each feature

## Outputs

- Per-lipid-class .csv fragment statistics tables containing scan count, average m/z, maximum intensity, RT at max intensity, and a binary fragment-presence flag for every feature-lipid pair
- Lipid identifications assigned at levels 1-4 (class + fatty acyl constituents; DIA; class-only; precursor m/z-only)
- Ranked lipid identifications per feature, ordered by summed fragment intensity

## How to apply

Take the feature-lipid candidate pairs produced by the MS1 exact-mass matching stage (user-defined Da tolerance at the precursor level) together with the peak-picked .ms2 files produced by MSConvert. Select MS/MS scans that fall within a user-defined retention-time and m/z tolerance of each feature, where the m/z tolerance equals the isolation window used for ion selection. Match experimental fragment m/z values against the candidate's in silico fragment m/z values using a ppm tolerance window; for each matched fragment compute the total scan count, average m/z, maximum intensity, and the retention time at maximum intensity across all scans. Assign each fragment a binary flag: 1 if it exceeds the user-defined minimum intensity and minimum scan-count threshold (default 1 scan for orbitrap data), 0 otherwise or if the fragment is absent. Lipids are identified only if the user-designated necessary fragments for that lipid type are observed, with ranking of candidate identifications by the summed intensity of all fragments with exact-mass matches.

## Examples

```
Rscript LipidMatch.R --feature_table my_features.csv --ms2_dir ./ms2/ --lipid_library LipidBlast_250k.csv --ppm_tol 5 --min_scans 1
```

## Evaluation signals

- Each .csv fragment statistics table is saved for the corresponding lipid class and every fragment's binary flag is 1 only when the fragment was found within the ppm tolerance AND met both the intensity and scan-count thresholds, and 0 when it did not or was absent.
- The number of matched fragments per candidate lipid equals the number of rows flagged 1 in the .csv table for that lipid class.
- The sum of fragment intensities used for ranking equals the sum of the maximum intensities across all fragments with exact-mass matches, including those not used for confirmation.
- No candidate lipid is identified as level 1 (class + fatty acyl constituents) unless every user-designated necessary fragment for that lipid type is flagged 1.
- The average m/z of each matched fragment falls within the user-defined ppm tolerance of the in silico fragment exact mass.

## Limitations

- The software does not currently support Waters files.
- LipidMatch was tested on Windows 7 through 10 and pinned to R version 3.3.3; cross-platform behavior is not documented.
- The default minimum scan-count threshold is 1 scan for orbitrap data, which may be too permissive for noisier Q-TOF data.
- The m/z tolerance for scan selection must equal the isolation window used for ion selection; misconfiguration here will silently exclude valid MS/MS scans.
- Users must develop their own fragmentation libraries in Excel for full customization, and the necessary fragments per lipid type must be user-designated - incorrect designation leads to false negatives.
