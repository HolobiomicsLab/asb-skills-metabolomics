# sparql-query-validation

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Validates and reconciles exported LOTUS structure-organism pair records against the live Wikidata knowledge base using SPARQL queries, ensuring upserted entities are correctly created or updated before public dissemination.

## When to use

Use when exporting curated structure-organism pairs from LOTUS to Wikidata and you need to verify that the upserted chemical, organism, and reference entities exist and are correctly linked in the live knowledge base.

## When NOT to use

- When you only need to add, edit, or delete individual LOTUS entries manually in the Wikidata web UI — no batch SPARQL reconciliation is required.
- When the input is the raw, unvalidated 2.5M+ initial pairs rather than the manually and automatically validated ~750,000 curated subset.

## Inputs

- curated LOTUS table.tsv.gz from Zenodo deposit 10.5281/zenodo.5794106
- batch upsert records generated by npwdimporter from lotus-wikidata-interact
- Wikidata knowledge base queried via SPARQL endpoint

## Outputs

- wikidata_structure_organism_pairs.csv
- SPARQL query results confirming entity existence and property-value links for sampled pairs

## How to apply

Load the curated LOTUS table.tsv.gz deposit (DOI 10.5281/zenodo.5794106) and map each row's chemical structure, biological organism, and reference fields onto the Wikidata properties used by LOTUS. Generate batch upsert records with the programs from the lotus-wikidata-interact repository (npwdimporter), which first check whether the grouped structure, organism, and reference entities already exist in Wikidata. Before committing the batch, run SPARQL queries (e.g. via the Wikidata Query Service) against the live graph to confirm that sampled entities exist and carry the expected LOTUS property values. Write the reconciled records to wikidata_structure_organism_pairs.csv and confirm the file is parseable, with sampled pairs reconcilable against Wikidata entries — mirroring the NPimporterBot activity overview that showed correct entity linking.

## Related tools

- **NPimporterBot** (Automated bot whose upload activity (using npwdimporter batch programs) produces the Wikidata entries that SPARQL queries then validate.) — https://github.com/lotusnprod/lotus-wikidata-interact
- **SPARQL** (Query language used to check whether structure, organism, and reference entities already exist in Wikidata and to reconcile sampled upserted pairs.)

## Examples

```
python -m lotus_wikidata_interact.uploadLotus --input table.tsv.gz --output wikidata_structure_organism_pairs.csv && sparql --query check_entity.sparql
```

## Evaluation signals

- wikidata_structure_organism_pairs.csv is present, parseable, and non-empty.
- Sampled pair records can be reconciled against live Wikidata entries via SPARQL queries, matching the NPimporterBot activity overview.
- Each validated record carries a curated chemical structure, biological organism, and reference — matching the ~750,000 curated subset definition.
- SPARQL checks confirm entities either already exist or were created by the upsert, without orphaned references.

## Limitations

- Wikidata lacks some typical queries of molecular electronic NP resources, such as structural or spectral searches, so SPARQL reconciliation cannot validate chemical similarity in this hosting layer.
- The dual-hosting approach (Wikidata + LNPN) exists precisely to address Wikidata's structural-search gaps, meaning SPARQL validation alone does not cover the full LNPN search surface.
