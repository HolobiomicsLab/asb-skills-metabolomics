# chromatographic-peak-alignment-input-preparation

## Summary

Prepare the input for IDSL.CSA composite spectra deconvolution by first running IDSL.IPA on raw LC/HRMS files (mzXML, mzML, netCDF) to produce per-file peaklists and an aligned peak table, then wiring the peaklists and peak_alignment directory addresses into the IDSL.CSA parameter spreadsheet (CSA0008/CSA0009).

## When to use

Use when raw LC/HRMS data (mzXML, mzML, netCDF) must be converted into chromatographic m/z-RT peaklists and an aligned peak table before running the CSA, DDA, or DIA deconvolution workflows of IDSL.CSA.

## When NOT to use

- When the input is already a processed peak table or aligned feature table that lacks the IDSL.IPA peaklists/peak_alignment directory structure expected by CSA0008/CSA0009.
- When the goal is direct MS2-based annotation from MS/MS library searches rather than MS1-only composite spectra construction — in that case use IDSL.FSA or a conventional MS/MS search instead.
- When only raw spectra exist and no IDSL.IPA chromatographic information has been generated yet; IDSL.CSA cannot be run until the IPA peak-picking step is done.

## Inputs

- Raw LC/HRMS mass spectrometry data (mzXML, mzML, netCDF) for an untargeted metabolomics study
- peaklists directory generated by the IDSL.IPA workflow (chromatographic m/z-RT peak information per file)
- peak_alignment directory generated by the IDSL.IPA workflow (aligned peak table)

## Outputs

- Configured IDSL.CSA parameter spreadsheet (CSA_parameters.xlsx) with CSA0008, CSA0009, CSA0005 and CSA0011 populated
- IDSL.CSA workflow run over the aligned peaklists, producing CSA_MSP (.msp composite spectra library), CSA_adduct_annotation, peak_alignment_subset, and aligned_spectra_table outputs

## How to apply

Process the raw mass spectrometry data with the IDSL.IPA workflow to acquire chromatographic information of the peaks (m/z-RT), which generates a peaklists directory and a peak_alignment directory (plus individual and aggregated aligned peaklists). Download the IDSL.CSA parameter spreadsheet (CSA_parameters.xlsx) and point CSA0008 to the IDSL.IPA peaklists directory and CSA0009 to the peak_alignment directory; also set CSA0005 to the MS1-level HRMS data location and CSA0011 to the output location. Set PARAM0001 to YES to run only the CSA workflow and adjust the processing threads via CSA0004 according to available compute. Run the workflow with library(IDSL.CSA); IDSL.CSA_workflow('<address of the CSA parameter spreadsheet>'). The rationale is that CSA deconvolution correlates MS1 ions across chromatographic profiles, so it needs the peak-picking and alignment outputs that IDSL.IPA already produces for population-size studies.

## Related tools

- **IDSL.IPA** (Upstream peak-picking and alignment tool: extracts peaks (m/z-RT) from untargeted LC/HRMS data and generates the peaklists and peak_alignment directories consumed by IDSL.CSA.) — https://github.com/idslme/IDSL.IPA
- **IDSL.CSA** (Downstream consumer: takes the IPA peaklists and peak_alignment directory addresses (CSA0008/CSA0009) via its parameter spreadsheet and runs chromatogram deconvolution into composite spectra.) — https://cran.r-project.org/package=IDSL.CSA

## Examples

```
library(IDSL.CSA); IDSL.CSA_workflow("Address of the CSA parameter spreadsheet")
```

## Evaluation signals

- The peaklists and peak_alignment directories supplied to CSA0008/CSA0009 were generated by IDSL.IPA for the same mzXML/mzML/netCDF study (file inventory matches).
- PARAM0001 is set to YES so only the CSA workflow is processed.
- The CSA0011 output location contains CSA_MSP (.msp), CSA_adduct_annotation, peak_alignment_subset, and aligned_spectra_table folders.
- Aligned peak table row counts and peak counts are consistent with the IPA study scale (IDSL.IPA supports population-size untargeted studies, n > 500).
- Aggregation on the aligned peak table can carry meta-variables such as InChIKey, SMILES, precursor type, and molecular formula (PARAM0006 behaviour) when reference library information is available.

## Limitations

- IDSL.CSA requires that mass spectrometry data 'should be processed using the IDSL.IPA workflow to acquire chromatographic information of the peaks (m/z-RT)' before the CSA step — it cannot run on raw vendor data alone.
- Full-scale CSA analysis needs 39 parameters distributed across 5 sections of the spreadsheet, so mis-setting one (e.g. CSA0008 or CSA0009) breaks the run.
- Parameter defaults are tailored to the ST002263-style HILIC-ESI-POS/NEG Orbitrap studies; other instrument modes may need parameter re-tuning.
- Thread count (CSA0004) must be adjusted to available computational power; parallel processing applies to Windows and Linux environments.
