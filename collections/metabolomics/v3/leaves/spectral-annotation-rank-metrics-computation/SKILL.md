# spectral-annotation-rank-metrics-computation

## Summary

Computes average rank (with standard deviation) and Rank@K for k=1..20 to evaluate how well a spectral prediction model (MLP, GNN, or the ESP ensemble) ranks the true molecule within a PubChem-derived candidate set, as used in the ESP paper on NIST-20/NPLIB1.

## When to use

Use when evaluating metabolite spectral annotation models on candidate sets — you need average rank and Rank@K (k=1..20) to compare models like ESP, MLP-PD, and GNN-PD on the same test spectra.

## When NOT to use

- When the goal is to train a new model rather than evaluate saved models — training omits --te_cand_dataset_suffix and does not produce candidate rankings.
- When no candidate sets exist for the test spectra (e.g. only raw NIST-20 spectra without PubChem-derived candidates); ranking metrics require a candidate pool per spectrum.
- When data is NIST-20 licensed material — the NIST-20 training data cannot be redistributed, only the pretrained MLP/GNN/ESP models and NPLIB1 data are available.

## Inputs

- Test candidate set file torch_tecand_<bins>bin_te_cand<cand_size>_torchgeometric.pkl (e.g. torch_tecand_1000bin_te_cand100)
- Pretrained model checkpoints, e.g. best_model_mlp_pd.pt, best_model_gnn_pd.pt, or an ESP ensemble checkpoint
- Test split of spectra with known true-molecule labels (NIST-20 test set or NPLIB1 test data)

## Outputs

- Average rank over the test set with standard deviation (e.g. 'Average rank 213.597 +- ...')
- Rank@K values for k = 1 through 20 (e.g. Rank at 1 0.187, Rank at 10 0.490)
- Per-spectrum ranked candidate lists

## How to apply

Run the pretrained model in evaluation mode on a test candidate set (e.g. torch_tecand_1000bin_te_cand100 generated by data_tecand.py), passing flags that disable auxiliary heads: --disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology with --correlation_mat_rank 100. For the ensemble, run ens_train_canopus.py in 'canopus' mode with the pretrained MLP and GNN model suffixes. The scripts output the candidate ranking per test spectrum and report 'Average rank X +- Y' followed by 'Rank at k' for k=1 through 20. Rationale: average rank captures full-ranking quality while Rank@K captures top-k hit rate, and the ESP paper reports both to show ESP (e.g. average rank 213.597, Rank@1 0.187, Rank@10 0.490) improves 23.7% over MLP and 37.2% over GNN baselines.

## Examples

```
python train.py --cuda 1 --model gnn --model_file_suffix gnn_pd --disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology --correlation_mat_rank 100 --te_cand_dataset_suffix torch_tecand_1000bin_te_cand100
```

## Evaluation signals

- Output must print 'Average rank <value> +- <std>' followed by 'Rank at k' lines for k=1..20.
- ESP average rank should be lower than both MLP-PD and GNN-PD on the same candidate set (reported ~23.7% better than MLP, 37.2% better than GNN).
- Rank@K must be monotonically non-decreasing in k and ESP Rank@1 ≈ 0.187, Rank@10 ≈ 0.490 in the paper's reported configuration.
- Rank@K values should fall within the ranges shown in the README's expected-output logs for the corresponding model suffix.
- Candidate-set suffix passed via --te_cand_dataset_suffix must match the file generated by data_tecand.py (e.g. torch_tecand_1000bin_te_cand100).

## Limitations

- Annotation performance depends on the training dataset, the number of molecules in the candidate set, and candidate similarity to the target molecule, so metrics are only comparable across identical candidate sets.
- NIST-20 training data cannot be published due to NIST license regulations; published pretrained models and datasets are for NPLIB1 only.
- Ranking metrics can be dominated by spectra with huge candidate sets (large standard deviations, e.g. 1264.715 in the README demo), so average rank alone may mislead.
