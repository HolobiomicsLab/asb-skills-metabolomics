# spectral-preprocessing-pipeline-execution

## Summary

Execute subMALDI's R pipeline to organize, pre-process (smooth, baseline-correct, peak-detect), normalize, average, and blank-subtract irregularly-spaced MALDI-MS/ESI-MS replicate spectra held as plain data frames, keeping m/z and intensity values accessible at every step.

## When to use

Use when irregularly-spaced MALDI-MS or ESI-MS replicate spectra are stored as R data frames (m/z in the first column, replicate intensities in adjacent columns) and need averaging, blank subtraction, or full pre-processing without S3/S4 object masking.

## When NOT to use

- Spectra are already held in S3/S4 class objects from other R packages (e.g. MALDIquant or MSnbase workflows) and you do not need subMALDI's data-frame-native design
- The analysis goal is something outside subMALDI's stated scope of organization, pre-processing (smoothing, baseline correction, peak detection), and normalization — e.g. de novo spectral identification or database searching
- Input is not m/z/intensity spectral data (e.g. already-reduced peak tables or feature matrices), since the pipeline operates on aligned m/z-vs-intensity data frames

## Inputs

- R data frames of irregularly-spaced MALDI-MS replicate spectra with m/z values in the first column and replicate intensity columns adjacent (e.g. sample replicates 'Before1', 'Before2')
- Matrix blank replicate spectra columns (e.g. 'Blank1', 'Blank2') in the same data frame layout
- subMALDI package installed from source tarball (e.g. subMALDI-1.0-2.tar.gz) with MassSpecWavelet and CRAN dependencies present

## Outputs

- Averaged blank intensity column produced by avgSpectra(method = 'mean')
- Blank-subtracted sample intensity columns (e.g. 'Sub_Before1', 'Sub_Before2') generated by subSpectra(Blank_Var = 'Average')
- Processed data frames retaining all m/z values in the first column with each replicate's intensities in adjacent columns, aligned to the specified m/z resolution

## How to apply

Install subMALDI from source: first install the BioConductor dependency MassSpecWavelet via BiocManager, then the CRAN packages (tidyr, ggplot2, ggpmisc, reshape2, RColorBrewer, signal), then install the package tarball with type = "source" and dependencies = TRUE. Load spectra so that all theoretically possible m/z values occupy the first column and each replicate's intensities sit in adjacent columns, aligning processed values to an m/z grid at a specified resolution. For matrix blank correction, average blank replicates (e.g. 'Blank1' and 'Blank2') with avgSpectra using method = 'mean', then call subSpectra with Blank_Var = 'Average' on each sample column (e.g. 'Before1' and 'Before2') to generate 'Sub_Before1'/'Sub_Before2' intensity columns. The no-masking design (no S3/S4 objects) means every intermediate data frame remains inspectable and compatible with functions from other R packages, so validate at each step by inspecting the returned columns.

## Evaluation signals

- The averaged blank column equals the mean of the matrix blank replicates (e.g. mean of 'Blank1' and 'Blank2') as computed by avgSpectra(method = 'mean')
- subSpectra with Blank_Var = 'Average' produces 'Sub_Before1' and 'Sub_Before2' columns whose values reproduce the blank-subtracted intensities shown in the subMALDI workflow vignette output
- Output data frame retains all m/z values in the first column with each replicate's intensities in adjacent columns, at the specified mass-range resolution
- Data remain plain data frames throughout — no S3/S4 class masking, so intermediate columns are directly inspectable after every processing step
- Installation succeeds with subMALDI installed from source (type = "source", dependencies = TRUE) after MassSpecWavelet and the listed CRAN packages are present

## Limitations

- The README notes the BioConductor install sequence 'doesn't always seem to work'; installing from source with dependencies = TRUE is the recommended workaround
- No software version numbers are stated for subMALDI, R, or any dependency, and no changelog/version history is provided, complicating reproducibility
- No DOI or data availability statement is given for the datasets used in the workflow vignette, so exact input files may need to be sourced from the package itself
- Alignment to the m/z grid requires the user to specify the mass range and resolution; no defaults or tolerances are stated in the provided context
