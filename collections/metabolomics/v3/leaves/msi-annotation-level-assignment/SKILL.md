# msi-annotation-level-assignment

## Summary

Assigns Metabolomics Standards Initiative (MSI) confidence levels to compound matches by filtering on main-peak isotope status, adduct and source database, then sorting by ppm error and collapsing duplicate SMILES — yielding MSI level 2 'putatively annotated compound' labels in MetaboShiny's annotation workflow.

## When to use

Use when significant m/z hits from statistical analysis (e.g. a t-test on DI-MS/LC-MS peak tables) need putative metabolite annotations with MSI confidence levels after a compound-database m/z search.

## When NOT to use

- Input is raw peak data — MetaboShiny does not accept raw peak data and requires pre-processed peak tables (e.g. from XCMS or MSnbase)
- The goal is to annotate all m/z values rather than significant hits — MetaboShiny restricts metabolite annotation to significant hits resulting from the analysis
- Confirmation-level (MSI level 1) identifications are required without reference-standard confirmation — this workflow yields putative MSI level 2 annotations for most hits

## Inputs

- List of significant m/z hit values from MetaboShiny statistical analysis (e.g. t-test results)
- Compound match table from the MetaboShiny/MetaDBparse database search, including adduct, isotope label, ppm error and source database metadata
- User-defined mass spectrometer error margin in parts per million (ppm), set during file import
- Locally built compound database (e.g. HMDB) with pre-generated isotope/adduct m/z values

## Outputs

- filtered_annotations.csv — prioritized annotation table with adduct, isotope and database filtering fields, MSI level labels, sorted by ppm error
- annotation_counts.csv — exact row count per MSI level (e.g. 4 m/z at MSI level 1 and 264 at the next level)

## How to apply

Load the compound match results produced by searching significant m/z values (e.g. the 264, 308, 441, 561 m/z lung cancer urine hits) against a locally built database (e.g. HMDB, pre-generated by MetaDBparse with over twenty common adducts and isotopes per compound), within the user-defined ppm error margin set at file import. Filter matches first by main peak isotopes (the 100% peak), then score and prioritize survivors by adduct and isotope status alongside source database, sorting within the mass tolerance by ppm error. Collapse rows sharing identical SMILES into single annotation entries while keeping distinct structural isomers (same formula, different SMILES) as separate rows. Assign MSI level 1 for confirmed identifications (e.g. creatine riboside as the M + H adduct of 264 m/z) and MSI level 2 'putatively annotated compound' for the remaining prioritized hits, and write the result to filtered_annotations.csv plus per-level tallies in annotation_counts.csv.

## Evaluation signals

- The output table contains adduct, isotope and database filtering fields
- All retained hits carry MSI level 2 'putatively annotated compound' labels (or level 1 where confirmed) and are sorted by ppm error within the user-defined mass tolerance
- Rows sharing identical SMILES are collapsed to one entry while structural isomers (same formula, different SMILES) remain separate rows
- annotation_counts.csv tallies exactly reproduce the reported counts per MSI level (e.g. 4 m/z at MSI level 1)
- Only main-peak (100%) isotopes are retained in the filtered table

## Limitations

- Metabolite annotation occurs only on significant hits from the statistical analysis, not on all detected m/z values
- Isotope scoring for compounds with the same weight currently supports only the M-score method (default 2% intensity imprecision)
- Databases are not automatically updated — re-building is a manual user step
- MSI level 2 labels are putative only; separating them from confirmed MSI level 1 identifications is required per the Metabolomics Standards Initiative
