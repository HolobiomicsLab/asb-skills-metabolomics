# closed-form-acquisition-numerical-validation

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Numerically validates a Bayesian-optimization decision rule (here BAGO's Expected Improvement acquisition over a Matern-3/2 Gaussian-process surrogate) by comparing an implementation against the closed-form EI formula on controlled Gaussian posterior test cases with a fixed exploration parameter (delta = 0.01).

## When to use

Use when you must verify that an acquisition-function implementation (EI over a fitted GP surrogate) reproduces the analytic closed-form values before trusting argmax-based gradient or parameter selection.

## When NOT to use

- When the acquisition function is not Expected Improvement over a Gaussian-process posterior — closed-form EI validation does not transfer to other acquisition rules
- When inputs are raw LC-MS mzML/mzXML data rather than already-encoded gradients and separation-efficiency outputs; data extraction is a separate upstream step

## Inputs

- Controlled Gaussian posterior test cases (posterior mean, standard deviation, current best observed value)
- Encoded LC-gradient inputs X and separation-efficiency outputs y
- Candidate gradient search space generated by genSearchSpace (gridX)

## Outputs

- Per-case EI deviation between implemented and closed-form Expected Improvement
- Maximum absolute deviation across all controlled Gaussian posterior cases
- Next LC gradient selected by argmax of EI via computeNextGradient(acqFunc='ei')

## How to apply

Define controlled Gaussian posterior test cases that vary posterior mean, standard deviation, and the current best observed value, fixing the exploration parameter delta = 0.01 for the EI formula. Build the surrogate as a scikit-learn GaussianProcessRegressor with a Matern32 kernel and fit it to encoded LC-gradient inputs X and separation-efficiency outputs y via gpModel.fit(X, y). Generate the candidate gradient search space with genSearchSpace, mirroring BAGO's encode-then-scale preprocessing. Implement the closed-form Expected Improvement from the posterior mean and standard deviation relative to the current best solution, then compare it against the implemented EI on every controlled Gaussian posterior case, recording the deviation per case and the maximum absolute deviation. Finally run the full decision rule end-to-end by invoking computeNextGradient with acqFunc='ei' (the BAGO default) to select the next gradient by argmax of EI over the search space.

## Related tools

- **scikit-learn** (Provides the GaussianProcessRegressor surrogate fitted with a Matern32 kernel to produce the posterior mean and standard deviation used in the EI computation) — https://github.com/HuanLab/bago
- **BAGO** (Supplies gpModel.fit, genSearchSpace, and computeNextGradient(acqFunc='ei') that constitute the decision rule being validated) — https://github.com/HuanLab/bago
- **Python** (Language in which the closed-form EI formula and controlled Gaussian posterior test cases are implemented and compared) — https://github.com/HuanLab/bago

## Examples

```
model = GaussianProcessRegressor(kernel=Matern32()); model.fit(X, y); xnext = bago.computeNextGradient(model, acqFunc='ei')
```

## Evaluation signals

- Implemented EI matches the closed-form EI on every controlled Gaussian posterior test case within floating-point tolerance, with the maximum absolute deviation reported per case
- The exploration parameter is exactly delta = 0.01 in the EI formula for all cases
- computeNextGradient with acqFunc='ei' completes without error and returns a gradient from the generated search space
- The surrogate is a scikit-learn GaussianProcessRegressor using a Matern32 kernel, consistent with the BAGO implementation
- Argmax-EI gradient selection agrees with the closed-form EI ranking across all test cases

## Limitations

- Validation is specific to EI with delta = 0.01; other exploration parameters or acquisition functions require re-deriving closed-form references
- The Matern32 kernel assumption of the surrogate may not hold for other GP kernels used in BAGO extensions
- Floating-point tolerance is the acceptance criterion, so cases with extreme posterior variances may show larger numerical deviation
