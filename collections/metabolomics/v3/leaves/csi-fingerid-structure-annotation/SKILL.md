# csi-fingerid-structure-annotation

## Summary

Converts per-feature MZmine 'Export for SIRIUS' MS2 spectra (.mgf) plus MS1 isotopic patterns into per-feature molecular formulas (with ZODIAC re-ranking), 2D structure candidates from CSI:FingerID searched against biological databases, and CANOPUS chemical-class predictions within the ENPKG workflow.

## When to use

Use when feature detection is complete (e.g., MZmine feature lists with associated MS2 scans in .mgf for 'Export for SIRIUS') and per-feature in-silico formula, 2D structure, and chemical-class candidates are needed for a knowledge-graph metabolomics annotation stage.

## When NOT to use

- The goal is spectral matching against an experimental library (e.g., GNPS-style FBMN matching) rather than in-silico formula/structure candidate enumeration — ENPKG pairs this skill with ISDB-LOTUS annotations instead of replacing them
- The input is already a feature-quantification table without the per-feature MS2 scans and MS1 isotopic patterns required by SIRIUS
- Compounds of interest exceed the maximum m/z of 800 enforced in this configuration

## Inputs

- Per-sample 'Export for SIRIUS' files from MZmine: feature MS1 isotopic patterns and MS2 spectra in .mgf format
- Feature lists filtered to features with an associated MS2 scan
- Ionization-mode specification (PI and/or NI) per sample

## Outputs

- Per-feature SIRIUS/CSI:FingerID annotation records (formula candidates re-ranked by ZODIAC and structure candidates searched against biological databases)
- Per-feature CANOPUS chemical-class predictions
- NPClassifier natural-product taxonomy terms for candidate anisomeric SMILES
- Collated annotation records with stored versions/parameters as sub-properties of enpkg:has_sirius_annotation

## How to apply

Collect the per-sample 'Export for SIRIUS' files (feature MS1 isotopic patterns and MS2 spectra, .mgf) generated by MZmine. Run SIRIUS with ZODIAC formula re-ranking and a CSI:FingerID structure search restricted to biological databases: in PI mode use SIRIUS v4.9.12 with adducts [M + H]+, [M + NH4]+, [M + K]+, [M + Na]+, and in NI mode SIRIUS v5.5.4 with adducts [M – H]−, [M + K-2H]−, [M + Na-2H]−; in both modes use a 10 ppm tolerance, maximum m/z 800, and consider 10 candidates. Run CANOPUS on the same feature spectra of both ionization modes (no additional parameters) to predict chemical classes. Submit the anisomeric SMILES of the candidate 2D structures to the NPClassifier API to retrieve natural-product taxonomy. Collate the per-feature SIRIUS/CSI:FingerID and CANOPUS records with the automated ENPKG script at 04_enpkg_sirius_canopus, saving the parameters used at each step so they are retrievable from the graph as sub-properties of enpkg:has_sirius_annotation (e.g., enpkg:has_sirius_annotation_00c339c3b183cb7fbf466b4d334dbef2).

## Evaluation signals

- Every feature with an associated MS2 scan carries formula/structure candidates within the 10 ppm parent-mass tolerance
- Run versions and parameters are retrievable from the graph as sub-properties of enpkg:has_sirius_annotation (e.g., enpkg:has_sirius_annotation_00c339c3b183cb7fbf466b4d334dbef2)
- Both ionization modes are represented: PI-mode runs show the v4.9.12 adduct set ([M + H]+, [M + NH4]+, [M + K]+, [M + Na]+) and NI-mode runs the v5.5.4 adduct set ([M – H]−, [M + K-2H]−, [M + Na-2H]−)
- CANOPUS class predictions exist for features in both ionization modes, and NPClassifier terms are attached to candidate anisomeric SMILES
- Comparing SIRIUS/CSI:FingerID outputs with ISDB-LOTUS annotations: agreeing results from both approaches strengthen confidence in spectral annotations

## Limitations

- Structure search is restricted to biological databases, so non-natural-product candidates are out of scope by design
- Maximum m/z is capped at 800 and only a fixed adduct list per ionization mode is considered; features ionized differently will not be annotated
- Results are candidate lists (10 candidates considered), not definitive identifications; confidence should be judged by agreement with complementary approaches such as ISDB-LOTUS
- The workflow requires a locally installed Sirius binary with account credentials (PATH_TO_SIRIUS, SIRIUS_USERNAME, SIRIUS_PASSWORD in .env), which is a machine-specific dependency
