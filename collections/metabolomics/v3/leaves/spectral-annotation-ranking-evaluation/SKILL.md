# spectral-annotation-ranking-evaluation

## Summary

Evaluate metabolite-annotation candidate-ranking models (ESP, MLP, GNN) by running pretrained checkpoints over torchgeometric test-candidate files and reporting average rank (with standard deviation) plus Rank@1 through Rank@20 metrics.

## When to use

Use when a pretrained mass-spectra annotation model must be scored on candidate sets from PubChem, and when average rank and Rank@K curves are needed to compare models or candidate-set designs.

## When NOT to use

- When the goal is EI/GC-MS spectra: the published NPLIB1 models cover ESI/LC-MS, and the article states NEIMS was generalized to ESI/LC-MS 'but not EI/GC-MS data'
- When NIST-20 training data is required: 'we are unable to publish the NIST-20 data alongside our models trained on NIST-20', so evaluation is restricted to the distributed NPLIB1 setup
- When ranking against a fixed small candidate list without spectral data — this skill needs test-candidate torchgeometric files, not plain SMILES tables

## Inputs

- Test-candidate torchgeometric pickle (torch_tecand_<N>bin_te_cand<k>_torchgeometric.pkl) generated by data_tecand.py at 1000-bin resolution
- Pretrained model checkpoints (best_model_mlp_can.pt, best_model_gnn_can.pt, ESP.pt / ESP_can.pt) from /pretrained_models
- mol_dict.pkl mapping InChiKeys to rdkit mol objects
- pos_train.csv (NPLIB1 dataset) if data regeneration is needed

## Outputs

- Average rank with standard deviation over the test spectra
- Rank@1 through Rank@20 hit rates (probability the true metabolite is in the top-K ranked candidates)
- Console metrics block suitable for tabulating into a comparison CSV (candidate_set_size, average_rank, rank_at_1 ... rank_at_20)

## How to apply

Build test-candidate torchgeometric files with `data_tecand.py` at the fixed 1000-bin spectral resolution, then run the saved model with `--te_cand_dataset_suffix` pointed at the generated file (e.g. `torch_tecand_1000bin_te_cand100`) and `--model_file_suffix` (or `--ens_model_file_suffix` for ESP) set to the checkpoint to evaluate. For ESP, supply the pretrained MLP (`best_model_mlp_can.pt`) and GNN (`best_model_gnn_can.pt`) via `--mlp_model_file_suffix` and `--gnn_model_file_suffix` and run `ens_train_canopus.py` in `--mode 'canopus'`. The scripts iterate over the 819-item NPLIB1 test batch and emit the average rank with its standard deviation plus Rank@1..Rank@20; identical evaluation can be run through `train.py` with the documented `--disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology --correlation_mat_rank 100` flags. Performance degrades with larger or more-similar candidate sets (average rank ~213.6 at full size vs 4.5-13.5 on 100-candidate subsets), so keep candidate size and similarity controls fixed when comparing models.

```

```

## Evaluation signals

- Metric block contains exactly the documented 819-item batch run with 'Average rank <val> +- <std>' and 20 sequential 'Rank at k <val>' lines
- On the NPLIB1 test data with all downloaded candidates, reported reference values are: MLP average rank 339.350 ± 1264.715, GNN 241.753 ± 939.827, ESP 279.557 ± 1170.300
- Rank@1..20 values are monotonically non-decreasing and bounded between 0 and 1 (e.g. ESP Rank@1 0.187 up to Rank@20 0.592)
- ESP evaluated on 100-molecule PubChem candidate sets should reproduce the paper's ~23.7% and ~37.2% average-rank improvements over MLP and GNN baselines
- Candidate-size sweep must show monotonic degradation: average rank worsens from ~3.194 (50-candidate sets) to ~213.597 (full candidate set)

## Limitations

- Published pretrained models and datasets cover NPLIB1 only; NIST-20 cannot be redistributed under NIST license regulations
- Ranking performance is strongly dependent on candidate-set size and on MACCS fingerprint similarity of candidates to the target (average rank 4.488 on least-similar vs 13.491 on most-similar 100-candidate sets), so uncontrolled candidate lists make cross-paper comparisons unreliable
- Rank@K on full PubChem candidate sets is low (ESP Rank@1 ≈ 0.187), so top-1 annotation confidence should not be over-interpreted; top-5 Rank@K still favors MLP baselines
