# in-source-fragment-recognition

## Summary

De novo recognition of in-source fragments (ISF) in LC-MS/MS metabolomics feature tables using the ISFrag R package, which flags MS1 features that are fragments of co-eluting precursor metabolites and could otherwise cause false metabolite annotation.

## When to use

Use when processing untargeted LC-MS/MS metabolomics data (e.g. DDA/DIA/fullscan mzXML from NIST plasma-style acquisitions) where ISF features may be misannotated as real metabolites.

## When NOT to use

- When CAMERA adduct and isotope annotation is required but the feature table was not generated by XCMS only (CAMERA annotation can only be used for XCMS-only ISFrag analysis)
- When the MS/MS reference library is not in msp format or the custom feature table does not follow the required m/z, rt, rtmin, rtmax, intensity column order with retention times in seconds
- When MS2 spectra have not been assigned/annotated to features, since find.level1/2/3 operate on the annotated feature table

## Inputs

- mzXML files from DDA, DIA, or fullscan LC-MS analyses (MS1 feature extraction and MS2 assignment)
- custom csv feature table from MS-DIAL/MZmine2 with columns m/z, rt, rtmin, rtmax, and per-sample intensities (rt in seconds)
- MS/MS reference library in msp format (e.g. MoNA-export-LC-MS-MS_Negative_Mode.msp)

## Outputs

- Complete dataframe feature table with ISF relationship annotated in additional columns (ISF_level, Annotation, DPscore)
- Detailed ISF precursor-fragment relationship dataframe / ISF relationship tree
- Count and proportion of features flagged as ISF relative to total feature count

## How to apply

Install ISFrag from GitHub (HuanLab/ISFrag) with devtools under R >= 4.0.0, then build the MS1 feature table either with XCMS.featuretable(MS1directory=..., peakwidth=c(5,20)) from mzXML files or by reading a custom csv (MS-DIAL/MZmine2) via custom.featuretable(); the csv must contain columns in order m/z, rt, rtmin, rtmax, per-sample intensities, with all retention times in seconds. Assign MS2 spectra from DDA mzXML files with ms2.assignment() and annotate features with feature.annotation() against an msp-format library (e.g. MoNA-export-LC-MS-MS_Negative_Mode.msp, dp = 0.1). Identify ISF hierarchically from level 3 down to level 1 using find.level3(), find.level2(), and find.level1(), then summarize with get.ISFrag.results(). The rationale is that ISF features share retention-time edges and structural relationships with precursor metabolites, so recognizing them prevents falsely annotating fragment ions as distinct metabolites. Export the annotated table with export.ISFrag.results() and quantify how many features are flagged as ISF relative to the total feature count.

## Examples

```
devtools::install_github("HuanLab/ISFrag"); library(ISFrag); xcmsFT <- XCMS.featuretable(MS1directory = MS1directory, type = "single", peakwidth = c(5, 20))
```

## Evaluation signals

- Annotated feature table exists and contains ISF_level / Annotation / DPscore columns for every feature
- Level 1 ISF recognition is complete (100%) and level 2 recognition is above 80%, as reported when ISFrag was tested using metabolite standards
- Number and proportion of features flagged as ISF are quantified relative to the total feature count
- MS2 assignment and annotation outputs are populated for features before running find.level3/level2/level1 (dp = 0.1 against the MoNA negative-mode library)

## Limitations

- CAMERA adduct and isotope annotation can only be used for XCMS-only ISFrag analysis, not for custom feature-table input
- Custom csv feature tables must have exactly the m/z, rt, rtmin, rtmax, intensity column order with retention times in seconds, or ISFrag cannot read them
- Increasing collision energies can increase the number of real metabolic and ISF features, but the percentage of ISF features might not necessarily increase
- Recognition is imperfect below level 1: only 100% correct recognition was achieved for level 1 ISF and over 80% for level 2 ISF on metabolite standards
