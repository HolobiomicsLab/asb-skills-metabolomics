# benchmark-dataset-retrieval-and-standardization

## Summary

Retrieves the nine MetaboLights benchmark metabolomic peak tables used by the NOREVA protocol (MTBLS6, MTBLS583, MTBLS403, MTBLS370, MTBLS59, MTBLS656, MTBLS319, MTBLS1569, MTBLS665) and manually standardizes each into the unified NOREVA peak-table format so downstream processing stages (S1–S4) and multi-criteria assessment (S5) can run.

## When to use

Use when a metabolomic peak table from a benchmark study (MetaboLights MTBLS accession or the NOREVA_exampledata.zip archive) must be obtained and reformatted into NOREVA's unified row-sample/column-metabolite layout before workflow processing.

## When NOT to use

- The input is still a raw instrument file in a proprietary format that must first be converted to an open format with tools such as Proteowizard or nmrML, not a peak table
- The peak table is already in the standardized NOREVA format, so re-standardization would only risk altering sample/molecule identity
- The goal is to score or rank processing workflows (stage S5 assessment) rather than to acquire and format the benchmark data

## Inputs

- MetaboLights benchmark dataset files (MTBLS6, MTBLS583, MTBLS403, MTBLS370, MTBLS59, MTBLS656, MTBLS319, MTBLS1569, MTBLS665)
- NOREVA_exampledata.zip archive of publication datasets
- Peak table file (rows = samples, columns = metabolites) in standardized or software-tool-specific format
- Label file naming time-course/multi-class group membership (when applicable)

## Outputs

- Peak table in the unified NOREVA format (rows = named samples, columns = metabolites) accepted by PrepareInuputFiles with dataformat=1
- Input object from PrepareInuputFiles ready for NOREVA assessment functions

## How to apply

Download the raw/peak-table files for the benchmark from MetaboLights by accession (e.g., https://www.ebi.ac.uk/metabolights/MTBLS403/files), or load the prepackaged NOREVA_exampledata.zip from https://idrblab.org/noreva/NOREVA_exampledata.zip. Then manually standardize each peak table to the unified format by preserving rows as samples (provided by name) and columns as metabolites, adding a label file when the data are time-course or multi-class. In R, feed the standardized file to NOREVA's PrepareInuputFiles with dataformat=1 (NOREVA's standardized format) or dataformat=2 (customized format generated by 12 available software tools) to produce the input object required by the assessment functions (normulticlassqcall, nortimecourseqcall, etc.). The rationale is that all subsequent NOREVA stages — S1 filtering/imputation, S2 QCS correction, S3 transformation, S4 normalization, S5 multi-criteria assessment — assume this single unified layout, and because raw data files are organized diversely, this standardization step is comparatively time-consuming and must not be skipped.

## Related tools

- **NOREVA** (R package whose PrepareInuputFiles function ingests the standardized peak table (dataformat=1 for the NOREVA standard, dataformat=2 for 12 software-tool-specific formats) with an optional label file) — https://github.com/idrblab/NOREVA
- **MetaboLights** (Source repository from which the nine benchmark raw/peak-table files are downloaded by accession) — https://www.ebi.ac.uk/metabolights/MTBLS403/files
- **R** (Environment in which the NOREVA package (>=3.5) and its dependency chain are installed to run PrepareInuputFiles) — https://www.r-project.org/

## Examples

```
library(NOREVA); PrepareInuputFiles(dataformat = 1, rawdata = "MTBLS403_peaktable.csv", label = "MTBLS403_labels.csv")
```

## Evaluation signals

- The standardized table has rows = samples (provided by name) and columns = metabolites, matching the unified NOREVA layout
- PrepareInuputFiles(dataformat=1, ...) accepts the file without format errors and yields the input object expected by normulticlass*/nortimecourse* functions
- All nine benchmark accessions (MTBLS6 through MTBLS665) resolve and download, or the NOREVA_exampledata.zip contents load identically
- For time-course/multi-class data, a label file naming each sample's class/timepoint accompanies the peak table
- Reformatted tables reproduce the sample and metabolite counts of the corresponding NOREVA example data

## Limitations

- Preservation of row/column is challenging because raw data files are organized diversely, making manual standardization relatively time-consuming
- Successful downstream use presupposes good experimental design — adoption of both QCSs and ISs — which this retrieval/standardization step cannot repair after the fact
- The protocol only covers commonly applied processing methods and is not automatically extensible to new ones
