# ms2lda-pipeline-execution

## Summary

Runs the MS2LDA latent Dirichlet allocation workflow end-to-end on an MS/MS data file — converting spectra into bag-of-fragments documents (with neutral-loss extraction and noise filtering), then decomposing them into Mass2Motifs via Gibbs sampling or variational Bayes inference.

## When to use

Use when an mzML/mzXML MS/MS dataset must be decomposed into recurring substructure motifs (Mass2Motifs) without prior compound identification, and stage-wise runtimes need benchmarking.

## When NOT to use

- Input spectra are low-information (few fragments per MS2, e.g. fixed low collision energy) — MS2LDA 'works best for complex mixtures where a large number of metabolites are fragmented and information-rich MS2 spectra are available (e.g., generated by ramped or stepped collision energy)'
- Data are data-independent acquisition spectra without reliable MS1-to-MS2 peak matching — MS2LDA relies on reliable matching of MS1 peaks to MS2 spectra (though DIA data processed by e.g. MS-DIAL is feasible in principle)
- The task needs fast, interactive annotation rather than de novo motif learning — for those cases spectral matching against Mass Bank/NIST/GNPS is far cheaper than LDA inference

## Inputs

- MS/MS data file (e.g. Beer3 positive-ionization mode file) from deposited research data
- LDA model configuration: 300 Mass2Motifs per data file
- Choice of inference engine: Gibbs sampling or variational Bayes

## Outputs

- Stage-wise wall-clock timings (feature extraction, Gibbs LDA, variational Bayes LDA) recorded with Python's time module
- runtime_benchmark.csv comparing measured timings against the paper's reported figures
- Learned Mass2Motif sets (co-occurring molecular fragments and neutral losses) for the input data file

## How to apply

Obtain the target MS/MS data file (e.g. the Beer3 positive-ionization file from the deposited research data at dx.doi.org/10.5525/gla.researchdata.313), clone the MS2LDA repository (git clone https://github.com/vdhooftcompmet/MS2LDA.git) and pip-install it. Preprocess to convert each spectrum into a bag-of-fragments document, extracting fragments and neutral losses and filtering noise, keeping the 10 most abundant ion species not on the dynamic exclusion list. Run LDA model training via Gibbs sampling with 300 Mass2Motifs per data file (the paper's setting), recording wall-clock time with Python's time module at each stage. Optionally run the same decomposition via variational Bayesian inference (the paper reports ~1 h Gibbs vs ~30 min VB on laptop hardware for one beer sample, and VB scaled to decompose the 5,670-spectrum GNPS dataset into 500 Mass2Motifs). Validate each stage timing is within the same order of magnitude as the reported reference figures (~20 min feature extraction, ~1 h Gibbs, ~30 min VB), consistent with the claim that MS2LDA is 'more costly than simpler tools, but not prohibitively so'.

## Examples

```
pip install ms2lda; python -c "import time; from ms2lda import LDA; t0=time.time(); LDA.train('Beer3_pos.mzML', n_topics=300); print(time.time()-t0)"
```

## Evaluation signals

- Each stage timing falls within the same order of magnitude as the paper's reference figures (~20 min feature extraction, ~1 h Gibbs sampling, ~30 min variational Bayes for one beer sample)
- The Gibbs-vs-VB runtime ratio matches the reported 2:1 relationship (Gibbs roughly twice VB runtime)
- Learned motif count matches the configured 300 Mass2Motifs per data file
- Decomposition quality: variational Bayes on the 5,670-spectrum GNPS dataset yields 500 Mass2Motifs, consistent with the paper's scaling example
- MS peaks per preprocessed sample are in the ~1,000 range for beer extracts, as reported

## Limitations

- MS2LDA is computationally more costly than simpler tools, but not prohibitively so — expect ~50 min total for one beer sample on laptop hardware
- Works best only for complex mixtures with information-rich MS2 spectra (ramped or stepped collision energy); low-fragment spectra yield poor motifs
- MS1 peak-to-MS2 spectrum matching must be reliable; DIA data needs prior conversion (e.g. MS-DIAL)
- No version number for MS2LDA is stated in the source; runtime figures reflect the authors' 2016 laptop-class hardware
- Only a fraction of available MS/MS information is typically utilized elsewhere; MS2LDA compensates but requires full fragmentation data
