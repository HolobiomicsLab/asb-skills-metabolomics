# dda-dia-provenance-fraction-analysis

## Summary

Quantifies the DDA-versus-DIA provenance split of MS2 spectra generated by the DaDIA hybrid acquisition workflow, and computes the high-/low-quality spectral fractions by dot-product scoring against the MoNA library.

## When to use

Use when processing combined DDA and DIA-(SWATH) mzXML files (e.g. human urine samples) through DaDIA.R and you need to report what fraction of MS2 spectra originates from each acquisition mode and their quality distribution.

## When NOT to use

- Input is a single acquisition mode only (pure DDA or pure DIA/SWATH without pooled-QC DDA mzXML files) — the provenance split is undefined.
- MS2 spectra have not yet been extracted and deconvolved from the raw mzXML files (use the DaDIA.R feature-extraction and MS2 deconvolution steps first).
- The analysis targets chromatographic feature counts or rescued-feature true/false-positive rates rather than MS2 spectral provenance and dot-product quality fractions.

## Inputs

- mzXML files from DDA acquisition of pooled QC samples
- mzXML files from DIA-(SWATH) acquisition of individual biological samples (e.g. human urine)
- MoNA MS2 spectral library (91,819 standard MS2 spectra)
- sample count matching the number of DIA mzXML files (declared on line 38 of the DaDIA.R script)

## Outputs

- ms2_quality_distribution.csv containing high-/low-quality fractions (dot-product-scored) and the DDA/DIA provenance split of MS2 spectra
- divergence flags when computed percentages do not reproduce the reported 13%/7%, 25%/43%, and 63%/37% values

## How to apply

Load the pooled DDA mzXML files and the individual-sample DIA-(SWATH) mzXML files together, then run DaDIA.R (built on XCMS centWave-based peak picking, requiring XCMS ≥ 3.11.4 and metaMS 1.25.1) to extract metabolic features and assemble MS2 spectra from both components. Each assembled experimental MS2 spectrum is graded by computing a dot-product score against the MoNA standard MS2 spectral library (91,819 spectra, downloaded September 20, 2020); spectra with dot product > 0.7 are kept as annotated/high-quality and the remainder binned as low-quality. Separately, count each MS2 spectrum's origin (DDA-derived vs DIA-derived) to compute the provenance fractions. For the urine study in RP(+) mode the expected reference values are 13% high-quality (dot-product 90–100) MS2 spectra for DaDIA vs 7% for DIA(SWATH), 25% vs 43% in the low-quality range, and a 63%/37% DDA/DIA provenance split; flag any divergence explicitly in the output table.

## Related tools

- **DaDIA.R** (R program that extracts metabolic features and assembles/annotates MS2 spectra from the combined DDA + DIA dataset; its output feeds the provenance and quality fraction computation) — https://github.com/HuanLab/DaDIA.git
- **XCMS** (centWave-based peak picking backend used by DaDIA.R (development version 3.11.4 or above required))

## Examples

```
Rscript DaDIA.R  # with the number of samples on line 38 matching the number of DIA mzXML files
```

## Evaluation signals

- Computed high-quality fraction for DaDIA MS2 spectra (dot product 90–100) must equal 13% for the urine RP(+) reference run; DIA(SWATH) must equal 7%.
- Low-quality range fractions must reproduce 25% (DaDIA) vs 43% (DIA(SWATH)); any deviation must be explicitly flagged in the output CSV.
- Provenance split must reproduce 63% DDA-derived and 37% DIA-derived MS2 spectra; the two fractions must sum to 100%.
- The dot-product cutoff of 0.7 must be applied identically for annotation/quality binning across DaDIA and DIA(SWATH) spectra to keep the comparison valid.
- The number of samples declared on line 38 of DaDIA.R must equal the actual number of DIA mzXML files supplied.

## Limitations

- Dot-product quality bins (e.g. 90–100 high-quality) are defined against the specific MoNA library version (91,819 spectra, downloaded September 20, 2020); a different library snapshot changes the fractions.
- Rescued-feature validation is partly manual: EIC inspection yields a 71% true-positive and 17% false-positive rate with 12% undetermined, so feature-level provenance can be uncertain.
- Version sensitivity: R 4.0 or above, XCMS development version 3.11.4 or above, and metaMS 1.25.1 are required; older XCMS versions cannot run DaDIA.R.
- The DDA-derived MS2 spectra come only from pooled QC injections, so provenance fractions reflect the pooled-QC DDA design rather than per-biological-sample DDA.

## Evidence

- [results] In urine data, 63% of MS2 spectra were generated from DDA data and 37% from DIA data: "63% of the MS2 spectra were generated from the DDA data and the remaining 37% were generated from the DIA data"
- [methods] Dot product annotation cutoff: "Only the annotated metabolites with a dot product score higher than 0.7 were kept for further analysis"
