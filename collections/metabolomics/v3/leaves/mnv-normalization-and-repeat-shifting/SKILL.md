# MNV normalization and repeat-shifting

## Summary

Prepares variant call data for cross-tool annotation comparison by phasing and normalizing multi-nucleotide variants (MNVs) and consistently grouping repeat-shifted alleles, so that HGVS nomenclature generated by ANNOVAR, SnpEff, and VEP can be concordantly compared against ClinVar annotations.

## When to use

Use when VCFs from different variant callers feed multiple annotation tools (ANNOVAR, SnpEff, VEP) and nucleotide repeats or MNVs could shift HGVS notation between tools or versus a ClinVar reference.

## When NOT to use

- Input is a single tool's annotation with no cross-tool or ClinVar comparison — normalization for concordance benchmarking adds no value
- All variants are already normalized against a common transcript set (e.g., MANE) with no repeat-region or MNV content to shift
- The analysis targets non-coding or structural annotation tasks rather than HGVS nomenclature and coding-impact concordance

## Inputs

- VCF files of variants from multiple variant callers (e.g., 164,549 ClinVar two-star variants)
- ClinVar reference annotations (HGVSc, HGVSp, coding impact) for high review-status variants
- Reference genome and transcript annotation set (identical across tools; MANE transcripts recommended)

## Outputs

- Phased and normalized VCF with consistently oriented repeat-shifted alleles
- Per-tool annotation records (HGVSc, HGVSp, predicted coding impact) comparable across ANNOVAR, SnpEff, and VEP
- Stratified concordance table (e.g., variant_type_concordance.csv: tool, variant type, annotation field, n variants, concordance rate)

## How to apply

Before annotating with ANNOVAR, SnpEff, and VEP, phase and normalize multi-nucleotide variants in the VCF, and left/right-align nucleotide-repeat alleles under a single convention so that repeat-shifted representations of the same variant group consistently. Recalibrate all inputs to an identical reference genome and transcript annotation across tools, since differing MANE selections alter the final annotation. After annotation, classify each variant by type (SNV, Ins, Del, Indel, MS, Dup, Inv) from the normalized VCF, then compare each tool's HGVSc, HGVSp, and predicted coding impact against ClinVar two-star annotations per type — the article found ~0.995 concordance for SnpEff/VEP on Ins, Del, and Indel, with MS the least consistent category. The rationale is that unnormalized MNVs and repeat shifts produce spurious HGVS discrepancies that contaminate concordance metrics and downstream ACMG/PVS1 interpretation.

## Related tools

- **ANNOVAR** (Downstream annotator whose HGVSc/HGVSp/coding-impact output is compared against ClinVar after MNV normalization)
- **SnpEff** (Downstream annotator whose HGVSc/HGVSp/coding-impact output is compared against ClinVar after MNV normalization)
- **Variant Effect Predictor (VEP)** (Downstream annotator; --per_gene and --coding_only options can streamline transcripts and reduce annotation complexity)

## Examples

## Evaluation signals

- SNV should be the most consistent variant-type category across all three tools after normalization
- SnpEff and VEP should reach >0.995 concordance with ClinVar for Ins, Del, and Indel categories
- SnpEff's worst category should be Inversion (Inv), while VEP's worst should be MS and Duplication (Dup)
- Overall study-level concordance benchmarks to reproduce: 58.52% HGVSc, 84.04% HGVSp, 85.58% coding impact
- Output CSV must contain columns for tool, variant type, annotation field, n variants, and concordance rate

## Limitations

- Some HGVS syntax in ClinVar does not adhere to HGVS recommendations, so residual discordance after normalization may reflect reference-database errors rather than tool errors
- Inconsistencies exist between ClinVar web pages and its VCF, capping achievable concordance
- Restricting transcripts to ClinVar-selected ones improves HGVSc/HGVSp/coding-impact consistency, but discrepancies with ClinVar persist even then
- No software versions for ANNOVAR, SnpEff, or VEP were reported, hindering exact replication
