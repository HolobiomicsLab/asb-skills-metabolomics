# transformation-product-component-prioritization

## Summary

Prioritizes transformation product (TP) components in patRoon 2.0 after parent and TP features have been grouped into components, by applying five complementary filters (RT direction, structure similarity, explained transformation, remove isomers, duplicates) that reduce false-positive parent/TP assignments in LC-HRMS non-target analysis.

## When to use

Use when TP components have already been generated by patRoon componentization from parent/TP feature links (e.g. patRoonData standard-X vs solvent-X, positive and negative ionization) and need filtering to remove spurious parent/TP pairs before reporting or identification.

## When NOT to use

- Input is a raw feature table or suspect-screening result before TP componentization — prioritization operates on components, not on unlinked features or candidate TP lists
- The analysis goal is initial TP structure prediction or parent selection (target list, suspect screening, or feature compound annotation) rather than filtering already-formed parent/TP components
- The workflow needs the patRoon 3.0 ion mobility separation (IMS) functionality or other post-2.0 features; this skill is grounded in the patRoon 2.0 prioritization filters

## Inputs

- TP components from patRoon 2.0 componentization (parent feature linked with corresponding TP features)
- Feature data from a classical patRoon workflow (patRoonData standard-X and solvent-X LC-HRMS, positive and negative ionization)
- Feature formula annotations used by the explained-transformation filter
- TP structures from in silico prediction (BioTransformer, enviPath, CTS) or library search (PubChem/PubChem Lite)

## Outputs

- Prioritized TP component table with one row per TP component
- Per-filter verdict columns recording RT direction, structure similarity, explained transformation, isomer-removal and duplicates outcomes (e.g. tp_components_prioritized.csv)

## How to apply

Load the TP components produced by the patRoon 2.0 componentization step (each parent feature linked with corresponding TP features), then run the patRoon prioritization routine in R with five filters enabled. The RT direction filter verifies the expected relative retention-time direction of each parent/TP pair based on chemical polarities (relevant to the sets workflow where positive and negative ionization data are processed simultaneously). The structure-similarity filter removes TPs with high MS similarity but low structural similarity; the explained-transformation filter verifies the proposed metabolic-logic transformation against feature formula annotations (e.g. from GenForm/SIRIUS candidates). The remove-isomers filter drops isomers that are difficult or impossible to distinguish with MS, and the duplicates filter removes duplicate TPs formed from the same parent through different pathways. Export the prioritized component table with per-filter verdicts so each retained parent/TP link is traceable to the filters that passed it.

## Related tools

- **patRoon 2.0** (Provides the componentization output and the prioritization filters (RT direction, structure similarity, explained transformation, remove isomers, duplicates) applied to TP components) — https://rickhelmus.github.io/patRoon
- **R** (Platform in which the patRoon prioritization routine is executed on TP components) — https://github.com/rickhelmus/patRoon
- **patRoonData** (Supplies example LC-HRMS data (standard-X standard mixture and solvent-X blank, triplicate, first ten minutes, m/z 75-450) for exercising the prioritization workflow) — https://github.com/rickhelmus/patRoonData

## Examples

```
Rscript -e 'library(patRoon); comps <- patRoon::prioritizeTPComponents(tpComponents, filters=c("RTDirection","StructuralSimilarity","ExplainedTransformation","RemoveIsomers","Duplicates")); write.csv(as.data.frame(comps), "tp_components_prioritized.csv")'
```

## Evaluation signals

- Output file (e.g. tp_components_prioritized.csv) exists and contains a row per TP component (file_exists, script_runs)
- Table includes columns recording each of the five filter verdicts: RT direction, structure similarity, explained transformation, isomer removal, duplicates (field_present)
- Every retained parent/TP pair is consistent with the expected relative retention-time direction for its chemical polarity in the mixed positive/negative sets workflow
- Tps removed by the structure-similarity filter have high MS similarity but low structural similarity, confirming the filter logic applied
- No duplicate TPs formed from the same parent through different pathways remain in the prioritized output

## Limitations

- Isomers can be difficult or impossible to distinguish with MS, so the remove-isomers filter cannot guarantee a unique TP assignment
- The RT direction filter relies on chemical polarities to set expected retention-time direction and can misjudge pairs whose chromatographic behaviour deviates from polarity expectations
- Explained-transformation verification depends on the quality of feature formula annotations; unannotated features cannot be checked against the proposed metabolic-logic transformation
- Filter thresholds and rule-based prioritization are configurable, so results are only comparable when the same filter configuration is used
