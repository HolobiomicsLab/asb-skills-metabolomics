# hierarchical-spectral-clustering

## Summary

Groups large sets of MS/MS spectra by clustering their learned GLEAMS 32-dimensional embeddings with hierarchical average-linkage clustering at a Euclidean distance threshold, then postprocessing clusters by precursor mass to split inconsistent groups.

## When to use

Use when millions of MS/MS spectra (e.g., from mzML peak files) have already been embedded with GLEAMS and the goal is to detect spectrum clusters of spectra generated by the same peptide, as in the 669M-spectrum MassIVE-KB analysis.

## When NOT to use

- Input spectra have not yet been converted to GLEAMS 32-dimensional embeddings (embed them first with `gleams embed`)
- The dataset is small and can be clustered directly on spectral similarity without a learned embedding, where hierarchical clustering of embeddings adds no benefit
- The goal requires de novo cluster annotation rather than propagating existing peptide identifications (PSMs) within pure clusters

## Inputs

- 32-dimensional GLEAMS embeddings (n x 32 NumPy .npy array)
- Corresponding spectrum metadata (parquet file with precursor mass, filename, scan number)
- MS/MS spectra in mzML peak files (upstream input to `gleams embed`)

## Outputs

- Cluster labels per embedding in a NumPy .npy file (-1 = noise, minimum cluster size 2)
- Cluster medoid indexes (representative spectra) in a .npy file
- Clustered fraction, incorrectly clustered fraction, and completeness quality metrics

## How to apply

First run `gleams embed` on the mzML peak files to convert MS/MS spectra into 32-dimensional embeddings stored as an n x 32 NumPy array with a companion metadata parquet file. Then run `gleams cluster`, which performs hierarchical clustering on the embeddings with Euclidean distance and a distance threshold of 0.35 (the value used for the full 669-million-spectrum MassIVE-KB run). This yields cluster labels per embedding, where -1 indicates noise and the minimum cluster size is 2, plus indexes of cluster representative spectra (medoids). Postprocess the clusters using precursor mass to split any cluster containing inconsistent precursor masses. In the reference run this clustered 511 million spectra (76%) with 1.16% incorrectly clustered spectra and 0.837 completeness, and label propagation within pure clusters added ~82 million new PSMs to unassigned spectra.

## Examples

```
gleams cluster --embed_name GLEAMS_embed --cluster_name GLEAMS_cluster --distance_threshold 0.35
```

## Evaluation signals

- Clustered fraction should approach ~76% (511M of 669M MassIVE-KB spectra clustered) at distance threshold 0.35
- Incorrectly clustered fraction should stay near ~1.16%
- Completeness of clustering should reach ~0.837
- Output GLEAMS_cluster.npy contains one label per embedded spectrum, with -1 marking noise and no cluster smaller than 2 spectra
- After precursor-mass postprocessing, no remaining cluster contains spectra with inconsistent precursor masses

## Limitations

- GLEAMS requires Python 3.8, a Linux operating system, and a CUDA-enabled GPU
- Model weights are served via Git LFS and may hit data-quota limits; they must be downloaded manually (e.g., gleams_82c0124b.hdf5) and placed in the data/ directory when installation fails
- The distance threshold controls cluster granularity; the article's methods example uses 0.3 while the repository-scale run uses 0.35, so threshold choice must be matched to the target precision/recall trade-off
- Precursor-mass postprocessing can only split clusters with inconsistent precursor masses; purity is not guaranteed otherwise
