# multi-batch-metabolomics-data-integration

## Summary

Integrate multi-batch LC/GC-MS-based metabolomics or label-free proteomics datasets by applying QC-based random forest signal correction (QC-RFSC) with the statTarget shiftCor function, which corrects feature-level inter- and intra-batch signal drift using pooled QC injection-order trends.

## When to use

Use when feature-intensity tables exported from XCMS, MZmine2, SIEVE, or Skyline span multiple or long LC/GC-MS batches and show injection-order signal drift (QC RSD rising over time) that must be corrected before statistical analysis.

## When NOT to use

- No QC samples are available in the batches — shiftCor requires named 'QC' injections; use the QC-free Combat alternative (shiftCor_dQC) instead.
- The goal is ready-to-submit feature peak areas from raw mass-spectrometric files rather than batch correction of an existing intensity table.
- A single short batch already meets precision criteria (e.g. most QC peaks already < 15% RSD), where correction would add no benefit.

## Inputs

- meta file: sample name, class, batch, injection order (QC rows tagged 'QC')
- profile file: feature-level peak intensity matrix from LC/GC-MS-based metabolomics or label-free proteomics
- input files generated by XCMS, MZmine2, SIEVE, or Skyline (converted via transX)

## Outputs

- signal-corrected intensity matrix for all samples (all batches integrated)
- corrected QC-only and sample-only matrices
- shift statistics for each feature
- RSD/CV distribution of raw vs. corrected QC peaks per batch and overall, plus loplot quality-control images

## How to apply

Build a meta file (sample name, class, batch, order) and a profile file of peak intensities, converting XCMS/MZmine2/SIEVE/Skyline exports via the statTarget transX function if needed. In shiftCor, evaluate missing values, apply the modified 80% rule (Frule = 0.8, keeping features with non-zero values in at least 80% of samples in any group), impute missing values by KNN (imputeM = 'KNN'), and label QC samples by their 'QC' name tag. Fit the QC-RFSC model with MLmethod = 'QCRFSC': an ensemble of ntree = 500 random regression trees trained on random sub-QC samples, which yields a per-feature correction factor Fij as a function of injection order, then divide each intensity by its factor (x'ij = xij/Fij) and integrate the multi-batch data. Outputs are corrected matrices for all samples, QC-only and sample-only, together with the shift statistics and per-batch RSD distributions; validate by confirming a marked QC peak RSD improvement (e.g. 43.9% → 86.2% of peaks with RSD < 30% in Dataset 1).

## Examples

```
shiftCor(samPeno, samFile, Frule = 0.8, MLmethod = "QCRFSC", QCspan = 0, imputeM = "KNN")
```

## Evaluation signals

- Corrected QC peaks show markedly improved RSD distribution, e.g. proportion with RSD < 30% rising from ~43.9% (raw) to ~86.2% (corrected) in Dataset 1, and 52.1% → 90.9% in Dataset 2.
- A 12.7-fold increase (to 25.1%) in the number of QC peaks within 15% RSD after correction (Dataset 1).
- Features surviving the modified 80% rule (Frule = 0.8) with non-zero values in ≥ 80% of samples in any group before correction.
- Per-batch and overall RSD/CV distributions are exported for raw vs. corrected peaks, allowing before/after comparison.
- Corrected matrices are produced for all samples, QCs only, and samples only, and the shift statistics file is non-empty for each feature.

## Limitations

- Requires pooled QC injections placed at regular intervals (e.g. every five, six, or eight real samples in Datasets 1–3); QC-free datasets must use the Combat branch (shiftCor_dQC).
- The 80% rule (Frule = 0.8) with KNN imputation precedes correction, so features with excessive missingness are filtered out before drift correction.
- Performance is validated only on LC/GC-MS metabolomics and SRM-based proteomics datasets; correction factors are RF-predicted and depend on QC sequence quality.
- statTarget depends on R (>= 3.3.0); on macOS, XQuartz and RGtk2 2.20.31 (tested with R 3.3.0) are needed for the GUI.
