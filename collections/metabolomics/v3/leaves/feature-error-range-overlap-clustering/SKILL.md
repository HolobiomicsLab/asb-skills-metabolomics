# feature-error-range-overlap-clustering

## Summary

Basket replicated MS features in NP Analyst by building connected-component graphs from m/z features with overlapping error ranges across rt and m/z dimensions using an R-tree spatial index, then averaging each component into a single unique feature.

## When to use

Use when you have replicate-comparison output — replicated feature peak lists from technical replicate mzML runs — and need to collapse them into a single list of unique MS features for downstream bioactivity integration.

## When NOT to use

- Input is a single unreplicated MS run — replicate comparison and basketing require replicated feature peak lists and cannot be applied to one-shot data
- Input is already a processed MZmine 2 or GNPS feature table — those platforms' outputs are imported directly via `npanalyst import -t MZmine` or `-t GNPS` and do not need R-tree basketing

## Inputs

- Folder of replicate-comparison CSV peak lists (output of the replicate task on replicate mzML injections)
- Config file (e.g. config.json from `npanalyst get_config`) specifying rt and m/z error tolerances and replicate presence requirement (default: present in n − 1 samples for n replicates)

## Outputs

- Basketed list of unique MS features (CSV), where each row is a unique m/z feature averaged from connected components of overlapping replicate features

## How to apply

After replicate comparison (signals present in n−1 of n replicate injections), apply R-tree based basketing: build connected-component graphs of m/z features whose error ranges overlap in all dimensions, then combine (average) features within each connected component to yield a basketed/replicated feature. This 'combine and average' step yields the unique-feature list NP Analyst uses for bioactivity scoring. The step is exposed via the `npanalyst` CLI basket task on a folder of replicate-comparison CSVs, with key parameters (rt and m/z tolerances, replicate presence requirement) set in a config file generated by `npanalyst get_config`. The output basketed feature list is the input NP Analyst expects for subsequent feature score determination.

## Related tools

- **NP Analyst** (Provides the `npanalyst` CLI whose basket task performs R-tree based connected-component basketing of replicated features into unique MS features) — https://github.com/liningtonlab/npanalyst
- **Docker** (Packaging environment for running the `npanalyst` CLI basket step locally via bind-mounted volumes) — https://www.docker.com/get-started

## Examples

```
npanalyst import -i data/basketed_mzml_features.csv -o out -t CSV -v
```

## Evaluation signals

- Output is a CSV peak list of unique MS features whose count is reduced relative to the replicate-comparison input
- Each output feature row should have averaged m/z and rt values from its connected component rather than raw replicate values
- Running `npanalyst --help` shows the basket usage and the CLI exits cleanly on a folder of replicate CSVs
- Downstream NP Analyst bioactivity scoring accepts the basketed list without import errors

## Limitations

- Replicate comparison (and thus basketing) is only possible 'where possible' — replicate data are not always available
- Running NP Analyst without replicate preprocessing increases the number of candidate bioactive MS features because raw mass lists include junk features
- The default replicate presence requirement (n − 1 for n replicates) can be tuned in the config file but affects how aggressively noise peaks are removed

## Evidence

- [readme] R-tree based basketing combines replicate features: "Using an r-tree to build connected component graphs of m/z features with overlapping error ranges (in all dimensions). These are then combined (averaged)"
- [discussion] Replicate comparison reduces noise peaks: "Replicate comparison can significantly reduce noise peaks in untargeted metabolomics data sets29,31,32 and is strongly recommended where possible"
- [intro] Replicate presence requirement n−1: "For n replicates, the default requirement is present in n – 1 samples"
- [readme] npanalyst CLI basket and config: "A lot of the parameters are specified via a config file that defaults to `npanalyst.configuration.DEFAULT_CONFIG`"
- [methods] Import replicate mzML peak lists: "docker run -it -v PATH/TO/DATA:/data npanalyst-cli import -i /data/GNPS.graphml -o /data -t GNPS -v"
