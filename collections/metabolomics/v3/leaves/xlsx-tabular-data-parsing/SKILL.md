# xlsx-tabular-data-parsing

## Summary

Parse a tabular .xlsx database (here, the DNA adductomics database deposited on GitLab) with pandas and the openpyxl engine, then filter rows by a discriminating column (e.g. presence of a reference link) to isolate a curated subset of entries for downstream curation and verification.

## When to use

Use when a scientific dataset is distributed as a multi-column .xlsx file and specific rows must be extracted by a metadata criterion (e.g. entries carrying publication references) before further validation or harmonization.

## When NOT to use

- The goal is to work with the 303 'suspected' potential adducts, which by definition lack reference links and cannot be selected by the reference-link filter
- The input is already a parsed, harmonized table (e.g. the interactive web datatables of experimental and predicted fragments), so re-parsing the .xlsx would duplicate work
- The data source is a spectral library (experimental MS/MS spectra of 15 reference standards or CFM-ID in silico fragments) rather than the tabular adduct metadata table

## Inputs

- .xlsx database file (e.g. the DNA adduct database from https://gitlab.com/nexs-metabolomics/projects/dna_adductomics_database) with per-entry metadata columns
- Ancillary structural files referenced by rows (.cdxml, .mol) used to cross-check names, formulas, and masses

## Outputs

- Filtered DataFrame of 279 literature-derived entries with non-null name, formula, mass, source, study-design, and technique fields
- curated_core_adducts.csv containing the verified core subset with all metadata fields
- Flag list of rows with missing/inconsistent metadata or mass discrepancies > 0.01 Da vs recomputed monoisotopic masses from .mol structures

## How to apply

Read the .xlsx file with pandas using the openpyxl engine to obtain the full table (582 DNA adduct entries in the source database). Identify the column that separates literature-derived entries from computational ones — in the DNA adduct database this is the reference/publication link, present for the 279 curated adducts and absent for the 303 'suspected' adducts generated by combining genotoxicants with nucleobases. Filter rows whose reference field is non-null to obtain the curated core subset. For each retained row, verify the expected metadata fields (name, abbreviation, alternative name, source/genotoxicant, study design classified as in vitro/in vivo/human, and identification technique such as LC-HRMS, HRMS/MS, or NMR), marking missing or inconsistent values. Optionally cross-check counts against published totals (279 literature adducts, 16 genotoxicant classes, 9 sources) and keep positional-isomer entries distinct, then write the verified subset to a structured output such as curated_core_adducts.csv.

## Related tools

- **pandas (openpyxl engine)** (Parses the .xlsx database file and filters the 279 literature-derived rows by non-null reference link)
- **ChemDraw** (Origin of the .cdxml and .mol structural files whose identifiers (SMILES, InChI, InChIKey, IUPAC names) correspond to the tabular entries being parsed and validated)
- **rstudio/DT** (R DataTables interface used to present the parsed tabular data as interactive web datatables) — https://github.com/rstudio/DT

## Examples

```
import pandas as pd; df = pd.read_excel('dna_adduct_database.xlsx', engine='openpyxl'); core = df[df['reference'].notna()]; core.to_csv('curated_core_adducts.csv', index=False)
```

## Evaluation signals

- The rebuilt core subset contains exactly 279 literature-derived rows, matching the published total
- Every retained row has non-null name, formula, mass, source, study-design, and identification-technique fields
- Recomputed monoisotopic masses from .mol/SDF exact-mass atom data match deposited [M+H]+ or [M]+ values within 0.01 Da
- Harmonized entry counts reconcile with reported totals of 16 genotoxicant classes and 9 sources, with positional-isomer entries kept distinct
- Rows lacking a reference link (the 303 suspected adducts) are correctly excluded from the curated core

## Limitations

- The reference-link criterion only separates literature-derived from suspected adducts; it does not itself validate metadata quality, which requires per-entry field checks
- Mass agreement is only verified to a 0.01 Da tolerance, so discrepancies at or below that threshold will pass unflagged
- The rstudio/DT package is in maintenance-only mode, so interactive-table rendering of parsed data receives only bug fixes
