# csv-output-file-handling

## Summary

Export Skyline-compatible transition lists (or Excalibur-compatible DDA precursor lists) from the Lipid Spectrum Generator by selecting the '.CSV' output option instead of the default '.MSP' spectral-library export.

## When to use

Use when a lipid LC-MS/MS workflow needs an in silico-generated transition list for Skyline (or an Excalibur precursor list for DDA orbitrap acquisition) rather than a '.MSP' spectral library.

## When NOT to use

- When a '.MSP' spectral-library file for spectral-library search is required — the default '.MSP' export is the appropriate format instead.
- When the input spectra are not generated by LSG's lipid-class/adduct generation workflow.
- When a database format other than CSV transition/precursor lists is required by the downstream software.

## Inputs

- Generated lipid species set defined by lipid class and fatty-acid composition
- Generated in silico fragmentation spectra defined by their adducts

## Outputs

- Skyline-compatible transition list exported as a .CSV file
- Excalibur-compatible precursor list for DDA analysis via orbitrap (alternative .CSV export)

## How to apply

First use the Lipid Spectrum Generator (LSG, https://github.com/98104781/LSG) to generate lipids by class and fatty-acid composition and spectra by adduct, using fragmentation patterns based on peer-reviewed studies. Then invoke LSG's export functionality and select the '.CSV' file-extension option so the tool writes a Skyline-compatible transition list (or an Excalibur-compatible precursor list for DDA analysis via orbitrap) instead of the default '.MSP' spectral-library file. Write the exported transition list to disk as the final artifact, verifying the file is produced with the CSV extension. The choice between '.MSP' and '.CSV' is the key decision point: '.MSP' suits spectral-library search, '.CSV' suits targeted assay building in Skyline or instrument acquisition-method generation.

## Evaluation signals

- The output file exists on disk and carries the '.CSV' extension rather than '.MSP'.
- The .CSV content is parseable as a Skyline-compatible transition list (precursor/product entries) rather than a spectral-library record block.
- The transitions correspond to the lipid class, fatty-acid composition, and adduct selections made during generation.
- If targeting DDA acquisition, the .CSV instead parses as an Excalibur-compatible precursor list for orbitrap.
- The generated file round-trips into Skyline (or Excalibur) without schema errors.

## Limitations

- The '.CSV' export is only documented to produce Skyline-compatible transition lists or Excalibur-compatible precursor lists; other tools' CSV schemas are not covered.
- The Excalibur precursor list path is specific to DDA analysis via orbitrap instruments.
- The README notes the brief how-to guide resides on the GitHub v1.3.0 release page rather than in the README itself.
