# chemical-chromatogram-perturbation

## Summary

Reconstructs ViMMS 2.0's pluggable chemical-perturbation modules (CleanColumn, LinearColumn, RetentionTimeDeviation, GaussianPeakNoise) that systematically modify retention time and intensity of Chemical objects before simulated LC-MS/MS acquisition, emulating column ageing and instrument noise.

## When to use

Use when a simulated chemical dataset (pickled Chemical objects from ChemicalMixtureCreator) must be perturbed with reproducible RT offsets, systematic RT drift across successive injections, and random RT/intensity noise prior to fragmentation-strategy simulation.

## When NOT to use

- When the input is raw mzML or ROI-extracted scan data (e.g. Beer_multibeers_1_T10_POS.mzML) rather than a Chemical object list — noise then applies at the spectral level, not via chemical column objects
- When the goal is to modify fragmentation/acquisition behaviour (Top-N, SmartROI, WeightedDEW controllers) rather than chemical properties such as m/z, RT and intensity
- When quantitative validation of noise modules is required — this paper reports no benchmark for them

## Inputs

- Pickled master list of Chemical objects (e.g. task_001.expected_outputs[0]) generated by ChemicalMixtureCreator
- Offset specification for CleanColumn (fixed, gaussian, or uniform offsets)
- drift_fn or fixed drift parameter for LinearColumn

## Outputs

- perturbed_chemicals.pkl — pickle file of rebuilt Chemical objects carrying applied RT offset, drift, and Gaussian/RT-deviation noise annotations
- Loadable, structurally complete perturbed chemical dataset ready for downstream controller simulation in an Environment

## How to apply

Load the master list of Chemical objects produced in a prior generation step (e.g. via ChemicalMixtureCreator) and build a CleanColumn — using from_fixed_offsets, from_gaussian_offsets or from_uniform_offsets — to assign each chemical a reproducible retention-time offset. Wrap that column in a LinearColumn with a drift_fn (or a fixed drift parameter) so successive injections experience systematic RT drift that emulates column ageing. Apply GaussianPeakNoise and RetentionTimeDeviation from the vimms.Noise package to add intensity fluctuation and random RT jitter, then rebuild the chemical objects with the perturbed chromatograms and save the result as perturbed_chemicals.pkl. These noise/perturbation classes are pluggable — importable from vimms.Noise alongside UniformSpikeNoise — reflecting ViMMS 2.0's modular design; acceptance is structural completeness (offset/drift/noise annotations present on every chemical) since no quantitative benchmark for the noise modules is reported.

## Related tools

- **ViMMS 2.0** (Provides the pluggable perturbation classes (CleanColumn, LinearColumn, RetentionTimeDeviation, GaussianPeakNoise) importable from the vimms.Noise package for modifying chemical properties before simulation) — https://github.com/glasgowcompbio/vimms

## Examples

```
from vimms.Noise import GaussianPeakNoise, RetentionTimeDeviation; col = LinearColumn(CleanColumn.from_fixed_offsets(chemicals), drift_fn); perturbed = [c for c in col.apply(chemicals)]
```

## Evaluation signals

- perturbed_chemicals.pkl exists and can be loaded (pickle deserialises without error)
- Every chemical in the output carries the applied RT offset/drift annotation from the CleanColumn/LinearColumn pipeline
- GaussianPeakNoise and RetentionTimeDeviation annotations are present on the chemicals/spectra (structural completeness check)
- Perturbed dataset remains compatible with downstream ChemicalMixture/Environment-based simulation workflows (loads as a master list of Chemical objects)

## Limitations

- No quantitative benchmark for the noise/perturbation modules is reported in the paper; validation is limited to structural completeness
- GaussianPeakNoise is level-specific (e.g. GaussianPeakNoiseLevelSpecific), so noise levels must be chosen per intensity band; thresholds interact with min_intensity settings (e.g. 1.75E5 reduces objects processed, 1E4 is more accurate but slower, 0 includes even noise)
- No explicit software version number is stated for ViMMS 2.0 in the paper, so module APIs may differ across releases
