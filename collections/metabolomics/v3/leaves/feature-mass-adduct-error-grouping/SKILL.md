# feature-mass-adduct-error-grouping

## Summary

Collapses redundant putative annotation rows in untargeted metabolomics tables by grouping entries that share identical experimental neutral mass, m/z, adduct, and mass error, and joining their abbreviated metabolite names with the '//' delimiter, as implemented by TurboPutative's RowMerger module.

## When to use

Use when an annotation table from an untargeted metabolomics workflow contains multiple putative annotation rows per feature that share the same experimental mass, m/z, adduct, and mass error, and downstream comparison or pathway prioritization requires a smaller consolidated table.

## When NOT to use

- Input is a feature-intensity table or raw spectrometry data rather than a putative annotation table already handled by REname — TPMetrics, not RowMerger, combines datasets with feature intensity and metadata.
- Rows differ in experimental mass, m/z, adduct, or mass error, so grouping them would merge distinct annotations rather than redundant ones.
- The goal is compound classification or biological-system insight — that is Tagger's role, not annotation-row consolidation.

## Inputs

- Abbreviated putative annotation table (CSV) generated by the REname module of TurboPutative

## Outputs

- Consolidated, size-reduced annotation table (rowmerger_output.csv) with merged name cells joined by the '//' separator

## How to apply

Load the abbreviated annotation table produced by the REname module (CSV) with pandas, then apply RowMerger's grouping logic: group rows that share identical experimental neutral mass, m/z, adduct, and mass error, honoring the module's user-selectable comparison criteria rather than hard-coding defaults. For each merged group, concatenate the abbreviated metabolite names into a single cell separated by the '//' delimiter, collapsing redundant rows. The abbreviated name itself is not used as a grouping criterion — compliant potential annotations are kept together and separated by '//'. Write the consolidated, size-reduced table to rowmerger_output.csv. This reduction is what makes manual comparison among annotations feasible; the companion article reports TurboPutative reduces putative annotation entries by 80%-90% in massive datasets.

## Related tools

- **TurboPutative** (RowMerger module performs the annotation grouping and '//' concatenation; runs on the REname output table and can be invoked via the platform's RESTful API services) — https://github.com/CNIC-Proteomics/TurboPutative-web

## Examples

```
import pandas as pd; df = pd.read_csv('rename_demo_output.csv'); df.groupby(['neutral_mass','mz','adduct','mass_error'])['abbreviated_name'].apply('//'.join).reset_index().to_csv('rowmerger_output.csv', index=False)
```

## Evaluation signals

- rowmerger_output.csv contains a subset of the input rows, with redundant entries collapsed.
- Cells in the merged name column contain the '//' separator where multiple abbreviated names were combined.
- All rows within one merged group share identical experimental neutral mass, m/z, adduct, and mass error.
- Row count reduction falls in the range reported for TurboPutative on massive datasets (approximately 80%-90%).
- The output table preserves the REname-abbreviated names so downstream manual comparison among annotations remains possible.

## Limitations

- Grouping criteria are user-customizable; the default (identical neutral mass, m/z, adduct, and mass error) may merge annotations the user would want kept separate if criteria are loosened.
- The abbreviated name is not processed as a grouping criterion — it is only concatenated with '//' — so name-level distinctions are not used to split groups.
- The skill presumes a prior REname pass; applied directly to unabbreviated annotation tables it will not produce the expected consolidated output.
