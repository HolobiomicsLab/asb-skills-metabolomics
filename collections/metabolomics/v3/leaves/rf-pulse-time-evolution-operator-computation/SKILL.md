# rf-pulse-time-evolution-operator-computation

## Summary

Computes the density-matrix time-evolution propagator for each shaped RF refocusing/editing pulse exactly once and reuses it, instead of recalculating and applying an individual propagator per sampled spatial point (the elementwise FID-A approach), accelerating density-matrix basis set simulation in MRSCloud.

## When to use

Use when simulating MRS metabolite basis sets with repeated shaped pulses (e.g. PRESS/MEGA-PRESS/HERMES/HERCULES with editTp 14 ms or 20 ms) and per-sample propagator recalculation is the dominant runtime cost.

## When NOT to use

- The target experiment is STEAM or SPECIAL localization — MRSCloud does not implement these and this propagator workflow is built around PRESS/sLASER
- An exact vendor-specific parameter set is required — MRSCloud simulates the most commonly used parameter set and cannot capture all Philips experiments or all disseminated MEGA-PRESS versions within a vendor
- The pulse shapes/timings differ from the stored product-sequence RF waveforms, which are not shared in the GitHub repo

## Inputs

- simMRS.json configuration file (metabolite list, vendor, mega_or_hadam option, localization, TE, editOn/editOff, editTp, spatial_points)
- Spin-system parameters and shaped RF pulse waveforms from the FID-A simulation framework (product RF waveforms are not shared in the MRSCloud repo)

## Outputs

- Density-matrix simulated metabolite basis functions (per metabolite) generated by run_simulations_cloud.m
- Per-metabolite runtime measurements for the pre-calculated-propagator implementation
- ICCs comparing propagator-precalculated spectra to the FID-A elementwise baseline (e.g. propagator_benchmark.csv)

## How to apply

Configure the edited sequence parameters in simMRS.json (editTp = 14 ms for MEGA-PRESS/HERMES or 20 ms for HERCULES; spatial_points = 41 acceptable, 101 ideal), then compute the density-matrix time-evolution propagator for each shaped refocusing/editing pulse once rather than serially calculating 256 per-sample propagators as in the elementwise FID-A code. Reuse the pre-calculated propagator across repeated pulse applications, coherence pathways/phase cycles, and all spatial points, combining it with coherence order filtering so the full phase cycle never has to be simulated. Run run_simulations_cloud.m to generate the PRESS (or sLASER) basis set and record per-metabolite wall-clock runtime, noting that complex J-coupled systems (Cystat, HCar, iLe, Lys, Glc) dominate simulation time. Validate by computing intraclass correlation coefficients (ICCs) in R/RStudio against the FID-A elementwise baseline, accepting the reconstruction only if every metabolite reaches ICC ≥ 0.98 and a measurable runtime reduction is achieved.

## Related tools

- **MRSCloud** (MATLAB simulation package in which propagators are pre-calculated and reused; run via run_simulations_cloud.m after editing simMRS.json) — https://github.com/shui5/MRSCloud
- **FID-A** (Elementwise baseline simulation framework on which MRSCloud is built; its per-sample propagator approach serves as the comparison baseline for ICC validation) — https://github.com/CIC-methods/FID-A

## Examples

```
editTp=14; spatial_points=41; run_simulations_cloud.m
```

## Evaluation signals

- ICCs between pre-calculated-propagator spectra and the FID-A elementwise baseline are at least 0.98 for every metabolite
- Wall-clock runtime per metabolite shows a measurable reduction versus the elementwise approach, with the full PRESS basis set simulated in roughly ~11 minutes on the server
- Each shaped pulse's propagator is computed once, not 256 times (once per spatial sample), verifiable in the simulation scripts
- Runtime is dominated by complex J-coupled spin systems (Cystat, HCar, iLe, Lys, Glc), consistent with the README remarks

## Limitations

- Complex J-coupled spin systems (Cystat, HCar, iLe, Lys, Glc) significantly or extremely increase simulation time
- Only 3T basis sets are supported, and the number of user-specified parameters is limited in favor of ease of use
- Product sequences and RF waveforms are not shared in the GitHub repo; spin-system parameters rest largely on Govindaraju et al. with only minor updates
