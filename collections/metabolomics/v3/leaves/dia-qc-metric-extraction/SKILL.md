# dia-qc-metric-extraction

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Extract per-file numerical QC metrics from multivendor DIA mass spectrometry raw files (Orbitrap, TripleTOF, timsTOF Pro) by converting vendor formats (.raw/.d/.wiff) to mzXML with msConvert, analyzing DIA files with DIA-NN (v1.7.15), and parsing those outputs — as implemented in the iDIA-QC pipeline.

## When to use

Use when raw DIA LC-MS/MS files (.raw/.d/.wiff) from Orbitrap, TripleTOF, or timsTOF Pro instruments need per-file numerical QC metrics (e.g., peptide number, protein number, MS1/MS2 intensity) for downstream quality evaluation or longitudinal QC reporting.

## When NOT to use

- Input is already a processed feature/quantification table or metric matrix rather than vendor raw DIA files
- Data are DDA or SRM acquisitions — the pipeline is designed for DIA raw files, and SRM/DDA QC tools cannot be directly applied to large-scale DIA experiments (and vice versa)
- Files were generated by instrument types outside the covered set (Orbitrap, TripleTOF, timsTOF Pro series) — the study notes newly emerging instruments are not covered

## Inputs

- Vendor raw DIA mass spectrometry files (.raw, .d, or .wiff)
- Instrument type annotation per file (Orbitrap, TripleTOF, or timsTOF Pro) and instrument ID
- Peptide/protein spectral library (e.g., published mouse spectral library, 110,126 precursors / 10,542 protein groups)
- Optional: maintenance-event timestamps for longitudinal sensitivity comparison

## Outputs

- Extracted per-file numerical QC metric matrices (17 metrics; flat format usable without R/Python)
- DIA-NN peptide and protein quantification results (1% FDR at peptide precursor and protein levels)
- Converted mzXML files
- Self-contained HTML QC report with per-file metrics and LC/MS qualified/unqualified predictions
- Ratio-of-change curves aligned with maintenance-event timestamps (for fault-sensitivity analysis)

## How to apply

Record the instrument type (Orbitrap, TripleTOF, or timsTOF Pro) for each input file and assign an instrument ID, then convert each vendor raw file (.raw, .d, or .wiff) to mzXML using msConvert. Analyze the converted DIA files with DIA-NN (v1.7.15) against an appropriate spectral library (the paper used a published mouse spectral library with 110,126 precursors and 10,542 protein groups), applying 1% FDR filtration at both peptide precursor and protein levels. Parse the mzXML files for metrics F3 and F5, parse timsTOF-generated MGF files for F15, and parse DIA-NN outputs for the remaining metrics of the 17 numerical QC metrics. Optionally align per-file metrics or their ratio-of-change between consecutive injections with maintenance-event timestamps (e.g., for the monitored QE HF-X instrument) to assess sensitivity to LC-MS system faults, and feed extracted matrices into the pretrained ML model for qualified/unqualified LC and MS predictions. Render results as a self-contained HTML report plus flat matrices usable without R/Python.

## Examples

```
msConvert --filetype mzXML <raw.dia.files> && dia-nn --fdr-pep 0.01 --fdr-protein 0.01 --lib <mouse.speclib> && python iDIA_QC.py --input <raw_files> --instrument Orbitrap --output <qc_report_dir>
```

## Evaluation signals

- Each input raw file yields an HTML QC report containing all metrics plus LC/MS qualified/unqualified predictions
- Analysis completes with processing time per file under 5 minutes
- DIA-NN results pass 1% FDR at both peptide precursor and protein levels
- In the maintenance-event comparison, DIA-based LC-MS/MS consensus QC metrics show higher sensitivity than DDA-based QC metrics (consistent with the paper's finding)
- Output matrices are flat files that can be opened without statistical software such as R/Python

## Limitations

- Model-building details are limited to a preprocessing/training/testing outline; hyperparameters and train/test split composition are not described
- The study could not cover all LC and MS instruments, especially newly emerging ones
- Generalization of the workflow to other QC and experimental samples requires further investigation
- No DOI/accession number for the PRIDE submission (2754 DIA files) is given in the text
