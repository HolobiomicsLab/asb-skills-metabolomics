# lc-msms-feature-table-ingestion

## Summary

Ingest MS-Dial-derived LC-MS/MS output into the margheRita mRList object using read_input_file(), which consumes two tab-delimited text files (a feature data file and a sample annotation file) and produces the main input/output container for all downstream margheRita functions.

## When to use

Use when starting a margheRita workflow from MS-Dial-exported LC-MS/MS feature tables and sample metadata, before any filtering, normalization, annotation or statistics can run.

## When NOT to use

- Data is already inside a margheRita mRList — skip ingestion and apply filtering/normalization functions directly.
- Input is raw instrument data (e.g. vendor RAW/mzML files) — peak picking must first be done externally (e.g. with MS-Dial) before ingestion.
- Data was read from MS-Dial Excel spreadsheets for the notame workflow (notame reads Excel; margheRita read_input_file requires tab-delimited text) — use the matching package's reader instead.

## Inputs

- Tab-delimited feature data file exported from MS-Dial (feature identifiers, m/z, retention times, MS/MS spectra, abundances)
- Tab-delimited sample annotation file with columns id, injection_order, batch, class, biological_rep, technical_rep
- Urine dataset feature file (Zenodo 10.5281/zenodo.11243781) and package extdata sample annotation for the demo workflow

## Outputs

- mRList object with five elements: data, metab_ann, sample_ann, QC, QC_ann

## How to apply

Call margheRita's read_input_file() on two tab-delimited files: the feature data file (usually generated by MS-Dial; containing feature identifiers, m/z, retention times, MS/MS spectra and abundances) and a sample annotation file with the columns id, injection_order, batch, class, biological_rep and technical_rep. The function assembles these into the mRList object with exactly five elements: data, metab_ann, sample_ann, QC and QC_ann; QC samples must be present in QC and QC_ann since downstream QC-based steps (e.g. CV filtering samples vs QCs) depend on them. Validation is straightforward: check that the returned object has precisely the five expected elements and that feature/sample dimensions match the source tables. For testing, the full Urine dataset (Zenodo doi 10.5281/zenodo.11243781) plus the sample annotation shipped in the package extdata directory can be used to build a demo mRList.

## Related tools

- **margheRita** (Provides read_input_file() which builds the mRList object from the two tab-delimited input files) — https://github.com/emosca-cnr/margheRita
- **MS-Dial** (Generates the feature data file that is usually ingested via read_input_file())
- **R** (Runtime environment in which read_input_file() is called and the mRList object is validated)

## Examples

```
library(margheRita); mL <- read_input_file(feature_file = "Urine_feature_table.txt", sample_ann_file = "Urine_sample_annotation.txt")
```

## Evaluation signals

- Returned object is an mRList containing exactly the five expected elements: data, metab_ann, sample_ann, QC and QC_ann.
- data contains feature identifiers, m/z, retention times, MS/MS spectra and abundances read from the MS-Dial feature table.
- sample_ann columns match id, injection_order, batch, class, biological_rep and technical_rep.
- Feature and sample counts in mRList match the source tables (demo Urine mRList yields 604 features across 243 samples before filtering).
- QC and QC_ann are populated so downstream CV (samples vs QCs) filtering can run.

## Limitations

- mRList ingestion requires the specific sample-annotation schema (id, injection_order, batch, class, biological_rep, technical_rep); files missing these columns will not populate the structure correctly.
- Downstream technical-replicate collapse depends on shared concatenations of class and biological_rep values, so annotation errors at ingestion propagate through the workflow.
- The pipeline is designed for LC-MS/MS untargeted metabolomics (especially DIA/SWATH with high-resolution MS/MS); other data modalities are out of scope.
