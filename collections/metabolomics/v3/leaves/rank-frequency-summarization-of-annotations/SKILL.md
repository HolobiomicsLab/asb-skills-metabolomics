# Rank-frequency summarization of annotations

## Summary

Aggregate per-file molecular formula annotations from IDSL.UFA into an aligned annotated peak table by computing, per peak, each candidate formula's detection frequency across samples and its median rank, then re-ranking formulas on these summary statistics.

## When to use

Use when per-file formula annotation peaklists (from IDSL.IPA/IDSL.UFA) must be collapsed into one annotated aligned peak table, and formulas per peak must be ranked across all samples by detection frequency and median rank.

## When NOT to use

- Input is a single-sample peaklist — aggregation statistics (frequency/median rank across samples) are undefined; use individual peaklist ranking instead
- You need structural (MS2) identification rather than MS1 formula annotation — this skill only summarizes isotopic-profile-based formula annotations
- Peak picking/alignment has not yet been performed — first generate chromatographic peak information with IDSL.IPA (mzXML, mzML, netCDF input)

## Inputs

- Per-file formula annotation peaklists generated by the IDSL.IPA/IDSL.UFA workflow
- Aligned peak table (peak_alignment directory) of m/z-RT peaks from IDSL.IPA
- UFA parameter spreadsheet with PARAM0006 (aligned-table aggregation) set to YES
- IPDB (.Rdata) isotopic profile database used for annotation (e.g. RefMetDB positive/negative mode)

## Outputs

- Aligned annotated peak table (csv) with per-peak formula lists ranked by detection frequency and median rank
- Per-peak formula detection frequencies across samples
- Per-peak median ranks for each candidate molecular formula

## How to apply

Load the individual per-file formula annotation peaklists and the aggregated peak alignment table produced by the IDSL.IPA workflow. For each aligned peak (m/z-RT), count in how many samples each candidate molecular formula was annotated (detection frequency) and compute the median rank of each formula across the samples where it was annotated. Rank the formulas per peak by these two statistics and export the aligned annotated peak table as a csv, retaining the top formula hits (e.g. top rank ≤ 30 and number of hits ≤ 30; a median rank ≤ 5 is used downstream to report high-confidence annotated peaks). Enable this via PARAM0005/PARAM0006 = YES in the UFA parameter spreadsheet and supply the peaklists and peak_alignment directories (PARAM0011/PARAM0012) plus an IPDB (.Rdata) formula source (PARAM0004).

## Related tools

- **IDSL.UFA** (Performs the aggregation: summarizes formula annotations using detection frequency and median ranks in multiple samples to build the aligned annotated peak table) — https://cran.r-project.org/package=IDSL.UFA
- **IDSL.IPA** (Upstream peak extraction producing the individual peaklists and peak_alignment directory consumed by the summarization) — https://github.com/idslme/IDSL.IPA
- **R** (Runtime environment; IDSL.UFA is an R package invoked with the UFA_workflow function)

## Examples

```
library(IDSL.UFA); UFA_workflow("Address of the UFA parameter spreadsheet")  # with PARAM0006 = YES
```

## Evaluation signals

- Aligned annotated peak table is a csv in which every aligned peak row carries formula candidates annotated with both a detection frequency and a median rank
- Per-peak formula sort order changes relative to the per-file lists and reflects frequency/median-rank ordering (higher frequency, lower median rank first)
- Reported annotated peaks satisfy a median rank ≤ 5 for at least one molecular formula
- Table corresponds to setting PARAM0005 and PARAM0006 to YES in the UFA parameter spreadsheet, with peaklists and peak_alignment addresses supplied as PARAM0011/PARAM0012

## Limitations

- Summaries are only as reliable as the underlying MS1 isotopic-profile matches; formula candidates are limited to the chemical space in the selected IPDB source
- Reporting thresholds matter: aligned-table filtering used top rank ≤ 30 and number of hits ≤ 30 for unique formula reporting in the article
- Detection-frequency/median-rank aggregation inherits gaps from compounds filtered out upstream by detection frequency and intensity thresholds (a stated weakness of database-dependent workflows)
