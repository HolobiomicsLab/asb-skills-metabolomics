# Cross-pipeline matrix comparison: IDSL.IPA vs MS-DIAL

## Summary

Benchmark skill that compares feature matrices generated by two untargeted LC/HRMS peak-picking pipelines (IDSL.IPA and MS-DIAL) by mapping both onto the same phenotype and testing peak-level statistical associations, e.g. Spearman correlations against birth weight in the 499-sample MTBLS1684 cord-blood study.

## When to use

Use when two peak-intensity/height data matrices were generated from the same raw LC/HRMS study by different pipelines (e.g. IDSL.IPA vs MS-DIAL) and you need a statistically grounded comparison of how many features each detects as associated with a phenotype.

## When NOT to use

- The two matrices come from the same pipeline and only differ in parameters - the comparison would measure parameter tuning, not pipeline sensitivity
- Peak matrices have not been aligned to a common sample-ID key, so per-peak phenotypic correlations would be computed on mismatched samples
- Input is already a set of annotated/formula-assigned peaks and the goal is formula or structural annotation rather than quantifying pipeline detection sensitivity

## Inputs

- IDSL.IPA aligned and gap-filled peak-height data matrix (samples x peaks)
- MS-DIAL exported aligned feature/peak table from the same raw data
- Study metadata table with sample IDs and phenotype values (e.g. birth weight, from Metabolomics Workbench study MTBLS1684)

## Outputs

- Per-pipeline table of Spearman rho, raw p, BH-adjusted p, and significance flag per peak (e.g. birth_weight_spearman_results.csv)
- Count of significant peaks (adjusted p < 0.05) per pipeline and their intersection (IDSL.IPA-only / common / MS-DIAL-only)
- Fold ratio of significant peaks between pipelines (e.g. 2.9x for IDSL.IPA vs MS-DIAL)

## How to apply

Load each pipeline's aligned, gap-filled peak-height matrix (IDSL.IPA writes an aligned matrix with peak-height columns per sample; MS-DIAL exports an analogous feature table) and join both to the study metadata on sample IDs, as done for the 499 cord-blood samples of MTBLS1684. For each pipeline separately, run a Spearman rank correlation of peak height vs the phenotype (birth weight) per peak and adjust p-values for multiple testing (Benjamini-Hochberg/FDR), filtering to adjusted p < 0.05. Compute the overlap of significant peak lists between the two pipelines and express sensitivity difference as a fold ratio (the published result: IDSL.IPA yielded 2.9x more significant peaks - 213 IDSL.IPA-only, 401 common, 37 MS-DIAL-only). Judge the comparison only after verifying that sample IDs, phenotype direction (e.g. birth weight in grams), and the significance cutoff are identical across both matrices.

## Related tools

- **IDSL.IPA** (Produces the aligned, gap-filled peak-height matrix whose significant-peak yield is benchmarked against MS-DIAL using Spearman correlation on MTBLS1684) — https://github.com/idslme/IDSL.IPA
- **MS-DIAL** (Reference peak-picking pipeline producing the comparison feature table; its significant-peak count is the denominator of the 2.9x enrichment benchmark)
- **R** (Language used to join matrices to metadata, run per-peak Spearman correlations, apply BH/FDR adjustment, and count significant peaks)

## Examples

```
library(IDSL.IPA); aligned <- read.csv('MTBLS1684_IPA_peak_height_matrix.csv'); meta <- read.csv('MTBLS1684_metadata.csv'); merged <- merge(aligned, meta, by='SampleID'); res <- data.frame(peak=names(aligned)[-1], rho=apply(aligned[-1], 2, function(x) cor(x, merged$birth_weight, method='spearman'))); res$p <- apply(res, 1, function(r) cor.test(aligned[[r['peak']]], merged$birth_weight, method='spearman')$p.value); res$padj <- p.adjust(res$p, 'BH'); write.csv(res[res$padj<0.05,], 'birth_weight_spearman_results.csv')
```

## Evaluation signals

- Both pipelines must be correlated against the same phenotype column and identical sample-ID set; a mismatch in sample count (e.g. not 499 for MTBLS1684) invalidates the comparison
- Significance threshold is fixed at Spearman adjusted p < 0.05 (BH/FDR); any peak listed in the result table must carry an adjusted p < 0.05
- The published reference counts are 213 IDSL.IPA-only, 401 common, and 37 MS-DIAL-only significant peaks; reproduced counts should approximate the 2.9x fold ratio
- The significant-peak set from IDSL.IPA should substantially overlap with MS-DIAL's (401 common peaks), not be entirely disjoint; near-zero overlap signals a sample or annotation misalignment
- Check that every peak in each matrix was tested and that missingness/gap-filled zeros were handled the same way in both pipelines before computing the ratio

## Limitations

- Comparison is phenotype- and study-specific: the 2.9x ratio was measured on 499 MTBLS1684 samples for birth weight and may not transfer to other cohorts or endpoints
- IDSL.IPA aligned matrices 'need to be further processed for identifying adducts and fragments, filtering for statistics and annotating molecular formulas by additional computational' workflows, so raw matrix size differences partly reflect isotope/adduct redundancy that both pipelines handle differently
- Fold ratio counts significant peaks without normalizing for total peak count differences between pipelines (e.g. IDSL.IPA detected 20,253 peaks in a single 003.d file), so the ratio mixes detection depth with association yield
