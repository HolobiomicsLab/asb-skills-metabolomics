# mzmine-feature-spectra-integration

## Summary

Imports MZmine-exported GNPS MGF files into R as Spectra objects via MsBackendMgf so that externally generated MS2 feature spectra can serve as the query in matchSpectra()-based annotation against a CompoundDb reference such as HMDB 5.0.

## When to use

Use when MS2 spectra were generated by an external feature-based tool such as MZmine or MS-DIAL and exported as MGF (e.g. MZmine-GNPS_AG_test_GNPS.mgf), and you need them as matchSpectra() query input in R.

## When NOT to use

- Query spectra are already available as an xcms result object in R, where MS2 can be extracted directly with chromPeakSpectra() instead of importing an external MGF
- The reference database provides precursor m/z values and a precursor-m/z prefilter is desired, so requirePrecursor = TRUE (default) in CompareSpectraParam is appropriate
- The goal is MS1-level annotation by m/z and retention time, which matchMz with Mass2MzParam or MzRtParam handles

## Inputs

- MZmine- or MS-DIAL-exported GNPS MGF file containing MS2 feature spectra (e.g. MZmine-GNPS_AG_test_GNPS.mgf)
- CompoundDb reference database (e.g. CompDb.Hsapiens.HMDB.5.0.sqlite, HMDB version 5.0)
- R environment with BiocManager, Spectra, MetaboAnnotation, CompoundDb, MsBackendMgf

## Outputs

- Spectra object of imported MZmine MS2 spectra retaining FEATURE_ID metadata
- Spectra object wrapping the CompDb target compounds
- Match table (e.g. mzmine_ms2_spectra_matches.csv) with FEATURE_ID, target_compound_id, target_name and score columns

## How to apply

Download the MZmine-exported GNPS MGF file (e.g. MZmine-GNPS_AG_test_GNPS.mgf from CCMS-UCSD/GNPSDocumentation) with curl_download, then import it as a Spectra object with Spectra(file, source = MsBackendMgf()), verifying that the FEATURE_ID variable from the MGF fields is retained so matches can be traced back to MZmine features. Build the target set by wrapping a CompDb database (CompDb.Hsapiens.HMDB.5.0.sqlite) in a Spectra object with Spectra(cdb). Run matchSpectra(query, Spectra(cdb), param = CompareSpectraParam(ppm = 50, requirePrecursor = FALSE)); disable the precursor-m/z filter because HMDB does not provide precursor m/z values, and rely on the default 0.7 normalized dot-product similarity threshold. Extract results with matchedData selecting columns such as FEATURE_ID, target_compound_id, target_name and score, and write them to a CSV (e.g. mzmine_ms2_spectra_matches.csv).

## Related tools

- **Spectra** (Creates Spectra objects for both the imported MGF query spectra and the CompDb target spectra) — https://rformassspectrometry.github.io/Spectra/
- **MsBackendMgf** (Backend used as the data source to import MZmine-exported MGF files into R)
- **MetaboAnnotation** (Provides matchSpectra() and CompareSpectraParam to match query feature spectra against the reference library) — https://rformassspectrometry.github.io/MetaboAnnotation/
- **CompoundDb** (Provides the CompDb reference compound database (HMDB 5.0) used as the annotation target) — https://rformassspectrometry.github.io/CompoundDb/

## Examples

```
spectra <- Spectra(file.path(tempdir(), "MZmine-GNPS_AG_test_GNPS.mgf"), source = MsBackendMgf())
```

## Evaluation signals

- mzmine_ms2_spectra_matches.csv exists and is parseable
- The imported Spectra object retains the FEATURE_ID metadata variable from the original MGF fields
- The match table contains rows with score entries for matched query-target spectrum pairs
- Scores are normalized dot-product similarities above the default 0.7 threshold
- Import succeeds with Spectra(file, source = MsBackendMgf()) without dropping MGF metadata fields

## Limitations

- HMDB does not provide precursor m/z, so the precursor-m/z filter must be disabled (requirePrecursor = FALSE), which increases the candidate space and comparison cost
- Only matches exceeding the default 0.7 similarity threshold are reported; weaker matches are silently dropped
- Retention of MGF fields such as FEATURE_ID depends on the export format produced by MZmine/MS-DIAL; other exports may not carry feature identifiers
