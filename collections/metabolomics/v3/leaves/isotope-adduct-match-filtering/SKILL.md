# isotope-adduct-match-filtering

## Summary

Prioritizes compound database matches for significant m/z values by filtering on main-peak isotope status, adduct status, and source database, then sorting by ppm error to yield putative (MSI level 2) annotations as implemented in MetaboShiny.

## When to use

Use when compound matches returned by an m/z database search (e.g. HMDB via MetaDBparse) must be filtered and prioritized by isotope and adduct status, with identical-SMILES rows collapsed, to assign putative MSI level 2 annotations.

## When NOT to use

- You need confirmed identities (MSI level 1); isotope/adduct filtering only prioritizes putative (MSI level 2) annotations and cannot confirm structures
- You want to annotate all measured m/z values rather than significant hits; MetaboShiny annotates only hits resulting from its statistical analysis
- Your raw spectra have not yet been peak-picked; MetaboShiny does not accept raw peak data and expects peaklists (e.g. XCMS/MetaboAnalyst export)

## Inputs

- Compound match results table from the MetaboShiny/MetaDBparse database search for queried m/z values (columns: adduct, isotope label, ppm error, source database)
- Significant m/z hit values from the statistical analysis (e.g. the 264, 308, 441, 561 m/z hits from the reproduced lung cancer study)
- Locally built compound database (e.g. HMDB) pre-generated by MetaDBparse with isotope and adduct m/z variants
- User-defined ppm error margin for the mass spectrometer

## Outputs

- filtered_annotations.csv containing prioritized MSI level 2 'putatively annotated compound' entries with adduct, isotope, ppm error, and database fields
- annotation_counts.csv with exact row counts per MSI level (e.g. 4 at MSI level 1, 264 at the next level)

## How to apply

Load the compound match results produced by the MetaboShiny/MetaDBparse search of significant m/z values (each row carrying adduct, isotope label, ppm error, and source database, e.g. HMDB), then retain only matches with main peak isotopes (100% peak) as MetaboShiny does in its search results table. Score and filter the survivors on adduct and isotope status together with source database, since MetaboShiny guides users to putative identifications by prioritizing compounds on these properties. Sort the remaining matches by ppm error within the user-defined mass tolerance (the ppm error margin set when loading the peak files). Collapse rows sharing identical SMILES into single annotation entries while keeping structural isomers (same formula, different SMILES) as separate rows. Label each prioritized hit as MSI level 2 'putatively annotated compound' and write the table to filtered_annotations.csv.

## Evaluation signals

- All retained matches have main peak (100%) isotope labels; non-main-peak isotope matches are removed
- Rows sharing identical SMILES are collapsed into a single annotation entry, while structural isomers (same formula, different SMILES) remain separate rows
- Output table contains adduct, isotope, ppm error, and source database columns for every retained hit
- Retained hits are sorted by ppm error within the user-defined mass tolerance
- Every retained hit carries an MSI level 2 'putatively annotated compound' label (e.g. creatine riboside as the M + H adduct of 264 m/z)

## Limitations

- The result is putative (MSI level 2) annotation only; MSI level 1 requires confirmed identifications, which this filtering step does not provide
- Annotation is restricted to significant hits from the statistical analysis, not the full peaklist of over a hundred thousand unidentified m/z values
- Databases must be pre-built once via MetaDBparse and are not automatically updated; rebuilding is manual via the 'build database' button
- Prioritization depends on the adduct rules and isotope scoring settings (e.g. M-score, intensity imprecision default 2%) configured in the app
