# compound-growth-measurement-across-expansion-generations

## Summary

Quantifies how a Pickaxe reaction-rule network expansion grows in size and computational cost by recording unique compound and reaction counts per expansion generation and benchmarking runtime, demonstrating the exponential growth that makes multi-generation expansions intractable (e.g. 12 million new compounds in the YMDB run).

## When to use

Use when planning or characterizing a rule-based network expansion and you need per-generation compound/reaction counts plus runtime measurements to decide how many generations or cutoffs are tractable.

## When NOT to use

- The goal is a single-generation expansion with filters applied for target-directed applications (e.g. similarity sampling or metabolomics filtering), not growth/tractability characterization
- The network is not generated by iterative reaction-rule application (e.g. a pre-computed network or web-only tool), so per-generation growth is not defined
- You need quantitative thermodynamic or feasibility annotations of compounds rather than expansion size and runtime scaling

## Inputs

- Starting compound set (e.g. YMDB compounds, 1,035 starting compounds for the YMDB expansion)
- Reaction ruleset (e.g. 100-rule subset of JN1224min derived from MetaCyc)
- Molecular-weight/memory cutoff (<300 g/mol for the Figure 3 growth run)
- Number of expansion generations (two generations in the reported YMDB multi-generation run)
- fig3_gen_exp_growth/run_files/mem_lt300_100r.py generation script
- fig3_gen_exp_growth/analysis/benchmarks.ipynb benchmark notebook

## Outputs

- Per-generation compound and reaction counts
- Per-generation Pickaxe runtime measurements
- Consolidated growth/runtime data table in CSV format
- Figure 3 exponential growth curves and runtime benchmark plots

## How to apply

Run the exponential-growth generation script fig3_gen_exp_growth/run_files/mem_lt300_100r.py, which expands a compound set with a 100-rule ruleset under a molecular-weight/memory cutoff below 300 using the minedatabase package, and record unique compound and reaction counts for each generation. Execute the runtime benchmarks in fig3_gen_exp_growth/analysis/benchmarks.ipynb to measure Pickaxe generation runtime per expansion generation (in the paper, 12 million new compounds were inserted into a mongo database in approximately nine hours). Consolidate the per-generation counts and measured runtimes into a single CSV data table. Render the growth curves and runtime benchmark plots with fig3_gen_exp_growth/analysis/fig3_plot.ipynb to reproduce the Figure 3 panels. Judge success by whether the reproduced plots show exponential growth of compounds and reactions across generations and runtime trends matching Figure 3's qualitative behavior.

## Evaluation signals

- Reproduced plots show exponential increase in unique compounds with each generation (e.g. YMDB run reaching 12 million new compounds over two generations)
- Per-generation compound/reaction counts are recorded for every generation, not only the final network size
- Runtime measurements from benchmarks.ipynb match the qualitative runtime trends of the Figure 3 benchmark panels
- Consolidated CSV contains paired per-generation count and runtime columns for each expansion run
- Growth run parameters match the Figure 3 setup: 100-rule ruleset, molecular-weight/memory cutoff below 300

## Limitations

- Multi-generation expansions grow exponentially and become computationally intractable; the reported YMDB run produced 12 million new compounds requiring ~9 hours to insert into a mongo database
- Runtime performance benchmark data is referenced as a supplementary file whose content is not included in the article text
- No Pickaxe software version number is stated (only Python 3.7 or higher), so exact reproducibility of runtime numbers may vary
- Qualitative trend matching, not exact numeric agreement, is the stated validation criterion for the reproduced Figure 3 plots
