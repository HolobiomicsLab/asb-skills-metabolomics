# microbeMASST-output-parsing

## Summary

Parses the tabular outputs generated by a microbeMASST batch search (_matches.tsv, _datasets.tsv, _count_domain.tsv, _library.tsv) and aggregates them into a per-compound table of taxonomic hits and unique sample counts, enabling validation of taxonomically specific molecule–microbe assignments.

## When to use

Use when microbeMASST jobs.py batch search output files (_matches.tsv, _datasets.tsv, _count_microbe.tsv) exist and you need per-compound taxon hit tables to answer which taxa match a molecule.

## When NOT to use

- The microbeMASST batch search has not been run yet (jobs.py output files do not exist) — run the search first, re-running with skip_existing=True until outputs stabilize
- The analysis target is plant, tissue, microbiome, or food context — use the corresponding _count_domain.tsv / plantMASST etc. outputs rather than microbe-specific counts
- Input is raw LC-MS/MS data not yet processed into .mgf or USI format — feature detection and .mgf generation (e.g., via MZmine) must precede the search

## Inputs

- _matches.tsv file from a microbeMASST batch search (all scans matching the searched spectrum)
- _datasets.tsv file (unique samples matching per indexed dataset)
- _count_microbe.tsv / _count_domain.tsv files (matches per domain-specific MASST)
- _library.tsv file (matching GNPS library spectra)
- _microbe.html and _microbe.json interactive tree outputs (optional, for visualization)
- Input spectrum list (.mgf from MZmine, or USI .csv/.tsv) used for the search

## Outputs

- Aggregated per-compound taxonomic hits table (TSV) listing, for each compound, taxa and unique sample counts
- Per-compound validation summaries (e.g., lovastatin -> Aspergillus only, salinosporamide A -> Salinispora tropica only)

## How to apply

After running jobs.py (re-running a couple of times with skip_existing=True until no new output is generated, since Fast Search API entries can fail), parse the _matches.tsv file containing all scans found to match the searched spectrum, the _datasets.tsv file with unique matching samples per indexed dataset, and the _count_microbe.tsv file with per-domain matches. For each input compound (e.g., GNPS library spectra of lovastatin, salinosporamide A, commendamide), extract the taxa at genus/species/strain level and the unique sample counts, then aggregate into one structured TSV with one row per compound. Validation checks: the output table exists as TSV, contains exactly one row per searched compound (e.g., nine rows for the nine-compound validation set), and specific reported distributions are reproduced (lovastatin exclusively to Aspergillus, salinosporamide A only to Salinispora tropica, no matches in human cell lines). Note that _matches.tsv also includes samples outside the curated microbeMASST domain, so filtering to the curated domain counts is needed for taxon-specific conclusions.

## Examples

```
python code/jobs.py --input spectra.mgf --output_prefix results/lovastatin --skip_existing True
```

## Evaluation signals

- Output table exists as TSV and contains exactly one row per searched compound (nine rows for the nine-molecule validation set)
- lovastatin shows Aspergillus as its exclusive taxon in the parsed _count_microbe.tsv aggregation
- salinosporamide A maps only to Salinispora tropica strains; commendamide maps to Flavobacteriaceae and Bacteroides cultures; no hits in human cell lines
- _datasets.tsv unique-sample counts per dataset are consistent with the taxon counts in _count_microbe.tsv for the same compound
- Re-running jobs.py with skip_existing=True produces no new output (all Fast Search API entries have been captured) before parsing

## Limitations

- Fast Search API entries can fail on a single run; jobs.py must be re-run a couple of times with skip_existing=True until no new output is generated
- _matches.tsv includes samples not part of the curated domain-specific MASSTs, so raw match counts overestimate domain-specific taxonomic coverage
- Python 3.10 is required; other versions may not run jobs.py correctly
- No changelog is available for the repository, so output schema stability across versions is not documented
