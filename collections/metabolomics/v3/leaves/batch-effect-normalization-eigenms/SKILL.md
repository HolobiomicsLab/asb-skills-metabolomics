# batch-effect-normalization-eigenms

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Applies EigenMS normalization, implemented via ProteoMM, to remove batch effects from metabolomic and lipidomic feature tables generated by the Multi-ABLE extraction method, and was identified in this paper as the best-suited normalization method for MultiABLER.

## When to use

Use when processing a metabolomic or lipidomic feature table through the MultiABLER pipeline and a single normalization approach that corrects for batch effects is needed before downstream differential-expression analysis (e.g. limma) or cross-validated classification.

## When NOT to use

- When the feature table has not yet passed through MultiABLER's tbManipulate (filtering, imputation, log-transformation) — EigenMS is positioned as the normalization step after this preprocessing in the pipeline
- When kNN imputation, mean normalization, or quantile normalization are explicitly required — the paper notes these methods were not implemented in MultiABLER, so the wrapper cannot supply them
- When the target data are proteomic — the article states MultiABLER does not currently provide functions to analyze proteomic data, even though the Multi-ABLE extraction method also outputs proteomes

## Inputs

- Preprocessed (filtered, imputed, log-transformed) metabolomic or lipidomic feature table (data frame of peak intensities) from MultiABLER's tbManipulate
- Sample information / metadata data frame carrying batch and biological-group labels (required as the sample.info argument to normEigenMS)

## Outputs

- EigenMS-normalized feature table (data frame) suitable for downstream limma differential-expression analysis, sPLS, or rCCA

## How to apply

After preprocessing the feature table with MultiABLER's tbManipulate(df, filter_threshold, impute, log_base) — which filters low-quality features, imputes missing values, and log-transforms abundances — apply EigenMS as the normalization step, passing the processed data frame together with the sample metadata so that batch structure in the design can be modelled. EigenMS uses singular-value-decomposition-based consensus correction (ProteoMM implementation) to remove batch effects while preserving biological contrasts, and is invoked via normEigenMS(df, sample.info) within the MultiABLER workflow. The paper compared EigenMS against no normalization, median normalization (normMedian), NOMIS, and CRMN, and found EigenMS alone to be best suited for MultiABLER; in 5-fold cross-validated classification of a liver lipidomic dataset (ClassifyR, DLDA, 20 repetitions), EigenMS reached median balanced accuracy 0.68 and AUC 0.75. EigenMS followed by median normalization performed similarly (BA 0.69, AUC 0.76), whereas no normalization (BA 0.40), NOMIS (BA 0.48) and CRMN (BA 0.38) performed markedly worse. The normalized tables are then suitable for downstream limma differential-expression modelling, sPLS, or rCCA.

## Examples

```
normEigenMS(df, sample.info)
```

## Evaluation signals

- Normalized feature table must retain the same number of samples and features as the input table, with no NaNs introduced where imputation was applied
- In 5-fold ClassifyR cross-validation (DLDA, 20 repetitions) on a downstream classification task, EigenMS-normalized data should yield median balanced accuracy around 0.68 and median AUC around 0.75 for a liver lipidomic dataset
- EigenMS alone should rank at or above alternatives (no normalization, median, NOMIS, CRMN) in balanced accuracy; expected approximate benchmarks: BA 0.40 (none), 0.68 (EigenMS), 0.48 (NOMIS), 0.38 (CRMN)
- After EigenMS, boxplots or PCA of intensities should show reduced between-batch spread relative to the unnormalized log-transformed table
- Downstream limma differential-expression counts (e.g. 903 lipids and 601 metabolites DE at adjusted p<0.05 on the Apoe+/+ vs Apoe−/− arterial data) should be reproducible when EigenMS precedes the limma model

## Limitations

- MultiABLER's EigenMS wrapper handles only metabolomic and lipidomic feature tables; proteomic data, another Multi-ABLE output, is not supported and integration is only planned for future development
- Alternative normalization approaches such as kNN imputation, mean normalization, and quantile normalization are not implemented in MultiABLER, so they cannot be substituted within this skill's pipeline
- EigenMS requires sample information to be supplied; without correct batch/group metadata the batch-effect correction cannot be modelled
- The published benchmarks (BA 0.68/AUC 0.75 for EigenMS alone; BA 0.69/AUC 0.76 for EigenMS followed by median) were obtained with 5-fold ClassifyR cross-validation and DLDA on a liver lipidomic dataset and may vary with different classifiers or data
