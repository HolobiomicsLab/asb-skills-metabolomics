# deep-learning-model-training

## Summary

Train a mass-spectrometry spectral prediction model (FormulaNet or SubsetNet) end-to-end with the RASSP pipeline by running rassp/forward_train.py against a YAML experiment configuration, producing PyTorch checkpoint and state files that can later be evaluated or used for inference.

## When to use

Use when you have a parquet dataset of (molecule, spectrum) pairs with columns such as mol_id, inchi, rdmol, cv_id, and spect, plus an expconfig YAML, and need to fit a GNN spectral prediction model from scratch.

## When NOT to use

- You only need spectra for a list of molecules from an already-trained model — use run_rassp.py or the spectroscopy.ai web API instead of retraining.
- Your molecules exceed the model's supported size (FormulaNet ≤ 48 atoms, SubsetNet ≤ 64 atoms) or contain elements outside HCONFSPCl — preprocessing and the trained model will not handle them.
- You want to evaluate an existing checkpoint or compute library-matching metrics — that is the job of forward_evaluate_pipeline.py and library_match_pipeline.py, not training.

## Inputs

- Parquet dataset with columns mol_id, inchi, inchi_key, smiles, rdmol (binary RDKit blob via Chem.Mol), cv_id, morgan4_crc32, and spect as List[Tuple[Float, Float]] (mass, intensity) pairs
- YAML experiment configuration (e.g. rassp/expconfig/demo.yaml) specifying model architecture and training hyperparameters
- Additional run name argument (e.g. 'first-test') used to name the output checkpoint

## Outputs

- PyTorch model checkpoint in checkpoints/ named <yaml_basename>.<additional_name>.<timestamp>.<epoch>.model (e.g. demo.first-test.48668593.00000000.model)
- Matching training/optimizer state file <yaml_basename>.<additional_name>.<timestamp>.<epoch>.state
- Tensorboard logs under tblogs.formulae

## How to apply

Set up the rassp Conda environment from rassp/environment.yml and install the rassp==1.0.0 module locally with `python -m pip install -e .`, resolving NumPy to version 1.21 if Numba or Tinygraph report binary-incompatibility errors. Load the sample parquet (e.g. sample_data/smallmols_cfm_pred_public_sample.parquet, the first 100 smallmols molecules with spectra generated by cfm-predict) and preprocess molecules into graph, subformula, and spectra tensors — molecules are filtered to HCONFSPCl atoms with total atoms ≤ 48 and ≤ 4096 unique fragment formulae, with subformulae enumerated recursively via setwise Cartesian product and subsets generated by breaking all bonds out to depth d = 3 plus exhaustive hydrogen rearrangements. Instantiate the model from the experiment YAML (rassp/expconfig/demo.yaml fixes the FormulaNet architecture and demo-scale hyperparameters) and execute the main training script `python rassp/forward_train.py rassp/expconfig/demo.yaml first-test`, optionally prepending `USE_CUDA=1 CUDA_VISIBLE_DEVICES='<GPU_ID>'` to select a device; the pipeline fits the model by stochastic gradient descent against minibatches of experimentally observed (molecule, spectra) pairs, minimizing the L2 error between predicted and observed spectra after power scaling. Validate on held-out cv_id splits (e.g. the 50-molecule fold in smallmols_cfm_pred_public_sample.1.parquet) and retain the best checkpoint by the Stein dot product-style criterion used by the pipeline. On success, checkpoints/ contains files matching the pattern `<yaml_basename>.<additional_name>.<timestamp>.<epoch>.model` (e.g. demo.first-test.48668593.00000000.model) alongside a matching `.state` file, and Tensorboard intermediates land in tblogs.formulae.

## Related tools

- **FormulaNet** (First RASSP model trained in this pipeline; a multilayer message-passing GNN with attention over subformulae embeddings that predicts probability distributions over chemical subformulae, achieving 92.9% Stein dot product on NIST 2017.) — https://github.com/thejonaslab/rassp-public
- **SubsetNet** (Alternative RASSP model trainable with the same forward_train.py script; predicts probability distributions over atom subsets via mean-pooled per-atom GNN embeddings, better suited to the high-resolution, low-data regime.) — https://github.com/thejonaslab/rassp-public
- **CFM-ID** (Generates the training spectra labels: the shipped 100-molecule smallmols sample dataset was produced by running cfm-predict against those molecules.) — https://cfmid.wishartlab.com/

## Examples

```
USE_CUDA=1 CUDA_VISIBLE_DEVICES='<GPU_ID>' python rassp/forward_train.py rassp/expconfig/demo.yaml first-test
```

## Evaluation signals

- Checkpoints directory contains a pair of files matching `<yaml_basename>.<additional_name>.<timestamp>.<epoch>.model` and `.state`, e.g. demo.first-test.48668593.00000000.model / .state.
- The trained checkpoint loads and produces spectra over the enumerated subformulae of held-out molecules without error.
- Validation Stein dot product on held-out cv_id folds is in the expected range (92.9% weighted Stein dot product was the headline NIST 2017 result for FormulaNet; a demo-scale run will be lower but should improve monotonically during training).
- Forward predictions from the checkpoint, when run through forward_evaluate_pipeline.py into forward.preds/demo.spect.sqlite, yield valid unpickled List[Tuple[Float, Float]] spectra in the spect column.
- No Numpy binary incompatibility errors (Numba requires NumPy ≤ 1.21; Tinygraph errors indicate a NumPy API mismatch) during training startup.

## Limitations

- Training is stochastic-gradient-descent based and benefits from GPU acceleration; multi-GPU training is described as 'finicky' and not recommended unless you are familiar with distributed training.
- NumPy version must be ≤ 1.21 to avoid Numba ImportError and Tinygraph binary-incompatibility errors.
- Models only cover molecules with HCONFSPCl atoms, ≤ 48 atoms (FormulaNet) or ≤ 64 atoms (SubsetNet), and ≤ 4096 unique fragment formulae.
- The demo configuration and 100-molecule sample are intended for pipeline validation, not for reproducing the full 100,438-molecule NIST 2017 training run (nist-train folds 2–9).
