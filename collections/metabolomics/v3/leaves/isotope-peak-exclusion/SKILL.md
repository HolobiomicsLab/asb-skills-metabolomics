# isotope-peak-exclusion

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Excludes peaks that the MassCube feature-detection backend has flagged as isotope peaks from pseudo MS/MS spectra generated by ms1-id, so that in-source fragment clusters represent true co-eluting structural fragments rather than isotope envelopes of the precursor ion.

## When to use

Use when generating pseudo MS/MS spectra from MS1-only LC-MS data (mzML/mzXML) or imaging data (imzML) with ms1-id, before writing correlated ion clusters to pseudo_msms.mgf, to strip isotope peaks.

## When NOT to use

- When peaks already derive from true tandem MS/MS scans rather than MS1-only data — isotope exclusion is specific to pseudo MS/MS generation from full-scan in-source fragments.
- When constructing molecular networking edges after modified cosine scoring — for that step, larger ions above the feature m/z are instead removed, which is a different cleaning rule.
- When the input is an already-generated pseudo_msms.mgf without MassCube isotope flags; the exclusion depends on MassCube feature-detection metadata.

## Inputs

- Full-scan LC-MS data in mzML or mzXML format
- Full-scan MS imaging data in imzML format
- MassCube feature detection output carrying per-peak isotope annotations

## Outputs

- Pseudo MS/MS spectra in pseudo_msms.mgf (MGF format) with isotope peaks removed from fragment lists
- Per-entry fragment peaks with original MS1 peak-height intensities and precursor feature m/z

## How to apply

After MassCube (ver 1.0.11) extracts metabolic features from the full-scan input, it determines which detected peaks are isotopes of other peaks; these isotope flags are carried into the ms1-id clustering step. When a target feature's pseudo MS/MS spectrum is assembled — collecting correlated features from XICs (LC-MS, Pearson ≥ 0.80 with ≥ 4 consecutive shared MS1 scans) or ion images (MSI, correlation ≥ 0.85 with ≥ 50 shared pixels) — any feature flagged as an isotope is dropped from the fragment list. Peak intensities written into the pseudo spectrum remain the original MS1 peak heights of the retained fragment peaks. This exclusion prevents isotope envelopes from being misregistered as in-source fragments and polluting downstream precursor-tolerant reverse spectral matching against the indexed GNPS library, where scores and matched-peak counts (min score 0.7, min 3 matched peaks) would otherwise be inflated by redundant isotope peaks.

## Related tools

- **ms1-id** (Generates pseudo MS/MS spectra via correlation-based clustering and applies the isotope-peak exclusion before writing MGF output) — https://github.com/Philipbear/ms1_id
- **MassCube** (Feature-detection backend that determines which peaks are isotopes; those flags drive the exclusion during pseudo MS/MS generation)

## Examples

```
ms1_id lcms --project_dir lc_ms --sample_dir data --ms1_id_libs db/gnps.pkl db/gnps_k10.pkl --ms2_id_lib db/gnps.pkl
```

## Evaluation signals

- Verify that no peak in each pseudo MS/MS entry corresponds to a known isotope offset (+1.00335, +1.99705, etc.) of the precursor feature m/z within the mass tolerance.
- Check that pseudo_msms.mgf entries still contain non-isotope fragment peaks correlated at Pearson ≥ 0.80 (LC-MS) or 0.85 (MSI) before exclusion was applied.
- Confirm peak intensities in the output MGF equal original MS1 peak heights of the retained fragments, not rescaled values.
- Cross-check that downstream annotation (min score 0.7, min 3 matched peaks, min spectral usage 0.20 for LC-MS) is not dominated by isotope-derived matches.
- Compare pseudo spectra with and without isotope exclusion: excluded spectra should show lower redundant matched-peak counts against the indexed GNPS library.

## Limitations

- Exclusion quality depends entirely on MassCube's isotope-peak determination; misassigned isotope labels will incorrectly remove true fragments or leave true isotopes in.
- The skill applies to the MS1 annotation path of ms1-id only; it is not part of the separate MS/MS library annotation path (ms2_id) that runs alongside it.
- If a pseudo spectrum loses all fragments after isotope exclusion (e.g. an isotopically dominated cluster), it may fail downstream cutoffs and be dropped from annotation.
