# mass-spectral-binning-0.1-da

## Summary

Bins predicted and experimental MS/MS peak lists into 0.1-Da intensity vectors and computes vectorized cosine similarity, the evaluation convention used to benchmark ICEBERG against MassFormer, FixedVocab, SCARF, NEIMS, and CFM-ID on NPLIB1 and NIST20.

## When to use

Use when comparing predicted tandem mass spectra (from ICEBERG or baseline simulators) against ground-truth library spectra and you need a dataset-wide average cosine similarity on a common binned representation.

## When NOT to use

- NPLIB1 support has been retired on the ms-pred main branch — use the iceberg_1.0 branch for NPLIB1 (CANOPUS) evaluation, or switch to NIST20/23 on main
- When the goal is fragment-level structural interpretation rather than scalar spectrum-level accuracy — binned cosine similarity cannot judge whether breakage-event explanations are physically correct
- When comparing predictors that operate on different fragmentation granularities without first mapping all outputs to a shared binned representation

## Inputs

- Predicted binned spectra generated by ICEBERG predict_smis.py or baseline predict scripts (02_predict_ffn.py, 02_predict_gnn.py, 02_predict_massformer.py, 05_predict_form_inten.py, CFM-ID)
- Ground-truth experimental MS/MS spectra from NPLIB1 and NIST20 processed test splits
- 0.1-Da binning configuration consistent with the ms-pred analysis module

## Outputs

- Per-spectrum cosine similarity values against ground truth
- Per-model, per-dataset average cosine similarity (assembled into a benchmark CSV table)

## How to apply

Convert each predicted spectrum and its ground-truth counterpart into binned intensity vectors with 0.1-Da bin width, then compute the vectorized cosine similarity implemented in the analysis module (analysis/spec_pred_eval.py) of the ms-pred repository. Run this per model per dataset test split (e.g., ICEBERG via src/ms_pred/iceberg/predict_smis.py, baselines via their run_scripts predict entry points), then average cosine similarity across each test split. The rationale is that fragment-level predictors (ICEBERG, GLACIER) emit spectra at the fragment level while formula-level predictors like SCARF emit at the chemical formula level, so a common 0.1-Da binned vector representation enables fair cross-model comparison. ICEBERG itself is trained to maximize this same vectorized cosine similarity, making the metric model-aligned. Accept the resulting benchmark table only if ICEBERG's row lands near the reported values (~0.627 on NPLIB1, ~0.727 on NIST20) and baselines fall within reported ranges (e.g., MassFormer/FixedVocab ~0.568 on NPLIB1, SCARF ~0.726 on NIST20).

## Examples

```
python analysis/spec_pred_eval.py
```

## Evaluation signals

- ICEBERG average cosine similarity on NPLIB1 must reproduce ~0.627
- ICEBERG average cosine similarity on NIST20 must reproduce ~0.727
- MassFormer and FixedVocab baseline rows must land near 0.568 on NPLIB1
- SCARF row must land near 0.726 on NIST20 (nearly equivalent to ICEBERG)
- All models must be evaluated on the same 0.1-Da binned vector representation before averaging across each test split

## Limitations

- Because ICEBERG trains on the vectorized cosine objective and equivalent-mass atom/bond rearrangements exist, there are no guarantees that generated fragment explanations are the correct physical explanations even when cosine similarity is high
- ICEBERG inference costs roughly 1 CPU second per molecule (nearly an order of magnitude more than SCARF), which limits benchmark throughput
- Dataset support differs by branch: NPLIB1 is retired on ms-pred main and only supported on the iceberg_1.0 legacy branch
