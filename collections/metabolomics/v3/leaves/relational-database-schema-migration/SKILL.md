# relational-database-schema-migration

## Summary

Migrates flat or static-HTML data holdings into a PostgreSQL relational database fronted by a REST-like web API, as done for MIBiG 2.0's repository of biosynthetic gene clusters (BGCs). Enables filtering, sorting and Boolean querying over annotation metadata instead of static pages.

## When to use

Use when a repository's data currently lives in static HTML pages or flat files and must be migrated into a relational schema (PostgreSQL) with an API layer so downstream clients can query/filter entries by metadata.

## When NOT to use

- The dataset already resides in a relational database with an existing API layer — re-migration would duplicate infrastructure
- The goal is exploratory analysis of BGCs rather than standing up a persistent public repository backend
- Annotation files cannot be made to conform to the JSON schema description and validation technology, which the antiSMASH 5 sideload depends on

## Inputs

- Curated MIBiG 2.0 BGC entries (annotation data with literature references and chemical structures)
- SQL schema for the MIBiG Repository from the mibig-secmet GitHub organisation
- JSON-formatted MIBiG data standard annotation files validated against json-schema.org
- Static HTML repository pages being replaced

## Outputs

- PostgreSQL relational database populated with MIBiG entries
- REST-like web API server (mibig-api) exposing annotation metadata
- AngularJS single-page web application with repository filtering/sorting and Boolean query support
- BGC detail pages generated by a customised antiSMASH 5 module via JSON sideload

## How to apply

Load the curated dataset (for MIBiG 2.0: 851 new BGCs, expanded from 1170 to 2021 curated BGC entries) into a PostgreSQL relational database using the SQL schema published in the project's GitHub organisation, replacing static HTML page storage. Implement the REST-like web API — for MIBiG this is the mibig-api Go server (requires Go 1.11.x for dependency handling; Apache License 2.0) — so it handles access to the underlying PostgreSQL database and serves annotation metadata for repository rows. Build a single-page AngularJS web application that consumes the API and supports browsing, filtering (e.g. by compound names, taxonomic identifiers or biosynthetic classes) and sorting of repository rows. For derived artefacts, validate incoming annotation files against the JSON schema description and validation technology before sideloading them into a customised antiSMASH 5 module that renders individual BGC detail pages. Validate the migration by confirming each component (database, API, front end, page generator) is present and functional as described, rather than by a numeric metric.

## Evaluation signals

- A PostgreSQL relational database backend is populated and the REST-like API handles access to it, serving annotation metadata for repository rows
- The AngularJS single-page UI supports filtering and sorting of repository rows by annotation metadata (e.g. compound names, taxonomic identifiers, biosynthetic classes)
- Boolean queries such as 'find all complete RiPP BGCs from the genus Streptomyces' return correct result sets
- Individual BGC pages are generated by the customised antiSMASH 5 module from a JSON annotation file that passes JSON schema validation
- Success is judged by components matching the article's described architecture (database, API, front end, BGC page generator), not by a numeric metric

## Limitations

- The mibig-api README provides minimal setup documentation — it only states the Go 1.11.x requirement for dependency handling and the Apache License 2.0, and contains no changelog
- Migration success is validated qualitatively against the article's described component architecture rather than a numeric threshold
- Downstream BGC page rendering depends on the JSON annotation file conforming to the MIBiG JSON schema; non-conforming files cannot be sideloaded
