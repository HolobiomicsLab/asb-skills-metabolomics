# compound-activity-mapping

## Summary

NP Analyst's Compound Activity Mapping workflow predicts compound bioactivity profiles directly from primary screening results by integrating processed MS feature lists (mzML, MZmine 2, or GNPS outputs) with normalized bioassay data, scoring each MS feature with Activity and Cluster Scores to prioritize metabolites for isolation.

## When to use

Use when you have an extract/prefraction library with MS feature data (mzML, MZmine 2 peak lists, or GNPS .graphml networks) and bioassay screening data, and need to identify which MS features or metabolites drive the observed bioactivity.

## When NOT to use

- Your data are already scored feature-activity associations (e.g., purified compound BioMAP profiles) rather than raw extract-level MS feature and bioassay matrices — mapping would add no information
- Your bioassay columns are not normalized to the same scale — run normalization per the npanalyst documentation first, or Activity Scores will be invalid
- You need spectral library dereplication of a known compound from MS/MS spectra alone — NP Analyst scores features from bioactivity profiles, not from spectral matching

## Inputs

- MS feature table: feature x sample matrix with retention time and m/z columns, from MZmine 2 peak lists or GNPS network .graphml files (or mzML-derivable data from major instrument manufacturers)
- Normalized bioassay CSV: samples x bioassay columns, with all assay columns normalized to the same scale
- Optional: replicated MS CSVs (output of the replicate comparison task) for basketing
- Optional: config.json generated by 'npanalyst get_config' for parameter tuning

## Outputs

- Per-feature Activity Score and Cluster Score columns appended to the feature table (e.g., scored_features.csv)
- Bioactive communities of prefractions linked by shared bioactive MS features
- Visualization outputs: scatter plot, network, and community views (retention time vs m/z ratio) exportable to third-party tools such as Tableau

## How to apply

Import processed MS data (e.g., a GNPS feature network .graphml) and bioassay CSVs whose columns are normalized to the same scale using the npanalyst CLI with the appropriate type flag; optionally run replicate comparison first (default requirement: signals present in n - 1 samples for n replicates) and apply a signal intensity cutoff informed by the assay's limit of detection to avoid uninformative low-abundance features. Run the R-tree based basketing routine, which builds connected component graphs of m/z features with overlapping error ranges and combines (averages) replicated features, then run compound activity mapping with the default configuration (inspect/tune via 'npanalyst get_config' to generate config.json). For each MS feature, the Activity Score is computed as the sum, over all bioassay columns, of the mean of the squares of the bioactivity values for each extract containing that feature; the Cluster Score is the mean Pearson similarity of the feature's binary biological fingerprint to its co-active partners. Prioritize features by using the scatter plot, network, and community views interdependently, and remember that all MS features from a single bioactive molecule (adducts, fragments, multiply-charged species) will have similar Activity and Cluster Scores but different m/z ratios, so look for retention-time stripes of co-active features.

```
docker run -it -v PATH/TO/DATA:/data npanalyst-cli import -i /data/GNPS.graphml -o /data -t GNPS -v
```

## Evaluation signals

- Activity Score for each feature equals the sum of squared normalized bioactivity values across all samples/extracts containing that feature — recompute independently and compare
- Cluster Score equals the mean Pearson correlation of each feature's binary biological fingerprint with those of its co-active partners
- Basketed features are combined (averaged) from m/z features with overlapping error ranges in all dimensions via the R-tree connected components
- Example invariant from the amychelin C validation: the reproduced community-16 must contain 5 prefractions connected by 3 MS features with [M+H]+ m/z 753.3243 and fragment 623.2319 present
- Replicated-feature check: for n replicates, default basketing requirement is presence in n - 1 samples

## Limitations

- Running NP Analyst without any data preprocessing typically increases the number of candidate bioactive MS features because raw mass lists include junk features
- NP Analyst scores each MS feature independently, so adducts, fragments, and multiply-charged forms of one molecule all score similarly — manual interpretation of feature stripes is required
- Replicate comparison is only possible where replicate data exist; low minimum signal cutoffs can dramatically increase network complexity without adding biologically informative MS features
- Some communities lack clear individual bioactive MS features and require retention-time stripe prioritization instead
