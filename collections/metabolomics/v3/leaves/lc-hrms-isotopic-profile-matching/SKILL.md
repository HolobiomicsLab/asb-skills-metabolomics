# lc-hrms-isotopic-profile-matching

## Summary

Assigns molecular formulas to LC/HRMS peaks using only MS1 data by matching observed isotopic profiles against theoretical profiles from an IPDB, via the IDSL.UFA R package's equation (6) composite scoring and ranking.

## When to use

Use when per-sample IDSL.IPA peak lists (m/z-RT peaks with nIsoPair, peak area) are available and molecular formulas must be assigned from MS1 isotopic patterns without tandem MS spectra.

## When NOT to use

- Only MS2-dependent structural annotation is needed and no MS1 isotopic profile matching is requested — IDSL.CSA/MS2 tools are more appropriate
- No prior formula/IPDB source exists and chemical space must be exhaustively enumerated — use IDSL.UFAx instead of UFA
- Peak lists come from other peak pickers (MZmine 2, xcms, MS-DIAL) in formats not generated by the IDSL.IPA workflow

## Inputs

- Raw LC/HRMS data (mzXML, mzML, netCDF) preprocessed by IDSL.IPA
- IDSL.IPA per-sample peaklist csv files (chromatographic m/z-RT peak properties)
- IDSL.IPA peak_alignment directory output
- IPDB .Rdata theoretical isotopic profile database (e.g. RefMetDB positive/negative mode)
- UFA parameter spreadsheet (UFA_parameters.xlsx, 30 parameters in 4 sections)

## Outputs

- Per-sample formula annotation csv with rank, score, molecular formula, and IPA-derived peak properties (e.g. nIsoPair, RCS, peak area) for each surviving candidate
- Aligned annotated peak table summarizing formula annotations by detection frequency and median ranks across samples
- Batch untargeted isotopic profile match figures

## How to apply

Process raw mzXML/mzML/netCDF data with the IDSL.IPA workflow to generate per-sample peaklists and an aligned peak table, then configure a UFA parameter spreadsheet (PARAM0004 = IPDB .Rdata address, PARAM0011 = peaklists dir, PARAM0012 = peak_alignment dir) and run UFA_workflow. For each peak in an individual sample's peak list, candidate formulas from the IPDB that pass the PCS, NEME (normalized Euclidean mass error), NDCS, and RCS screening filters have their theoretical isotopic profiles computed and compared to the observed MS1 profile. Surviving candidates receive a composite score via equation (6) combining Profile cosine similarity (PCS), retention-of-candidates score (RCS), normalized Euclidean mass error (NEME), and the experimental-to-theoretical R13C ratio, with a default parameter weight of 1 for each component. Candidates are ranked in descending score order and written to an annotation csv containing rank, score, formula, and IPA-derived peak properties. For reporting across samples, apply the paper's thresholds: median rank ≤ 5 for annotated aligned peaks, and top rank ≤ 30 with number of hits ≤ 30 for unique molecular formula reporting.

## Related tools

- **IDSL.UFA** (Computes theoretical isotropic profiles for IPDB formulas, matches them against experimental MS1 profiles, scores candidates via equation (6), and ranks annotations) — https://cran.r-project.org/package=IDSL.UFA
- **IDSL.IPA** (Generates the per-sample peaklists and aligned peak tables (peaklists and peak_alignment directories) that are the required input for formula annotation) — github.com/idslme/IDSL.IPA
- **R** (Execution environment for the IDSL.UFA and IDSL.IPA packages)

## Examples

```
library(IDSL.UFA); UFA_workflow("/path/to/UFA_parameters.xlsx")
```

## Evaluation signals

- Top-ranked candidate formulas satisfy the paper's ranking criterion: median rank ≤ 5 for aligned annotations; top rank ≤ 30 and number of hits ≤ 30 for unique molecular formulas
- Every surviving candidate row in the output csv has non-empty rank, score, and peak-property (nIsoPair, RCS, peak area) columns
- Equation (6) score components (PCS, RCS, NEME, R13C ratio) each carry their parameter weight, with default value 1 when defaults are used
- Reference validation reported 54.31–85.51% of true positive annotations as the top hit and 90.58–100% within the top five hits

## Limitations

- Database-dependent approach risks missing exposure compounds poorly represented in biochemical databases, bioaccumulative compounds lacking transformation products, and compounds filtered by detection frequency/intensity thresholds
- The IDSL.UFA pipeline requires MS1-only data processed through IDSL.IPA; it cannot operate directly on raw vendor files or third-party peak tables
- Article/README context does not state IDSL.UFA or IDSL.IPA version numbers, complicating exact reproducibility
