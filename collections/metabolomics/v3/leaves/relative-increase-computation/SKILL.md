# relative-increase-computation

## Summary

Computes the relative percentage change in LC-IM-MS MS1 lipid features consistently detected across 3 replicates between original and PNNL PreProcessor-smoothed data, by intersecting replicate-specific feature sets. It reproduces the paper's 70.7% increase for the NIST SRM 1950 human plasma lipid extract (MassIVE MSV000087295).

## When to use

Use when replicate-level LC-IM-MS MS1 feature lists exist for two conditions (original vs PreProcessor-smoothed) and the goal is to quantify a relative percentage gain in features consistently detected across 3 replicates, e.g. the 70.7% smoothing increase for NIST SRM 1950 plasma.

## When NOT to use

- Inputs are raw LC-IM-MS files (e.g., Agilent ".d" MS-files or UIMF) rather than per-replicate feature lists — preprocessing and feature finding (PreProcessor, Lipid Annotator) must run first before counts exist to compare
- The target metric is the 19.4% increase in lipid annotations (an annotation-level metric from Lipid Annotator) or saturation-repair peak-height gains, not replicate-consistent MS1 feature counts
- Fewer than 3 replicates are available, so no replicate-consistent feature intersection can be defined

## Inputs

- Original-data detected-feature lists (feature tables) for 3 replicates of the NIST SRM 1950 human plasma lipid extract, downloaded from MassIVE ftp://massive.ucsd.edu/MSV000087295
- Preprocessed-data detected-feature lists for the same 3 replicates, generated by PNNL PreProcessor smoothing (demultiplexing with 75% pulses, 3-point LC / 7-point IM smoothing, 50-count intensity threshold, 1 adjacent point spike removal)

## Outputs

- Per-condition counts of LC-IM-MS lipid features consistently detected across all 3 replicates (set intersection of replicate feature sets for original and preprocessed conditions)
- Relative percentage increase written to replicate_feature_counts.csv (expected value approximately 70-71%, i.e. 70.7% per the paper)

## How to apply

Retrieve the deposited original-data and preprocessed-data detected-feature lists for the 3 replicates of the NIST SRM 1950 human plasma lipid extract from MassIVE (ftp://massive.ucsd.edu/MSV000087295); the preprocessed files were produced with demultiplexing at 75% pulses, multidimensional smoothing (3 points in LC, 7 points in IM), a 50-count intensity threshold, and 1 adjacent point spike removal. Load each replicate's feature list into pandas, treating a feature as an ion with one or multiple isotopic peaks detected in the MS1 data (collapse isotopic peaks so each ion counts once). For each condition, intersect the three replicate-specific feature sets so only features consistently detected across all 3 replicates are retained, and record count_original and count_preprocessed. Compute the relative increase as (count_preprocessed - count_original) / count_original * 100 and write the per-condition counts plus the percentage to replicate_feature_counts.csv. Validation: the recomputed percentage should fall within approximately 70-71%, matching the paper's reported 70.7%; gains concentrate among low-abundance ions because multidimensional smoothing improves peak shapes of poorly defined low-abundance signals.

## Related tools

- **PNNL PreProcessor** (Produces the preprocessed replicate feature lists (multidimensional smoothing, demultiplexing with 75% pulses) that are intersected against original-data lists to compute the relative increase) — https://omics.pnl.gov/software/pnnl-preprocessor

## Evaluation signals

- Recomputed relative increase falls within approximately 70-71%, matching the paper's reported 70.7% for smoothed vs original data
- Per-condition counts equal the cardinality of the intersection of the 3 replicate feature sets (features detected in all 3 replicates), not the union or pairwise counts
- The preprocessed count must exceed the original count (positive percentage), with the greatest gains among low-abundance ions, consistent with smoothing improving poorly defined low-abundance peak shapes
- Each ion is counted once regardless of isotopic peak multiplicity, per the paper's definition of a feature as an ion with one or multiple isotopic peaks detected in the MS1 data
- replicate_feature_counts.csv contains both per-condition counts and the computed percentage so the arithmetic is auditable

## Limitations

- The 70.7% result is specific to the NIST SRM 1950 plasma lipid extract analyzed by LC-DT IM-MS in triplicate with this smoothing configuration; other datasets or IM-MS instrumentation require revalidation and may need conversion to UIMF as an intermediate step
- Both conditions must come from identical downstream feature finding for the comparison to be fair; the paper used Lipid Annotator on Agilent ".d" MS-files
- No PreProcessor version is specified in the article and no quantitative performance metrics appear in the discussion, so exact reproduction depends on the deposited MassIVE files (MSV000087295)
