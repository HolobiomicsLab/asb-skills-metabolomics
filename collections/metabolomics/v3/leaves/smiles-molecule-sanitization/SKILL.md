# smiles-molecule-sanitization

## Summary

Parse and canonicalize SMILES strings with RDKit so molecules are sanitized and substructure-searchable, enabling scaffold extraction and HasSubstructMatch checks on Spec2Mol recommendations.

## When to use

Use when raw SMILES strings (e.g., Spec2Mol recommended or ground-truth structures) must be converted into RDKit Mol objects before Murcko scaffold extraction or functional-group SMARTS matching.

## When NOT to use

- Input is already a parsed and sanitized RDKit Mol object rather than a raw SMILES string
- The goal is spectra embedding generation or decoder training rather than post-decoding chemical comparison of structures

## Inputs

- Recommended SMILES strings from the Spec2Mol decoder output
- Ground-truth test SMILES strings for the same MS/MS spectra

## Outputs

- Canonicalized, sanitized RDKit Mol objects for each recommended and ground-truth SMILES
- Substructure-searchable molecule objects ready for MurckoScaffold extraction and HasSubstructMatch queries

## How to apply

Take the SMILES strings produced by the decoder (recommended structures) and the corresponding ground-truth test structures, and parse each with RDKit to produce a sanitized Mol object; sanitization is required because subsequent MurckoScaffold extraction and HasSubstructMatch queries fail on unsanitized or invalid molecules. Canonicalize the parsed structures so that identical chemistry written as different SMILES strings maps to a single representation before comparison. Once sanitized, apply RDKit's MurckoScaffold module to derive the Bemis-Murcko scaffold of each ground-truth molecule, then run SMARTS-based HasSubstructMatch queries against the recommended SMILES to test scaffold presence and predefined functional groups. The output feeds directly into tabulation of substructure-recovery rates per test compound, which validates the paper's claim that Spec2Mol identifies key molecular substructures from MS/MS spectra.

## Related tools

- **RDKit** (Parses, sanitizes, and canonicalizes the SMILES strings; also provides the MurckoScaffold and HasSubstructMatch functionality used downstream) — https://www.rdkit.org/
- **PyTorch** (Generates the recommended SMILES strings that are the input to sanitization (decoder output from spectra embeddings)) — https://github.com/KavrakiLab/Spec2Mol

## Examples

```
from rdkit import Chem; mols = [Chem.MolFromSmiles(s) for s in smiles_list]
```

## Evaluation signals

- Every SMILES string parses without RDKit throwing a MolSanitizeException; molecules are non-null after Chem.MolFromSmiles
- Canonical SMILES generated by MolToSmiles(Canonicalize) are stable across repeated runs on the same input
- Mol objects support HasSubstructMatch and MurckoScaffoldSmiles calls without re-sanitization errors
- Sanitized molecule count equals the number of input SMILES strings (no silently dropped records)
- Downstream scaffold/functional-group recovery fractions are computable and consistent with the paper's substructure-recovery claim

## Limitations

- RDKit sanitization may fail on invalid or non-standard SMILES produced by the decoder, silently excluding those structures from substructure analysis
- The four input MS/MS spectra files (e.g., [M+H]+ at 35% and 130% NCE) and the NIST 2020 trained encoder are context for generating recommendations, not for the sanitization step itself
- Scaffold and SMARTS matches depend on correct predefined patterns; errors in the functional-group list propagate into recovery-rate statistics
