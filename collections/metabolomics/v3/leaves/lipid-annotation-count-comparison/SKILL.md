# lipid-annotation-count-comparison

## Summary

A method for recomputing the change in lipid annotation yield attributable to PNNL PreProcessor preprocessing by counting lipid annotations present in at least 2 of 3 replicates, as generated by Lipid Annotator from Agilent .d LC-DT IM-MS files, and comparing original versus preprocessed annotation totals.

## When to use

Use when evaluating whether PNNL PreProcessor preprocessing improves lipid annotation yield in a replicate LC-DT IM-MS lipidomics workflow, or when reproducing a reported annotation-count improvement between two processing conditions on the same deposited MSV000087295 lists.

## When NOT to use

- When the input is already an aggregated feature table without replicate-level annotation lists — the consensus rule requires per-file annotation lists to recompute the ≥2-replicate counts
- When the comparison basis differs from MS1-level lipid annotations in Agilent .d files processed by Lipid Annotator (e.g., proteomics feature counts or MS2-level identifications) — the counting rule and tool consensus logic would not apply

## Inputs

- Deposited lipid annotation lists for 3 original Agilent .d LC-DT IM-MS lipid files (MassIVE MSV000087295)
- Deposited lipid annotation lists for 3 PreProcessor-processed Agilent .d LC-DT IM-MS lipid files (MassIVE MSV000087295)

## Outputs

- Per-group lipid annotation counts (original vs preprocessed) for features in ≥2 replicates
- Recomputed percentage increase in total lipid annotations
- Comparison table written to lipid_annotation_comparison.csv

## How to apply

Retrieve the deposited detected-feature and lipid-annotation lists for the three original and three PreProcessor-processed Agilent .d MS-files from the MassIVE accession MSV000087295. Following the Lipid Annotator consensus rule that an MS1-level feature must be present in at least half of the analyzed MS-files, count lipid annotations supported in at least 2 of 3 replicates within each group (original vs preprocessed). Compute the percentage increase in total annotations between the two groups on the same counting basis. The recomputed increase should match the published 19.4% increase for features found in at least 2 replicates. Write per-group counts and the percent increase to a comparison CSV for downstream validation.

## Related tools

- **Lipid Annotator** (Feature-finding and lipid annotation software that generated the deposited annotation lists from Agilent .d MS-files; its consensus rule (feature in at least half of analyzed MS-files) defines the counting basis)
- **PNNL PreProcessor** (Tool whose preprocessing output is the 'preprocessed' group being compared; it produced the MS-files yielding the 19.4% annotation increase) — https://omics.pnl.gov/software/pnnl-preprocessor
- **UIMF-Viewer** (Associated PNNL tool from the same lab ecosystem for working with UIMF-format intermediate files generated during PreProcessor processing) — https://github.com/PNNL-Comp-Mass-Spec/UIMF-Viewer

## Examples

```
python compare_lipid_annotations.py --original msv000087295/original/ --preprocessed msv000087295/preprocessed/ --min-replicates 2 --out lipid_annotation_comparison.csv
```

## Evaluation signals

- Recomputed percentage increase falls within the 19–20% range reported in the paper
- Annotation counts match the deposited lists in MassIVE MSV000087295 for both original and preprocessed groups
- Consensus counts are based on features present in at least 2 out of 3 replicates in each group
- The output CSV contains exactly two groups (original vs preprocessed) with per-group annotation totals and a percent-increase value

## Limitations

- Comparisons are only meaningful when original and preprocessed files are analyzed with the same annotator (Lipid Annotator) and identical consensus rule; mixing counting bases invalidates the percent increase
- The 19.4% result is specific to this human plasma lipid extract triplicate LC-DT IM-MS experiment; other sample types or acquisition modes may differ
- The individual-file analysis reported a different magnitude (average 41% ± 7% increase), so the group-level and per-file metrics must not be conflated
