# false-positive-rate-quantification

## Summary

Quantifies the false positive proportion of nontargeted LC-MS peak lists generated by MZmine 2 under different extraction stringency (More/Less Restrictive) and measures how machine learning filters (image-based deep neural network, peak group parameter logistic regression) remove false peaks while retaining true positives.

## When to use

Use when evaluating peak-calling quality on nontargeted LC-MS metabolomics peak lists — specifically when you need the fraction of false positive peaks before/after filtering and true positive retention under 'More Restrictive' vs 'Less Restrictive' MZmine 2 settings.

## When NOT to use

- The input is already a curated, manually validated feature table with no false-peak population to quantify
- The peak list was produced by software other than MZmine 2 peak extraction (e.g., centWave or local minimum search alone), where the paper's More/Less Restrictive setting comparison does not directly apply
- You need to train a new classification model from scratch rather than quantify filter performance of the published models

## Inputs

- Raw LC-MS metabolomics datasets (e.g., Cohort 2 human plasma, N=526, from https://doi.org/doi:10.25345/C5FD2F)
- Non-filtered peak lists generated in MZmine 2.14 with 'Less Restrictive' peak extraction parameters
- Manually reviewed true/false peak examples (ground truth labels for ROC/threshold evaluation)

## Outputs

- Filtered peak list (CSV) with true-peak probability scores per peak group
- Filter performance summary (CSV): false positive proportion before/after, fraction of false peaks removed, true positive retention
- ROC curve data with sensitivity/specificity at each score threshold cutoff

## How to apply

Download the raw Cohort 2 LC-MS datasets from https://doi.org/doi:10.25345/C5FD2F and extract peaks in MZmine 2 (v2.14) with 'Less Restrictive' parameters to generate a non-filtered peak list (the paper reports ~75% false positives under these settings vs ~50/50 true:false and 11,026 features under More Restrictive). Score each peak group with the image-based deep neural network (EDML_deep_learning2.py), which converts stacked peak plots from the 63 most-intense samples into raster images and assigns a true-peak probability; apply the optimum operating point threshold of 0.4725. Independently classify the same peak groups with the peak group parameter multiple logistic regression model built on the 15 forward-selected peak group parameters (custom R scripts). Then compare filtered vs unfiltered lists to compute false positive proportion before/after, fraction of false peaks removed (reported ~90% for the neural network; the parameter model retained 80% of true peaks while removing 66% of false peaks), and true positive retention. Rationale: quantify filter performance against ground-truth manually reviewed examples (true/false peaks) so that sensitivity and specificity at each threshold cutoff can be assessed via ROC curves.

## Related tools

## Examples

```
python EDML_deep_learning2.py  # after downloading the Cohort 2 datasets from https://doi.org/doi:10.25345/C5FD2F
```

## Evaluation signals

- Reproduced false positive proportion under Less Restrictive settings should be ~75%
- ML filtering should remove up to ~90% of false peaks while minimally reducing true positives (DNN captured 98% of true positive peaks under More Restrictive settings)
- The peak group parameter model should retain 80% of true peaks while removing 66% of false peaks
- Score threshold of 0.4725 should correspond to a true positive rate of ~0.945 and false positive rate of ~0.04
- DNN performance should be consistent with reported AUC of 0.992 (training) and 0.988 (test)

## Limitations

- The 90% false peak removal figure was reported on the Less Restrictive Cohort 2 data; under More Restrictive settings (11,026 features, ~50/50 true:false) the DNN reduced false peak detection by only more than 50%
- Ground truth relies on manually reviewed peak examples (1304 training, 740 calibration, 726 test), so labels are reviewer-dependent
- No specific software/library used to build the deep neural network is named, and no code/model hosting repository beyond the manuscript repo is referenced
- Random Forest trained on the original 59 peak group parameters showed similar performance but is a separate model from the 15-parameter logistic regression
