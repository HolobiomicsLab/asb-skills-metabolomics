# molecular-formula-stratified-grouping

## Summary

Stratifies ESP training spectra by their associated molecular formulae so that each formula group becomes the molecular candidate set used to train the ranking-based ensemble classifier (fENS), avoiding retrieval of candidates from external databases.

## When to use

Use when training ESP's ensemble classifier on spectra for which ground-truth molecular formulae are known, and you need per-molecule candidate groups drawn from the training data itself (e.g. NPLIB1/NIST-derived spectra in torch_trvate_10bin.pkl).

## When NOT to use

- When the evaluation target is test candidate sets from an external database (e.g. PubChem candidate files generated by data_tecand.py) — those groups come from data_tecand.py, not from formula-stratified training data
- When training spectra lack associated molecular formulae/InChIKeys (mol_dict.pkl mappings), since groups cannot be formed
- When training new MLP or GNN base models — stratification is only needed at the ESP ensemble-training stage (ens_train_canopus.py)

## Inputs

- Preprocessed NPLIB1 training/validation/test spectra in torch_trvate_<N>bin.pkl (output of data_trvate.py at the chosen resolution, e.g. 1000 bins)
- Molecular formula (or InChIKeys resolvable via mol_dict.pkl rdkit mol objects) for each training spectrum
- Pretrained base model predictions/checkpoints: best_model_mlp_can.pt and best_model_gnn_can.pt

## Outputs

- Formula-stratified candidate sets (one group per molecular formula)
- Per-group base-model average ranks, derived dMLP/dGNN binary labels, and SMAPE-derived importance weights
- Trained ensemble classifier parameters saved as ESP_can.pt (mode 'canopus')

## How to apply

Load the preprocessed training spectra from the data_trvate.py output file (torch_trvate_ + str(int(1000/resolution)) + bin.pkl, e.g. torch_trvate_10bin.pkl for 1000-bin resolution) and group spectra by their associated molecular formulae. Each formula group then serves as the molecular candidate set during ensemble classifier training: for every group, compute each base model's (MLP from best_model_mlp_can.pt and GNN from best_model_gnn_can.pt) average rank over the group's candidates, derive binary dMLP/dGNN labels by comparing those per-group ranks, and compute SMAPE between the two base models' spectral predictions within the group to derive importance weights. Train fENS with PyTorch binary cross-entropy on these labels/weights and save the result as ESP_can.pt. The rationale is that molecules sharing a formula form a chemically well-defined candidate set, so candidates come from the training data rather than external retrieval from databases like PubChem.

## Examples

```
python ens_train_canopus.py --cuda 0 --disable_two_step_pred --disable_fingerprint --disable_mt_fingerprint --disable_mt_ontology --correlation_mat_rank 100 --full_dataset --mode 'canopus'
```

## Evaluation signals

- Each training spectrum is assigned to exactly one formula group; group membership is fully determined by the molecular formula associated with each spectrum (no leakage across strata)
- For every formula group, both base models (MLP and GNN) yield a computable average rank over that group's candidates, and dMLP/dGNN labels are consistent with the rank comparison
- Running ens_train_canopus.py in 'canopus' mode completes 819/819 iterations (~15s on CPU in the README demo) and saves the ensemble as ESP_can.pt
- Weighted-average MLP+GNN combination from the trained fENS evaluated on the NPLIB1 test set should reproduce the reported ESP ranking behavior: Average rank 279.557, Rank@1 = 0.187, Rank@20 = 0.592

## Limitations

- Annotation performance is dependent on the training dataset, the number of molecules in the candidate set, and candidate similarity to the target molecule, so formula-stratified groups of very different sizes may behave differently
- NIST-20 data cannot be redistributed under NIST license; published formula-stratified training is reproducible only for the NPLIB1 dataset
- Two large inputs (mol_dict.pkl and pos_train.csv) must be fetched from Zenodo before grouping, since they are excluded from the git repository
