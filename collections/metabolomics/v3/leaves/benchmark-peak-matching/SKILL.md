# benchmark-peak-matching

## Summary

Matches peaks and features from a generated benchmark dataset against non-targeted pre-processing (NPP) output tables from tools like XCMS or MZmine 2, providing the non-equivalent join required to compute peak-picking and alignment performance metrics.

## When to use

Use when you have a validated benchmark (e.g. Benchmark.csv from MTBLS267) plus unaligned and aligned NPP output csv files and need to join them to quantify split peaks, missed peaks, degenerated isotopologue ratios, or alignment errors.

## When NOT to use

- You only have a raw feature table without a benchmark derived from user-supplied target molecules with known retention boundaries and molecular formulas — matching requires the validated benchmark as reference
- The NPP outputs come from an unvalidated source; run check_nonTargeted_input first and do not match malformed or schema-incompatible csv files
- Data are not centroided LC-HRMS mzML-derived outputs — benchmark generation and matching assume centroided profile data

## Inputs

- Benchmark.csv — validated benchmark table of isotopologue peaks extracted from mzML files (e.g. MTBLS267 _POS.mzML files)
- Unaligned NPP output csv (e.g. XCMS_unaligned_run2.csv, XCMS_unaligned_run3.csv, or 30 MZmine 2 unaligned csv files)
- Aligned NPP output csv (e.g. XCMS_aligned_run2.csv, XCMS_aligned_run3.csv, MZmine_aligned.csv)
- NPP options table generated by generate_options for the chosen pre-processing tool

## Outputs

- Matched benchmark-to-NPP peak and feature tables from match_peaks_to_benchmark and match_features_to_benchmark
- Peak-picking metrics (proportion of split peaks, missed peaks, false-negative classification)
- Post-alignment detection rate and degenerated isotopologue-ratio (IR) proportion
- Alignment error counts/rate from assess_alignment
- Diagnostic plots: sunburst plots of found/not-found peaks (plot_sunburst_peaks, plot_sunburst_alignment) and abundance-quality line plot
- Exported metric tables such as xcms_run2_assessment.csv or mzmine2_npp_assessment_metrics.csv

## How to apply

Load the prepared Benchmark.csv and import the NPP outputs with tool-specific importers — import_ungrouped_xcms/import_grouped_xcms for XCMS runs or import_ungrouped_mzmine/import_grouped_mzmine for MZmine 2 — validating each with check_nonTargeted_input and generating the options table via generate_options. Then match benchmark peaks to NPP peaks with match_peaks_to_benchmark, benchmark features to NPP features with match_features_to_benchmark, link NPP peaks to features with match_NPPpeaks_to_NPPfeatures, and quantify alignment quality with assess_alignment. Matching is non-equivalent: each benchmark peak is compared against NPP peaks within an m/z precision window (article example: 6 ppm mz precision, 5 ppm mz accuracy) and retention-time boundaries, so split peaks (multiple NPP peaks matched to one benchmark peak), false negatives, and alignment-lost peaks can all be classified. Finally, run derive_performance_metrics (and metrics_per_molecule, check_IR_biases, check_missing_peaks, classify_false_negative) to populate the Peak Picking, Post Alignment, and Alignment boxes. Because mzRAPP bootstraps confidence intervals, expect slight run-to-run variation in the reported percentages.

## Examples

```
library(mzRAPP); npp_opts <- generate_options('XCMS'); xcms_un <- import_ungrouped_xcms('XCMS_unaligned_run2.csv'); xcms_al <- import_grouped_xcms('XCMS_aligned_run2.csv'); check_nonTargeted_input(); bm <- read.csv('Benchmark.csv'); matched <- match_peaks_to_benchmark(bm, xcms_un, xcms_al, npp_opts); derive_performance_metrics(matched, npp_opts)
```

## Evaluation signals

- XCMS run 2 split-peaks percentage falls within the 1–3% range stated in the article (bootstrapped CI)
- XCMS run 3 metrics fall within reported ranges: 93–99% post-alignment detection, 3–20% degenerated isotopologue ratios, 4–10% peaks lost during alignment
- MZmine 2 run 1 post-alignment found-peaks fall within 82–92%, degenerated IRs within 1–9%, alignment errors up to ~7% of divergences
- Both unaligned and aligned inputs pass check_nonTargeted_input before matching is attempted
- Every benchmark peak with a detected main adduct is either matched, classified as split, or classified as a false negative — no unmatched-uncategorized rows remain

## Limitations

- mzRAPP bootstraps confidence intervals, so metric values have an element of randomness and will vary slightly between runs
- Only adducts enabled in the enviPat package and at least two detected isotopologues per adduct enter the benchmark, limiting what can be matched
- Matching quality depends on the mz precision/accuracy parameters (article example: 6 ppm precision, 5 ppm accuracy); too-loose windows inflate split-peak counts
- Reported percentages are ranges, not point values — exact reproduction of a single number is not expected
