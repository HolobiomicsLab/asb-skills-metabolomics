# adduct-and-isotope-expanded-database-querying

## Summary

Expands each database compound into its adduct and isotope-derived m/z variants and searches user peak m/z values against the expanded entries at a user-set ppm error margin, returning matched identities with adduct and dppm columns.

## When to use

Use when you have a positive- or negative-mode m/z peaklist (e.g. MetaboLights MTBLS28-style lung cancer urine data) and need putative MSI level 2 identities including which adduct/isotope explains each m/z.

## When NOT to use

- Input is raw peak data rather than a processed m/z peaklist — MetaboShiny does not accept raw peak data; use XCMS or MSnbase first
- You only need statistical analysis of m/z values without annotation — MetaboShiny annotates only significant hits that result from the analysis, so pre-matching all m/z is optional
- Your compound database has not been built — each database must be built once via MetaDBparse before any m/z search is possible

## Inputs

- m/z peaklist (MetaboAnalyst-like, MetaboShiny-native or MetaboLights format; raw peak data not accepted)
- Locally built compound database (SQLite) generated by MetaDBparse, supporting 35 databases e.g. HMDB
- User-set mass spectrometer error margin in ppm
- Adduct definition and adduct rule tables

## Outputs

- Annotation table with adduct and dppm columns (mz_annotation_matches.csv) containing name, molecular formula, SMILES, database ID, adduct and isotope percentage per hit
- Putative MSI level 2 annotations (putatively annotated compounds)
- Clickable compound info (SMILES, name, formula) copied to clipboard

## How to apply

Build the compound database locally via MetaDBparse, which stores m/z values for common isotopes and adducts (e.g. M + H) of every compound, then compute each query m/z's accepted window with ppm_range at the user-set error margin in ppm. Query the SQLite-backed database for entries inside that window, retrieving name, molecular formula, SMILES and database ID per hit, and collapse hits sharing identical SMILES while keeping compounds with identical formulas but different structures as separate rows. Filter matches to main-peak isotopes first, then sort by ppm error, retaining adduct and isotope-percentage fields, and export to mz_annotation_matches.csv. Correct application is judged by a benchmark pool of 100 m/z values spread over 60–600 m/z: e.g. searching 264 m/z against HMDB must return creatine riboside as an M + H putative hit.

## Related tools

- **MetaboShiny** (Interactive R/Shiny app that computes the ppm window, queries the compound database, filters and sorts matches by isotope status and ppm error, and exports the annotation table) — https://github.com/joannawolthuis/MetaboShiny
- **MetaDBparse** (Companion package that builds the SQLite compound databases, expanding every compound into adduct and isotope m/z variants for over 30 databases) — https://github.com/joannawolthuis/MetaDBparse
- **R** (Language in which MetaboShiny and MetaDBparse are implemented and invoked)

## Examples

```
Rscript -e "MetaboShiny::start_metshi(inBrowser=F)"  # then set ppm error margin, build database via MetaDBparse, upload peaklist and metadata, and run 'Search' on 264 m/z against HMDB
```

## Evaluation signals

- Searching 264 m/z against HMDB returns creatine riboside as a putative hit with M + H adduct assignment
- Exported mz_annotation_matches.csv contains adduct and dppm columns, plus name, molecular formula, SMILES and database ID
- Hits sharing identical SMILES are collapsed into single rows while compounds with identical formulas but different structures/SMILES remain separate rows
- Matches are filtered to main-peak isotopes and sorted by ppm error, retaining isotope-percentage fields
- Benchmark: all 100 m/z values evenly distributed over the 60–600 m/z range return hits within the user-set ppm error margin

## Limitations

- MetaboShiny does not automatically update databases; re-building is required to refresh database versions
- Only 4 m/z values (264, 308, 441, 561) reached MSI level 1 in the demonstrated lung cancer workflow, so most matches remain putative MSI level 2
- Isotope scoring currently supports only the M-score method, with a default intensity imprecision of 2%
- Search over millions of adduct/isotope-expanded m/z values is bounded by the user-set ppm error margin and the quality of the locally built databases
