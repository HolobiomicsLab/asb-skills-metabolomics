# pfam-domain-sequence-encoding

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Encode biosynthetic gene cluster sequences as Pfam protein-domain representations — word2vec-like pfam2vec embeddings for the BiLSTM detector and binary one-hot domain vectors for the random forest product-class/activity classifiers — instead of raw nucleotide or amino-acid sequence.

## When to use

Use when training DeepBGC detection or classification models whose inputs are Pfam domain compositions (Pfam TSV from deepbgc prepare) and the sequence must be transformed into pfam2vec embeddings or a binary one-hot vector before modeling.

## When NOT to use

- Input is raw nucleotide or protein FASTA that has not yet undergone gene prediction and Pfam domain annotation — encode only after domains are assigned
- Input is already an encoded feature table or vectorized domain matrix — re-encoding via prepare/transformers would be redundant
- Analysis requires residue-level sequence detail (e.g. active-site motif validation) that domain-level composition vectors discard

## Inputs

- Annotated sequences in Pfam TSV format produced by deepbgc prepare (columns: protein, pfam domain, position)
- Manually added in_cluster label column (1 inside BGC, 0 outside) and sequence_id grouping column
- Trained pfam2vec.csv embedding vectors (deepbgc release v0.1.0)
- Negative training set GeneSwap_Negatives.pfam.tsv (deepbgc release v0.1.0)

## Outputs

- pfam2vec embedding vectors per Pfam domain for the BiLSTM detector input
- One-hot binary vectors of Pfam domain composition per BGC (sequence_as_vector=true) for random forest classifiers
- Labeled Pfam TSV training sets ready for deepbgc train

## How to apply

Annotate coding genes (e.g. via Prodigal) and their Pfam domains, then run `deepbgc prepare` to produce training examples in Pfam TSV format. Manually add an `in_cluster` column (1 for Pfams inside a BGC, 0 outside) and a `sequence_id` column so each sample's Pfams stay grouped during shuffling. For the BiLSTM detector, feed the ordered domain sequence through Pfam2VecTransformer plus ProteinBorderTransformer, reusing the trained pfam2vec.csv vectors generated by a word2vec-like skip-gram network from a large unlabeled corpus of genomic sequences (available in deepbgc release v0.1.0). For the random forest product-class/activity classifiers, collapse each BGC's Pfam domain composition into a single binary vector with the OneHotEncodingTransformer set to sequence_as_vector=true. The rationale is that domain-composition vectors let the models treat genomes as a language of Pfam words, which underpins DeepBGC's reduced false-positive detection and its product-class AUC of 0.80 versus the antiSMASH baseline of 0.78.

## Evaluation signals

- sequence_id column keeps each sample's Pfams grouped through shuffling, so no domain from one BGC leaks into another sample's vector
- in_cluster column is strictly binary, with 1 for Pfams inside annotated BGC regions and 0 outside
- OneHotEncodingTransformer with sequence_as_vector=true yields a fixed-length binary vector per BGC suitable for scikit-learn RandomForestClassifier (n_estimators=100, random_state=0)
- Downstream cross-validation reproduces reported metrics: product-class AUC 0.80 and chem-act AUC 0.61 for the random forest, detection ROC AUC 0.946 for the BiLSTM detector
- Trained detector's validation AUC ROC improves monotonically until early stopping (patience 20, min_delta 0.0001)

## Limitations

- Encoding inherits training-data bias: existing BGC databases are heavily biased towards BGCs from natural product 'workhorses' such as Streptomyces
- pfam2vec annotation of domains of unknown function was left incomplete, beyond the scope of the study
- After detection, the majority of novel BGC classes could not be confidently assigned to a product class
- Recovery of some BGC classes is threshold-dependent
