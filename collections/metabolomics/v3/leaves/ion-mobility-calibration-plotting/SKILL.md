# ion-mobility-calibration-plotting

## Summary

Performs and visualizes ion mobility CCS calibration using mzapy.calibration (TWIMS/SLIM power-function calibration) and mzapy.view plotting utilities, operating on calibrant arrival-time distributions extracted from MZA/HDF5 files.

## When to use

Use when calibrating drift/arrival times to collision cross section (CCS) for TWIMS or SLIM IMS-MS data stored in MZA (HDF5) format, and when a fitted-calibration plot is needed for QC.

## When NOT to use

- The data contain no ion mobility dimension (plain LC-MS in MZA) and only mass calibration is needed — use mzapy.calibration.MassCalibration instead
- Raw files are still in vendor formats (Thermo .raw, mzML, Agilent/Bruker .d) and have not been converted to MZA/HDF5 with the mza converter
- The goal is raw extraction of chromatograms or MS/MS spectra rather than CCS calibration

## Inputs

- MZA/HDF5 file containing IMS-MS1 spectra with IonMobilityTime metadata (arrival time in ms for DT and SLIM; 1/k0 in Vs/cm2 for TimsTOF)
- Calibrant reference table of monoisotopic masses and literature CCS values (e.g., the example calibrant dataset in the mzapy repository)
- Optionally, vendor-embedded calibration coefficients stored in the MZA file as CCScalDT = [Tfix, Beta] (Agilent DT) or CCScalSLIM = [C0, C1, C2, C3] (SLIM)

## Outputs

- Fitted CCS calibration object with power-function parameters (slope/intercept) and fit statistics
- Calibrated CCS values back-calculated for each calibrant ion via transform/calibrated_ccs
- Calibration plot generated by mzapy.view.plot_tw_ccs_calibration

## How to apply

Convert the vendor raw file (Agilent .d, Bruker .d, Thermo .raw, or mzML) to MZA with the mza executable, then load it with mzapy.MZA and use collect_atd_arrays_by_rt_mz to extract calibrant arrival-time distributions and metadata headers. Assemble calibrant reference masses and literature CCS values from the example calibrant dataset in the mzapy repository. Instantiate mzapy.calibration.CCSCalibrationTW (which implements the Nat. Protoc. 2008 dt/CCS corrections and the Anal. Chem. 2016 power-function form; single-field DTIMS follows Anal. Chem. 2017, 89, 9048-9055) and call the inherited _CalibrationBase.fit on the calibrant drift times vs. reference CCS. Back-calculate CCS with transform/calibrated_ccs, record the fitted slope/intercept/power-function parameters and fit statistics, and visualize the result with mzapy.view.plot_tw_ccs_calibration. Validate by comparing fitted parameters and calibrated CCS values against the tolerances asserted in mzapy.test unittest.TestCase subclasses.

- **h5py** (Underlying HDF5 access layer for reading MZA metadata tables and jagged intensity/mzbin arrays during calibrant extraction)

## Examples

```
cal = mzapy.calibration.CCSCalibrationTW(t_d, ccs_ref); cal.fit(); mzapy.view.plot_tw_ccs_calibration(cal)
```

## Evaluation signals

- Fitted calibration parameters must reproduce the expected calibrated CCS values within the tolerances encoded in the mzapy.test unittest.TestCase subclasses
- Back-calculated CCS for each calibrant (via transform/calibrated_ccs) should agree with the literature reference CCS values used in the fit
- The MZA metadata table must supply non-null IonMobilityTime values for every calibrant scan used in the fit
- The plot_tw_ccs_calibration output should show calibrant points and the fitted power-function curve; systematic residuals indicate a wrong calibration form (e.g., applying DTIMS single-field to TWIMS data)

## Limitations

- IonMobilityTime semantics differ by platform: arrival time in milliseconds for DT and SLIM, but 1/k0 in Vs/cm2 for TimsTOF, so calibrations are not interchangeable across instrument types
- The documented CCS calibration covers single-field DTIMS (Anal. Chem. 2017, 89, 9048-9055) and the TWIMS/SLIM power-function form; other mobility separations may not be supported
- MZA files with very many spectra may be partitioned into multiple HDF5 groups (MzaPath column), so calibrant array access must honor the partition index
