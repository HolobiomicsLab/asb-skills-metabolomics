# inchikey-based-structure-matching

## Summary

Evaluates whether a predicted molecular structure matches a reference (suspect) structure by comparing the first 14 characters (skeleton layer) of their InChIKeys, the correctness metric BAM uses to score generated derivatives against anchor–suspect pairs.

## When to use

Use when benchmarking structure prediction or annotation pipelines where candidate and reference structures must be compared exactly at the connectivity level, e.g., scoring BAM derivatives against known suspects.

## When NOT to use

- When stereochemistry or tautomer/protonation state differences are themselves the object of comparison — the truncated 14-character InChIKey intentionally discards those layers.
- When structures lack computable InChIKeys (e.g., RDKit cannot assign 'chemical sense' to a predicted product, leaving the 'smiles' field empty in PROXIMAL2 output).
- For spectral similarity or mass-difference matching — this skill only verifies structural identity, not precursor mass agreement or MS/MS similarity.

## Inputs

- Suspect structure (SMILES/InChI) from the anchor–suspect pair dataset (60,368 pairs from 30,184 structurally unique annotated spectrum pairs)
- Candidate derivative structures generated by BAM (JSON outputs from PROXIMAL2 with 'smiles' and 'mol' fields)
- GNN-SOM ranked candidate list with tie-resolved average ranks

## Outputs

- Per-pair correctness labels (first-14-character InChIKey match true/false)
- Overall correct-structure assignment rate (e.g., 24.2% on the global molecular network benchmark)
- benchmark_results.csv table of per-pair outcomes

## How to apply

For each anchor–suspect pair, compute the InChIKey of the suspect structure and of each candidate derivative generated by BAM (via PROXIMAL2 rule application and GNN-SOM ranking), then mark the pair correct if the first 14 characters of the candidate InChIKey match the suspect's first 14 characters — this compares molecular skeletons while ignoring protonation/stereochemistry layers. Record per-pair outcomes in a benchmark table (e.g., benchmark_results.csv) and compute the fraction of examined pairs with a correct assignment; in the BAM benchmark, 4,171 of 17,271 queries with generated derivatives were correct, a 24.2% recall. Because candidates are ranked by GNN-SOM site-of-metabolism likelihood, resolve rank ties by averaging duplicate ranks before selecting top candidates for matching.

## Related tools

- **BAM** (Generates and ranks candidate derivative structures whose InChIKeys are compared against the suspect structures) — https://github.com/HassounLab/BAM
- **PROXIMAL2** (Produces the candidate derivative structures (SMILES/mol) that are converted to InChIKeys for matching) — https://github.com/HassounLab/PROXIMAL2
- **PubChemPy** (Used (with BioServices) to analyze PROXIMAL2 results and retrieve/standardize structures for identity comparison)

## Examples

```
correct = ik_candidate[:14] == ik_suspect[:14]  # first-14-char InChIKey block comparison per anchor–suspect pair
```

## Evaluation signals

- Reproducing the reported 24.2% correct-structure assignment rate among the 17,271 queries where BAM generated derivatives (4,171 correct matches).
- Every scored pair must have both a suspect InChIKey and at least one candidate InChIKey truncated to exactly 14 characters before comparison.
- Per-pair outcome counts summed over the 60,368 anchor–suspect pairs must be internally consistent in benchmark_results.csv.
- Candidates ranked by GNN-SOM must have ties resolved via averaged ranks before the top candidate is selected for matching.
- Matched InChIKey blocks should correspond to identical molecular skeletons when spot-checked with RDKit canonical SMILES comparison.

## Limitations

- Matching on the first 14 InChIKey characters ignores stereochemistry and protonation layers, so distinct stereoisomers of the same skeleton are scored as correct.
- Correctness is only assessed among queries where BAM generated one or more derivatives (17,271 of the examined cases); the metric is a recall conditional on derivative generation.
- Some PROXIMAL2 predictions yield no SMILES because RDKit does not find chemical sense in the prediction, precluding InChIKey computation for those candidates.
