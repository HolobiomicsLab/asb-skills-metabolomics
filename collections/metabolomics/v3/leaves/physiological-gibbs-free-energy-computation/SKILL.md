# physiological-gibbs-free-energy-computation

## Summary

Computes the physiological Gibbs free energy (ΔG) of each generated reaction using eQuilibrator-api, flagging reactions whose ΔG exceeds 50 kJ/mol as thermodynamically infeasible; un-computable ΔG values are recorded and the corresponding reactions retained.

## When to use

Use when a generated reaction network (e.g. from Pickaxe) must be pruned by thermodynamic feasibility before downstream pathway design or metabolomics annotation, so likely-impossible reactions are excluded on a per-reaction basis.

## When NOT to use

- If the reaction network is already filtered by DeepRFC or another feasibility method and thermodynamic pruning is not required.
- If the input reactions fall outside eQuilibrator's prediction scope so no ΔG can be computed and the filter cannot comment on their feasibility.
- If the reaction set has not been generated by Pickaxe or stored in a MongoDB database the workflow can query.

## Inputs

- Pickaxe-generated reaction set stored in a MongoDB database
- PyMongo connection to the MINE/Pickaxe run database
- physiological Gibbs free energy threshold (50 kJ/mol)
- eQuilibrator-api installation (conda-forge equilibrator-api)

## Outputs

- Per-reaction physiological ΔG values (or a non-computable flag)
- Thermodynamics-filtered reaction network with ΔG > 50 kJ/mol reactions removed
- List of reactions whose ΔG was non-computable and thus retained

## How to apply

Load the generated reaction set from the MongoDB database where Pickaxe run results are stored via PyMongo. For each reaction, compute the physiological Gibbs free energy with eQuilibrator-api, recording reactions for which no ΔG can be computed as non-computable. Apply the thermodynamics filter by removing reactions whose physiological ΔG exceeds 50 kJ/mol, but retain reactions whose ΔG falls outside the scope of eQuilibrator predictions, since the filter cannot comment on their feasibility. Validation: verify the output covers every input reaction and that the ΔG and feasibility fields are present for each row, with removal decisions consistent with the >50 kJ/mol threshold; the paper describes but never evaluates these filters in isolation, so no quantitative accuracy criterion is available.

## Examples

```
conda install -c condaforge equilibrator-api
```

## Evaluation signals

- Every input reaction in the database is accounted for in the output (no silent drops).
- Each output row contains a computed ΔG value or an explicit non-computable flag.
- No retained reaction has a physiological ΔG greater than 50 kJ/mol.
- Reactions outside eQuilibrator's prediction scope are present in the output with a non-computable marker.

## Limitations

- The paper describes but never evaluates the thermodynamics filter in isolation, so no quantitative accuracy criterion is available.
- Reactions for which eQuilibrator returns no ΔG (outside its prediction scope) are retained and cannot be commented on for feasibility.
- Requires a MongoDB installation and PyMongo; results must be stored in a database the workflow can query.
