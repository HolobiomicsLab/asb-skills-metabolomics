# peak-label-filtering-for-classification-rates

## Summary

Excludes peaks labeled 'noise_2' — noise peaks located inside signal windows — from classification-rate computations when evaluating signal/noise classifiers on synthetic mass spectrometry data, so ROC comparisons are not distorted by peaks that neither method can remove.

## When to use

Use when computing true-/false-positive classification rates or ROC curves for signal-vs-noise classification (e.g. LSH vs. intensity thresholding) on labeled synthetic windows that contain a 'noise_2' peak class.

## When NOT to use

- When evaluating on real timsTOF data with vendor-selected DDA peaks rather than synthetic windows — no noise_2 label class exists there and the authors note no gold-standard peak-level annotation was available
- When the downstream method explicitly removes noise peaks inside signal windows (the exclusion is only valid because both compared methods fail to remove noise_2 peaks)

## Inputs

- Labeled synthetic windows from createSynthetics (data/output_create_synthetics folder of the unzipped Zenodo record 5036526 dataset)
- Per-peak classification results from the LSH approach (pyproteolizard-algorithm) at settings (m,n) = (32,16), (64,32), (32,32)
- Per-threshold classification results from the intensity/SNR thresholding baseline

## Outputs

- Noise_2-excluded true-positive and false-positive classification rates per threshold and per intensity panel (I = 500, 250, 125, 64, 32)
- ROC curves for LSH and intensity-thresholding methods, plotted per intensity panel and saved as plots/roc_curve.png

## How to apply

Load the labeled synthetic windows generated by createSynthetics (stored in data/output_create_synthetics of the unzipped Zenodo record 5036526 dataset). For each classifier variant — here the LSH approach from pyproteolizard-algorithm across hash settings such as (m,n) = (32,16), (64,32), (32,32), and the intensity/SNR thresholding baseline swept over thresholds — compute per-threshold true-positive and false-positive rates over all labeled peaks EXCEPT those labeled noise_2. The rationale is stated by the authors: noise peaks inside signal windows are not removed by either the LSH approach or intensity thresholding, so including them in the rate computation would unfairly penalize both methods and confound the ROC comparison. Apply the exclusion identically to both methods before computing and plotting the ROC curves per maximum-intensity panel (I = 500, 250, 125, 64, 32).

## Evaluation signals

- plots/roc_curve.png exists in the plots folder after running the roc scripts
- The LSH ROC curve dominates the intensity-thresholding curve across the intensity panels, consistent with the paper's reported finding
- Identical noise_2 exclusion is applied to both LSH and intensity-thresholding rate computations (symmetric treatment)
- ROC panels correspond one-to-one to the maximum signal-intensity panels I = 500, 250, 125, 64, 32 of Additional file 2

## Limitations

- Peaks labeled noise_2 (noise inside signal windows) are not removed by either method and would otherwise distort the ROC comparison if included
- Synthetic data cannot fully reflect the behavior of real data
- Self-similar chemical noise would still be classified as true signal by the LSH approach even after this filtering
