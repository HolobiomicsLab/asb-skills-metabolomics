# reaction-thermodynamics-filtering

## Summary

Prune generated Pickaxe reaction networks using two filters: a thermodynamics filter that removes reactions with physiological Gibbs free energy greater than 50 kJ/mol (computed via eQuilibrator), and a reaction feasibility filter that removes reactions DeepRFC predicts to be infeasible.

## When to use

Use when a Pickaxe-generated reaction network contains too many chemically implausible reactions and you need to prune them by computed ΔG and DeepRFC feasibility predictions before downstream analysis or storage.

## When NOT to use

- When you need to filter by compound-level properties such as chemical similarity to targets or metabolomics m/z matching — these are separate Pickaxe filters, not thermodynamic or feasibility ones.
- When the network is small enough that manual curation is feasible, or when a strict ΔG cutoff would discard reactions whose ΔG falls outside eQuilibrator's prediction scope (these are intentionally retained by the paper's approach).

## Inputs

- Reaction set generated by Pickaxe and stored in a MongoDB database
- PyMongo connection to the local or remote mongo database
- Installed eQuilibrator-api for Gibbs free energy computation
- Installed DeepRFC for reaction feasibility prediction

## Outputs

- Filtered reaction network with thermodynamically infeasible reactions (physiological ΔG > 50 kJ/mol) removed
- Reactions predicted infeasible by DeepRFC removed
- Per-reaction annotations: physiological ΔG value (or non-computable flag) and feasibility label
- CSV or mongo-stored table of surviving reactions

## How to apply

After a Pickaxe run, load the generated reactions from the MongoDB database where results are stored using PyMongo. For each reaction, compute the physiological Gibbs free energy with eQuilibrator-api; reactions for which no ΔG can be computed (falling outside the scope of eQuilibrator predictions) are recorded as non-computable and retained, since the thermodynamics filter cannot comment on their feasibility. Apply the thermodynamics filter by removing reactions whose physiological ΔG exceeds 50 kJ/mol — the threshold used in the paper's E. coli untargeted metabolomics example. Then score each remaining reaction with DeepRFC (installed from bitbucket.org/kaistsystemsbiology/deeprfc) and remove reactions predicted infeasible. Write the filtered results back (e.g. to a CSV or the mongo database) so each reaction carries its computed ΔG value or non-computable flag and its feasibility label.

## Evaluation signals

- Every removed reaction should have physiological ΔG strictly greater than 50 kJ/mol; verify no reaction below the threshold was dropped.
- Reactions for which eQuilibrator returns no ΔG must be present in the retained set, flagged as non-computable rather than silently removed.
- Reactions removed by the feasibility filter should each carry a DeepRFC infeasible label; surviving reactions should carry feasible labels.
- The output table should have exactly one row per input reaction (from the mongo database) with both ΔG and feasibility fields populated.
- Cross-check that filter decisions are recorded separately for thermodynamics and feasibility so a reaction failing either criterion is traceable.

## Limitations

- The paper describes the filters but never evaluates them in isolation — no quantitative accuracy metric (e.g. ΔG prediction error or feasibility-filter precision) is reported.
- The 50 kJ/mol physiological ΔG cutoff is a single threshold from one example application; other thresholds are not benchmarked.
- Reactions outside the scope of eQuilibrator's ΔG predictions cannot be filtered and are retained regardless of actual thermodynamic feasibility.
- DeepRFC predictions are only as good as its training on KEGG substrate–product pairs; reactions outside that training domain may be mislabeled.
- Runtime can be substantial — the analysis code is provided both for a laptop and a supercomputer, indicating the filters are computationally heavy for large networks.
