# untargeted-metabolomics-raw-data-processing

## Summary

Optimize dataset-specific peak-picking parameters for untargeted metabolomics by running AutoTuner, which performs statistical inference on raw data in a single step to estimate the seven continuous centWave parameters (used by XCMS and MZmine2) plus a key grouping parameter, replacing days-long iterative parameter sweeps.

## When to use

Use when raw untargeted metabolomics files (mzML, mzXML, or CDF from qTOF, orbitrap, or FT-ICR instruments) must be processed into a feature table and no universal parameter set applies, so centWave peak-picking parameters must be estimated from the data itself.

## When NOT to use

- Input is already a processed features table or peak list — AutoTuner performs statistical inference on raw data, not on processed results
- Fewer than 3 samples of raw data are available, since AutoTuner requires at least 3 samples for parameter estimation
- The goal is estimating retention time correction parameters by comparing EIC peaks across samples — AutoTuner's divide-and-conquer approach comes at a loss of cross-sample EIC peak comparison

## Inputs

- Raw untargeted metabolomics data converted from proprietary instrument formats (e.g. .mzML, .mzXML, or .CDF), tested on qTOF, orbitrap, and FT-ICR mass analyzers
- A spreadsheet with at least two columns: one matching raw data sample names and one describing the experimental factor each sample belongs to
- At least 3 raw-data samples (9 recommended for culture datasets, 12 for community datasets)

## Outputs

- Estimates of the seven continuously valued centWave peak-picking parameters required by XCMS and MZmine2, plus a key XCMS grouping parameter
- A features table generated by peak-picking and retention time correction of the raw data using the optimized parameters

## How to apply

Convert raw instrument files to an open format (.mzML, .mzXML, or .CDF) and supply a spreadsheet mapping sample names to experimental factors; AutoTuner requires at least 3 samples and R >= 3.6. Run AutoTuner's sliding-window TIC peak detection followed by its single-step statistical inference to estimate the seven continuously valued centWave parameters for XCMS/MZmine2; the Group difference parameter is estimated via a non-automatable cross-sample comparison during the TIC peak detection step. Use 9 samples for culture datasets and 12 for community datasets — in the Monte Carlo robustness experiment, 9 samples sufficed for most parameters to reach coefficient of variation (CV) < 0.1. Feed the estimated parameters into XCMS or MZmine2 centWave peak-picking to build the feature table, reducing the parameter search from at least 24*58 combinations to 40.

## Evaluation signals

- Coefficient of variation (CV) across replicate Monte Carlo subsample draws should reach <= 0.1 for most parameters when 9 samples are used for estimation
- All seven continuous centWave parameters (plus the grouping parameter) should be returned per run; mzDiff is excluded since AutoTuner does not optimize it
- Runtime should be minutes rather than days — roughly a 100-1000X speed improvement over iterative approaches like IPO
- The resulting feature table can be benchmarked against IPO-optimized or default XCMS/MZmine2 parameters for feature counts and information per feature
- Installability check: the package installs via BiocManager from BioConductor and passes its Travis/Codecov test suite

## Limitations

- Robustness of the Group difference parameter estimate cannot be checked, as it is estimated through a non-automatable cross-sample comparison during the TIC peak detection step
- mzDiff is the one continuous centWave parameter not optimized by AutoTuner (only a sensitivity analysis showed minimal effect on the returned feature table)
- The sliding window analysis requires user input during the first portion of AutoTuner, and AutoTuner is not parallelized
- Requires at least 3 samples and R >= 3.6; the divide-and-conquer speed gain sacrifices cross-sample EIC peak comparison for retention time correction estimation
