# lcms-peak-artifact-classification

## Summary

Classify XCMS-detected LC/MS peaks as artifacts or true peaks using PeakDetective, a semisupervised deep learning pipeline that combines an unsupervised autoencoder smoother with an actively learned classifier, requiring fewer than 100 user-labeled peaks.

## When to use

Use when raw mzML files and an XCMS peak list need peak-level curation — i.e., detected peaks must be scored as artifacts vs. true peaks with minimal manual labeling (e.g., <100 peaks) before downstream statistics.

## When NOT to use

- Input is already a curated or filtered feature table with no raw mzML data — EIC extraction from raw scans is required for the autoencoder representation
- The peak list was not generated by peak detection (e.g., XCMS) — PeakDetective curates detected peaks rather than detecting peaks de novo
- Rapid inference on a new dataset where a trained model exists — load saved weights instead of retraining the smoother and classifier

## Inputs

- Raw LC/MS data files in mzML format
- XCMS-generated peak list CSV with mz and rt columns (e.g., peaks_formatted.csv)
- User labels for a small set of peaks (<100) provided interactively during active learning
- Data parameters: ms1ppm tolerance (25.5 ppm), RT alignment flag

## Outputs

- Per-peak artifact/true-peak classification scores and curated peak list from curatePeaks (peak_curated, peak_scores, peak_intensities)
- TPR and FDR estimates per cutoff from validation peaks
- Score histogram and TPR/FDR cutoff plots
- Saved PeakDetective model weights directory (via integ.save())

## How to apply

Load each mzML file into a PeakDetective.rawData object with ms1ppm = 25.5, read the XCMS peak list as mz/rt pairs, and build the EIC data matrix with makeDataMatrix (resolution = 60 data points/min, window = 1.0 min, align = True for RT alignment). Train the unsupervised smoother (smooth_epochs = 10, batchSizeSmoother = 64, validationSplitSmoother = 0.1) so EICs get a low-dimensional latent representation, then train the classifier with trainClassifierActive using active learning — 10 validation peaks labeled first, then 10 peaks per round (min 200 / max 1000 epochs, classifierBatchSize = 4, randomRestarts = 1) — until 5-10 iterations produce a bimodal score histogram and val_mean_absolute_error drops sharply. Inspect the plotted TPR/FDR curves to set the classification cutoff (e.g., cutoff = 0.8), then apply curatePeaks to score and filter the peak list. Save model weights with integ.save() so the trained classifier can be reloaded and audited.

## Evaluation signals

- After 5-10 active learning rounds, the score distribution across all peaks becomes bimodal and val_mean_absolute_error drops dramatically
- Reported accuracy on training and validation peaks is consistent, and TPR/FDR curves from the ~10 validation peaks support the chosen cutoff (e.g., 0.8)
- PeakDetective trained on ~70 actively selected labels outperforms NeatMS retrained with transfer learning on 70–~400 manually labeled peaks (63.9% at 70 peaks, 69.3% at ~400 on Dataset 1)
- Saved weights directory from integ.save() can be reloaded with integ.load() and reproduces the same peak scores
- Model is trained with fewer than 100 user-labeled peaks in minutes, matching the paper's active-learning claim

## Limitations

- Classification quality depends on interactive user labeling — the active learning loop prompts the user to label validation and training peaks each round
- Cutoff selection is manual: the threshold (e.g., 0.8) is set by inspection of TPR/FDR curves according to user preference for specificity vs. sensitivity
- The smoother requires a large peak corpus to train (min_peaks = 100000 in the README defaults), so very small peak lists may be insufficient
- Accuracy on a specific LC/MS method depends on tailoring to that method/sample type; models trained on one data type may not transfer without retraining
