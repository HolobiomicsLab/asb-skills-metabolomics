# reaction-feasibility-scoring

## Summary

Applies DeepRFC-based reaction feasibility scoring as an on-the-fly filter in Pickaxe/MINE network expansions, pruning generated compounds and compound–peak pairs before metabolomics peak annotation (as demonstrated for the EcoCyc Figure 6 E. coli case).

## When to use

Use when a Pickaxe-generated network expansion (e.g. EcoCyc <600 Da compounds, top 50 JN1224min rules, two generations) yields too many candidate compounds for unannotated metabolomics peaks and you need to prune reactions by enzymatic feasibility with DeepRFC.

## When NOT to use

- The question is purely thermodynamic plausibility (ΔG cutoffs) — use the eQuilibrator thermodynamics filter instead, which removes reactions with physiological Gibbs free energy greater than 50 kJ/mol but retains reactions with no computable Gibbs energy.
- The network has not yet been generated by Pickaxe — feasibility scoring operates on Pickaxe-generated reactions/compounds (e.g. stored in MongoDB), not on raw peak lists or starting databases.
- You only need m/z matching of compounds to peaks (metabolomics filter alone), e.g. when network size is not a limiting factor.

## Inputs

- Pickaxe network expansion stored in MongoDB (compounds and reactions, e.g. two-generation EcoCyc expansion with top 50 JN1224min rules)
- List of unannotated metabolomics peaks with m/z values (e.g. 200 peaks, 150–300 Da, E. coli untargeted dataset) as metabolomics-filter inputs
- DeepRFC feasibility scripts and models (installed per the Bitbucket repository instructions)

## Outputs

- Filtered network of feasible reactions and their associated compounds in MongoDB
- Per-filter-combination annotation counts (figure6_peak_annotations.csv)
- Figure 6 comparison plot of annotated peaks across filter combinations (figure6_annotation_plot.png)

## How to apply

Generate the network first with Pickaxe (via the minedatabase package), expanding compounds under 600 Da from the source database (e.g. EcoCyc) for two generations with the top 50 JN1224min rules (65% MetaCyc mapping), storing generated compounds and reactions in MongoDB. Select the unannotated peaks as metabolomics-filter inputs — in the paper's case, 200 unannotated peaks with m/z values between 150 and 300 Da from an E. coli untargeted metabolomics dataset. Then run the DeepRFC feasibility scoring scripts over the generated network (the paper repo speeds this up with feasibility_first_gen.py and feasibility_second_gen_gen2.py, alongside get_physiological_dgs.py), keeping only feasible reactions and their compounds. Compare against the metabolomics-only filter and the thermodynamics filter (eQuilibrator, removing reactions with physiological Gibbs free energy >50 kJ/mol while retaining reactions with no computable Gibbs energy) to isolate the feasibility filter's effect. Query the Mongo database with PyMongo from ecoli_metabolomics_analysis.ipynb, write per-combination annotation counts to CSV (figure6_peak_annotations.csv), and render the Figure 6 comparison plot. Rationale: feasibility scoring is stricter than the metabolomics or thermodynamics filters, so it dramatically reduces the candidate space while potentially preserving peak-annotation capability.

## Evaluation signals

- Adding the feasibility filter to the metabolomics filter reduces both the number of generated compounds and compound peak pairs by an order of magnitude relative to the metabolomics filter alone.
- Despite the order-of-magnitude reduction, the feasibility-plus-metabolomics combination still matches a similar number of unannotated peaks as the metabolomics filter alone (qualitative match to the paper's Figure 6 finding).
- Per-combination counts (metabolomics-only, thermodynamics+metabolomics, feasibility+metabolomics) are written to figure6_peak_annotations.csv and rendered as figure6_annotation_plot.png from the ecoli_metabolomics_analysis.ipynb notebook.
- DeepRFC must be installed before running the feasibility scripts — the README directs installation via the DeepRFC Bitbucket instructions; a missing installation is a setup failure.
- MongoDB must be reachable (local or remote) and contain the Pickaxe-expanded network before the feasibility scripts and PyMongo analysis can run.

## Limitations

- DeepRFC is an external dependency installed from Bitbucket (not PyPI/conda), adding setup friction and its own environment requirements.
- The feasibility filter is aggressive — it cuts compounds and compound–peak pairs by an order of magnitude — so it can prune candidate annotations that the metabolomics filter alone would retain; validate that peak-annotation counts are not lost.
- By contrast, the thermodynamics filter cannot comment on reactions without a computable Gibbs free energy and leaves them in the network, so filter-combination comparisons conflate different retention policies for unscorable reactions.
- Feasibility computation over large networks is slow; the paper repo notes the analysis can be sped up using feasibility_first_gen.py, feasibility_second_gen_gen2.py, and get_physiological_dgs.py, and repeats the code on a supercomputer.
