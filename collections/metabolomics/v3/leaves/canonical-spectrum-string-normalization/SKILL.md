# canonical-spectrum-string-normalization

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Convert a peak list into the SPLASH canonical single-line spectrum string (ion:intensity pairs space-delimited, m/z scaled by 10^6 as 64-bit integers) so that a deterministic SHA256 hash block can be computed and compared across spectral databases.

## When to use

Use when a mass spectrum needs a database-independent, reproducible identifier (SPLASH) and the input is a peak list such as a MassBank record (e.g. caffeine PR100026) rather than an existing SPLASH string.

## When NOT to use

- The input is already a SPLASH identifier (e.g. splash10-0002-0900000000-b112e4e059e1ecf98c5f) — only the hash block needs matching, not re-normalization.
- The spectrum is raw instrument data (e.g. mzML/mzCloud raw files) with noise peaks and no curated peak list; SPLASH requires a defined ion-intensity list.
- The goal is fuzzy spectral similarity search rather than exact identity matching — the SPLASH hash only flags exact (or near-exact) duplicates, as identical SPLASHes arose only for single-ion spectra of the same mass in the 53.25-million-spectrum test.

## Inputs

- Peak list of m/z / intensity pairs (e.g. from MassBank record PR100026: 138.0641 71.59, 195.0815 261.7)
- Single-line string representation of a mass spectrum ('ion:intensity ion:intensity ...')
- Spectrum type flag (default MS)

## Outputs

- Canonical single-line spectrum string with 64-bit-integer-scaled m/z and normalized intensities
- Input string suitable for the SHA256 hash that yields the SPLASH fourth (hash) block
- Full SPLASH identifier, e.g. splash10-0002-0900000000-b112e4e059e1ecf98c5f

## How to apply

Take the peak list as pairs of m/z and intensity (e.g. caffeine PR100026: 138.0641 71.59 and 195.0815 261.7) and serialize each pair as 'ion:intensity' with pairs separated by spaces, in the single-line spectral representation defined by the SPLASH project ('ion:intensity ion:intensity ...'). Scale each m/z by 10^6 and represent it as a 64-bit integer so that the ion values are integer-stable across platforms and languages (reference implementations exist in Java, C++, Python, C#, R, Ruby and Scala). Normalize intensities as required by the SPLASHer implementation and join ion:intensity pairs into one canonical line; this exact string is the input to the SHA256 hash that produces the 20-character fourth block (e.g. b112e4e059e1ecf98c5f for caffeine). The rationale is that any byte-level difference in the string changes the hash, so the normalization must be deterministic and identical across implementations — the project ships a Java validation tool (-c -s 2 -t ms flags) to compare generated SPLASHes against the reference implementation over test sets like test-set-v1.csv.

## Evaluation signals

- The canonical string for caffeine PR100026 (138.0641:71.59 195.0815:261.7) must yield SHA256-truncated-to-20-chars = b112e4e059e1ecf98c5f.
- The full SPLASH must equal splash10-0002-0900000000-b112e4e059e1ecf98c5f.
- The same spectrum identified as PR100026 (MassBank/MoNA), 5464 (HMDB) and CCMSLIB00000222858 (GNPS) must produce identical SPLASHes after normalization.
- Running the Java validation tool (java -jar validation/target/validation-1.8.jar -c -s 2 -t ms) over test-set-v1.csv should report zero mismatches against the reference implementation.
- Hash collision testing on 53.25 million spectra showed identical SPLASHes only for single-ion spectra of the same mass — any unexpected collision on multi-ion spectra signals a normalization bug.

## Limitations

- Identical SPLASHes can still occur for spectra containing a single ion of the same mass (observed in the 53.25-million-spectrum dataset); theoretical collision probability is ~10-31 for a database of 10^9 spectra.
- Not all spectra in validation sets are annotated with structures, so SPLASH identity does not confirm structural identity.
- The second summary block was chosen from 136 candidate formats and reduces search space by ~94% but does not replace full similarity scoring (only 87% of spectra returned within similarity score 700).
