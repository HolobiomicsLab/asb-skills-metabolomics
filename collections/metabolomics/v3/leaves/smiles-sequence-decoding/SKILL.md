# smiles-sequence-decoding

## Summary

Decode spectra-encoder embeddings into candidate molecular structures by autoregressively generating SMILES token sequences with a pre-trained Spec2Mol decoder, then validating each generated SMILES string chemically with RDKit.

## When to use

Use when you have MS/MS spectra embeddings (e.g. from Spec2Mol's encoder over [M+H]+/[M-H]- at 35%/130% NCE) and need to reconstruct de-novo candidate molecular structures as SMILES strings.

## When NOT to use

- Input is already a set of chemical structures or SMILES strings rather than spectra embeddings — the decoder consumes encoder embeddings, not raw molecules.
- You only have raw mass spectra (m/z, intensity pairs) without first running the encoder to generate embeddings — decoding directly from spectra bypasses the encoder stage the architecture depends on.
- You need spectra-to-spectra or spectrum-to-MGF conversion rather than spectra-to-molecule translation; the decoder's objective is specifically reconstructing SMILES representations of recommended chemical structures.

## Inputs

- MS/MS spectra embeddings generated by the Spec2Mol encoder from four precursor/energy CSV files ([M+H]+ 35% NCE, [M+H]+ 130% NCE, [M-H]- 35% NCE, [M-H]- 130% NCE)
- Pre-trained Spec2Mol decoder model
- Comma-separated spectra CSVs with m/z in the first column and intensity in the second column

## Outputs

- SMILES token sequences representing recommended chemical structures for each input spectra embedding
- RDKit-validated SMILES strings collected in predicted_smiles.csv

## How to apply

Run predict_embs.py over the four input spectra CSV files ([M+H]+ low/high and [M-H]- low/high, comma-separated m/z in column 1 and intensity in column 2) to produce spectra embeddings, since the decoder only operates on embeddings the encoder generates. Initialize the pre-trained Spec2Mol decoder — trained on a massive dataset of chemical structures for translating between different molecular representations — with these embeddings and autoregressively generate SMILES token sequences for each spectra embedding. Parse every generated SMILES string with RDKit to confirm it is chemically valid, discarding or flagging invalid reconstructions. Collect the surviving predicted SMILES sequences and write them to predicted_smiles.csv for downstream similarity scoring (Tanimoto, Dice, MCCS, exact match) against the original structures. Environment setup matters: Python 3.7 conda env with rdkit via conda-forge and pytorch=1.6.0 plus torchvision from the pytorch channel, since the decoder implementation is PyTorch-based.

## Examples

```
conda create -n spec2mol python=3.7 && conda install rdkit pytorch=1.6.0 torchvision -c conda-forge && python predict_embs.py -pos_low_file 'sample_data/[M+H]_low.csv' -pos_high_file 'sample_data/[M+H]_high.csv' -neg_low_file 'sample_data/[M-H]_low.csv' -neg_high_file 'sample_data/[M-H]_high.csv'
```

## Evaluation signals

- Each output row in predicted_smiles.csv contains a syntactically and chemically valid SMILES string that RDKit can parse without error.
- One decoded SMILES sequence is produced for each spectra embedding across all four experimental conditions ([M+H]+ 35%, [M+H]+ 130%, [M-H]- 35%, [M-H]- 130%).
- Downstream similarity metrics (Tanimoto, Dice, MCCS, exact match) computed against the original structures fall within the valid 0–1 range per condition.
- The spec2mol conda environment resolves pytorch=1.6.0 and torchvision from the pytorch channel and rdkit via conda-forge before decoding.
- Generated SMILES strings contain key molecular substructures identifiable from the mass spectrum, consistent with Spec2Mol's reported ability to detect substructures.

## Limitations

- The pre-trained decoder depends on the encoder embedding quality; embeddings trained on the commercial NIST Tandem Mass Spectral Library 2020 may bias decoding toward spectra resembling that library's precursor/energy conditions.
- Only four precursor/energy conditions ([M+H]+ and [M-H]- at 35% and 130% NCE) are supported in the provided sample_data interface; other collision-energy regimes require re-encoding or re-training.
- Decoder output is not guaranteed to be chemically valid — RDKit validation must be treated as a filter step, and invalid SMILES reconstructions are a known failure mode.
