# caret-hyperparameter-tuning

## Summary

Trains and hyperparameter-tunes the peak-reporting random forest model used by automRm's process_batch(), using the caret R package to combine quality scores from qslog.tsv with expert labels in manual_peakcheck.xlsx and serialize the fitted model for later inference.

## When to use

Use when a labeled set of peak quality scores (qslog.tsv) plus an expert annotation file (manual_peakcheck.xlsx with scores 0/1/2) is available and a peak-reporting classification model must be trained, tuned, and serialized in R.

## When NOT to use

- The goal is peak picking itself — the peak-picking ML model must already be trained before process_batch() can produce the qslog.tsv scores that this skill consumes
- No expert labels (manual_peakcheck.xlsx) exist yet, so there is no supervised target (0/1/2) to train the peak-reporting model against
- The task is generic caret modeling on data other than automRm's MRM peak quality scores; this skill is specific to automRm's LC-QQQ-MS peak-reporting workflow

## Inputs

- qslog.tsv containing peak-picking classification scores for every metabolite in every sample (produced by automRm's process_batch())
- manual_peakcheck.xlsx expert training solution with labels 0 (do not report), 1 (exclude from training), or 2 (report) per metabolite-sample pair
- manual_peakcheck_template.xlsx template generated by process_batch() for labeling

## Outputs

- Serialized random forest peak-reporting ML model on disk, for later use by process_batch()
- Training-summary metrics for the 20% validation subset (e.g. F1 score)

## How to apply

First run automRm's process_batch() with the trained peak-picking ML model to generate qslog.tsv, which contains the peak-picking classification scores for every metabolite in every sample, and generate the manual_peakcheck_template.xlsx template. An expert then supplies manual_peakcheck.xlsx with labels 0 (do not report), 1 (exclude from training), or 2 (report) for each metabolite-sample pair. Invoke automRm's train_model() in R — caret is listed among the package's dependencies alongside mzR and openxlsx — and combine the qslog.tsv quality scores with the manual_peakcheck.xlsx labels. Automatically split the data into 80% training and 20% validation subsets, then perform hyperparameter tuning to fit a random forest peak-reporting model via caret. Serialize the trained model to disk for later use by process_batch(), and record training-summary metrics such as the F1 score on the validation subset; on combined training data sets the paper reports peak-reporting performance of F1 > 0.98.

## Related tools

- **caret** (Performs the hyperparameter tuning and training of the random forest peak-reporting ML model inside train_model())
- **automRm** (Provides train_model(), which combines qslog.tsv quality scores with manual_peakcheck.xlsx labels and serializes the trained model for process_batch()) — https://gitlab.gwdg.de/joerg.buescher/automrm
- **openxlsx** (Reads and writes the xlsx-based manual_peakcheck.xlsx labels and template used as the training target)
- **R version 4.0.2** (Runtime environment in which automRm and caret are executed for model training)

## Evaluation signals

- Reported F1 score of the trained peak-reporting model on the 20% validation subset; acceptance is consistent with the paper's F1 > 0.98 for combined models trained on combined data sets
- The training/test split is 80% training / 20% validation and is generated automatically by train_model()
- The serialized model can be loaded and applied by process_batch() in a subsequent batch-preprocessing run
- All metabolite-sample pairs in manual_peakcheck.xlsx with label 0 or 2 are represented in the training data, while label-1 pairs (exclude from training) are dropped
- Training-summary output records validation metrics in addition to the serialized model file

## Limitations

- With insufficient training on relevant raw data, results cannot reach a quality similar to manual peak review — sufficient relevant training data is required
- For optimal performance, automRm requires the use of at least one qualifier in addition to the quantifier in the acquisition method
- Manual peak review is still needed for selected metabolites in special cases such as excessively dirty samples, very-low-input samples, or new LC methods
- The choice of training data set and the applied ML algorithm both affect automRm's ability to correctly report chromatographic peaks
