# tab-delimited-data-import

## Summary

Ingests MS-Dial-derived LC-MS/MS output into margheRita's internal data structure by reading two tab-delimited text files (a feature data file and a sample annotation file) via read_input_file(), producing the mRList object used as main input/output by all margheRita functions.

## When to use

Use when starting a margheRita workflow from MS-Dial-exported feature tables: the inputs are tab-delimited feature data (m/z, retention times, MS/MS spectra, abundances) plus a sample annotation file, and the analysis needs the mRList object.

## When NOT to use

- Input is a single pre-joined matrix or an existing R object (e.g. already-parsed data frame) rather than the two separate MS-Dial tab-delimited text files margheRita expects
- Input is MS-DIAL data exported as Excel spreadsheets — the notame package handles Excel-based MS-DIAL reading, whereas margheRita requires tab-delimited text files
- Data were processed by another pipeline and you need downstream statistics only, without reconstructing margheRita's mRList structure

## Inputs

- Tab-delimited feature data file, usually generated by MS-Dial (feature identifiers, m/z, retention times, MS/MS spectra, abundances)
- Tab-delimited sample annotation file with columns id, injection_order, batch, class, biological_rep, technical_rep
- Optional: Urine dataset feature file from Zenodo 10.5281/zenodo.11243781 and package extdata sample annotation file for testing

## Outputs

- mRList object with exactly five elements: data, metab_ann, sample_ann, QC, QC_ann
- Populated QC and QC_ann elements holding quality-control sample annotation

## How to apply

Call read_input_file() on the two required tab-delimited text files: the feature data file, usually generated by MS-Dial, containing feature identifiers, m/z, retention times, MS/MS spectra and abundances, and a sample annotation file with columns id, injection_order, batch, class, biological_rep and technical_rep. The function assembles these into the mRList object with five elements: data, metab_ann, sample_ann, QC and QC_ann; quality-control sample annotation goes into QC and QC_ann. The sample annotation columns matter downstream because margheRita collapses technical replicates over samples sharing the same concatenation of 'class' and 'biological_rep' values. A ready-to-use test input is the Urine dataset feature file from Zenodo deposit 10.5281/zenodo.11243781, with the sample annotation file located in the margheRita package extdata directory. Validate that the returned mRList contains exactly the five expected elements before passing it to downstream preprocessing (m/z filtering, CV filtering, probabilistic quotient normalization).

## Related tools

- **margheRita** (Provides read_input_file(), which reads the two tab-delimited files and constructs the mRList object) — https://github.com/emosca-cnr/margheRita

## Examples

```
mR <- read_input_file("urine_feature_data.txt", "sample_annotation.txt")  # returns mRList with data, metab_ann, sample_ann, QC, QC_ann
```

## Evaluation signals

- The returned mRList object contains exactly the five expected elements: data, metab_ann, sample_ann, QC and QC_ann
- sample_ann (and QC_ann) expose the six required annotation columns: id, injection_order, batch, class, biological_rep, technical_rep
- The data element contains feature identifiers, m/z, retention times, MS/MS spectra and abundances imported from the MS-Dial feature file
- Row count of data matches the number of features in the tab-delimited feature file; column count matches the samples listed in the sample annotation file
- QC and QC_ann are populated with quality-control sample annotation rather than left empty

## Limitations

- Requires exactly two text files in tab-delimited format; the feature data file is usually generated by MS-Dial, so exports from other peak-picking tools may not map directly
- The mRList structure (data, metab_ann, sample_ann, QC, QC_ann) is margheRita-specific; downstream functions expect this layout and will fail on other object types
- Correct assignment of 'class' and 'biological_rep' in the sample annotation file is critical because technical replicate collapsing uses their concatenation
