# mgf-spectrum-parsing

## Summary

Load deconvoluted GC-MS spectra from an .mgf file (e.g., produced by MSHub/GNPS auto-deconvolution) so each compound fragmentation pattern can be matched against the GNPS GC-MS reference library via cosine similarity on fragment ions.

## When to use

Use when deconvoluted GC-MS compound spectra are supplied as .mgf (from MSHub auto-deconvolution or another tool) and need to be parsed and annotated against GNPS GC-MS library standards.

## When NOT to use

- Input is raw (non-deconvoluted) GC-MS chromatographic data that first needs MSHub's unsupervised non-negative matrix factorization auto-deconvolution step.
- Input is LC-MS/MS feature-based molecular networking data for pyMolNetEnhancer-style chemical class annotation — a different GNPS workflow domain.
- Input is already an annotated feature or quantification table rather than fragment spectra in .mgf form.

## Inputs

- .mgf file of deconvoluted GC-MS compound spectra (generated by MSHub/GNPS auto-deconvolution or imported from another tool)
- GNPS GC-MS reference library spectra (released reference data: 19,808 spectra for 19,708 standards), plus public and user libraries
- Kovats retention index values for candidate compounds (optional, used to filter matches)

## Outputs

- Parsed collection of deconvoluted spectra (query fragments + metadata per spectrum)
- library_search_annotations.tsv with best-matching library standard and match score per query spectrum

## How to apply

Parse each MGF block as one deconvoluted compound spectrum with its m/z–intensity fragment list, since the .mgf is the output of the upstream MSHub non-negative matrix factorization deconvolution step. If also parsing the released GNPS GC-MS reference library, verify it contains exactly 19,808 spectra covering 19,708 unique standards. Match each parsed query spectrum against library standards using the GNPS GC-MS library search, which scores candidates by cosine similarity on fragment ions. Where a Kovats retention index is available for a candidate compound, restrict accepted matches to those consistent with that RI. Write the best-matching library standard and its score per query spectrum to library_search_annotations.tsv.

## Related tools

- **MSHub** (Machine-learning engine that auto-deconvolves GC-MS compound fragmentation patterns into the .mgf spectra this skill parses.) — github.com/bittremieux/GNPS_GC
- **GNPS** (Hosts the GC-MS library search workflow (cosine similarity on fragment ions) that consumes the parsed spectra and the released reference library.) — http://github.com/CCMS-UCSD/GNPS_Workflows

## Evaluation signals

- Parsed reference library contains exactly 19,808 spectra representing 19,708 unique standards.
- Every parsed query spectrum carries a fragment m/z–intensity list suitable for cosine similarity scoring on fragment ions.
- library_search_annotations.tsv has one best-matching library standard plus score for each query spectrum.
- Matches inconsistent with an available Kovats retention index are excluded from candidate annotations.
- Query spectra trace back to deconvoluted fragmentation patterns from the upstream MSHub auto-deconvolution output.

## Limitations

- Annotations are limited to compounds present in the GNPS GC-MS reference library (19,708 standards); compounds outside the library remain unannotated.
- Match quality depends on upstream deconvolution quality; the deconvolution itself required a Fast Fourier Transform-based strategy to overcome scalability limits on large datasets.
- Retention-index filtering can only be applied where a Kovats RI is available for the candidate compound.
