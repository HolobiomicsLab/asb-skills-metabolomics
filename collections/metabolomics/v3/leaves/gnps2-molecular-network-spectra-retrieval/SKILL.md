# gnps2-molecular-network-spectra-retrieval

## Summary

Retrieves the raw MS/MS spectra of a molecular network component from GNPS2 (via Task ID + component number or USIs through the metabolomics resolver) so they can be fed into MMSA's global spectral alignment; it is the sourcing step of the MMSA workflow.

## When to use

Use when input is a GNPS2 molecular networking task ID with a component number, or a set of Universal Spectrum Identifiers (e.g. mzspec:GNPS2:TASK-<task-id>-nf_output/clustering/specs_ms.mgf:scan:<scan-number>), and you need the spectra of a single molecular family for alignment.

## When NOT to use

- Input is a single MS/MS spectrum you already have locally — this skill is for sourcing spectra from public repositories via Task ID/USI, not for local file ingestion.
- You need alignment of the full molecular network, not a single component — MMSA operates per molecular network component, so component-level retrieval is the scope.
- Your spectra are already preprocessed and aligned (e.g. consensus spectrum from another tool) — retrieval would be redundant; go straight to MMSA's alignment interface.

## Inputs

- GNPS2 task ID and component number (or FBMN task ID and component numbers)
- Universal Spectrum Identifiers in format mzspec:GNPS2:TASK-<task-id>-nf_output/clustering/specs_ms.mgf:scan:<scan-number>, one per line

## Outputs

- MS/MS spectra of a molecular network component (fetched from GNPS2 tasks, MassIVE/GNPS, Metabolomics Workbench, PRIDE, or GNPS2)
- Alignment data JSON (generated by clicking "Process and Save JSON")

## How to apply

First, in the MMSA web interface choose one of three sourcing routes: (1) a GNPS2 Task ID plus component number for standard molecular networking, (2) FBMN Task ID plus component numbers for feature-based molecular networking (which also supports multiple cluster analysis), or (3) a list of USIs, one per line, resolved through the metabolomics resolver so spectra can be pulled from any public source that supports USIs (MassIVE/GNPS, Metabolomics Workbench, PRIDE, GNPS2). Then click "Process and Save JSON" to fetch the spectra and generate the alignment data file (JSON). For example, to reproduce the ~80-spectrum rhamnolipid family from seven P. aeruginosa strains, source those spectra from the GNPS2 task by Task ID and component number or resolve them via USIs through the metabolomics resolver. The rationale is that MMSA's greedy spanning-tree alignment (NetworkX 3.3, modified-cosine edges) operates per molecular-network component, so retrieval must be scoped to one component rather than the full dataset.

## Examples

```
In the MMSA web UI: enter GNPS2 Task ID + component number (or paste USIs like mzspec:GNPS2:TASK-<task-id>-nf_output/clustering/specs_ms.mgf:scan:<scan-number>), then click "Process and Save JSON".
```

## Evaluation signals

- The alignment data JSON exists and parses after "Process and Save JSON" is clicked; it contains the MST/alignment structure with peak sets annotated with m/z and intensity values per spectrum in the component.
- The spectra retrieved match the component's node count (e.g. ~80 MS/MS spectra for the rhamnolipid family) so the downstream greedy spanning-tree alignment is well-defined.
- USI strings follow the documented pattern mzspec:GNPS2:TASK-<task-id>-nf_output/clustering/specs_ms.mgf:scan:<scan-number> and are accepted by the metabolomics resolver.
- For validation cases like the phenylalanine-cholic acid adducts, the alignment JSON can later support shared fragment peak sets across all five adduct spectra — indicating retrieval supplied the correct five spectra.
- The retrieval step precedes MMSA preprocessing (top-6 peaks within ±25 m/z, excluding ±17 m/z around the precursor, square-root intensity transform, normalization), so raw spectra are fetched before those filters apply.

## Limitations

- The interface fetches molecular networks from GNPS2 tasks by Task ID and component number; if a dataset is not deposited in a USI-supporting public source (MassIVE/GNPS, Metabolomics Workbench, PRIDE, GNPS2), spectra cannot be retrieved via this route.
- FBMN sourcing supports multiple cluster analysis, but standard and FBMN routes are distinct — choosing the wrong mode may yield mismatched spectra.
- Retrieval alone produces the alignment JSON; the correctness of the alignment still depends on downstream MMSA preprocessing and the greedy spanning-tree alignment, which can miss shifted or smaller peaks (e.g. C12 HAA m/z 239.162, y2 peaks in the albicidin family).
