# r-package-workflow-scripting

## Summary

Script a full targeted-metabolomics QC workflow in R by chaining mzQuality's readData → buildExperiment → doAnalysis functions, which load a tab-delimited peak-area table, convert it into a SummarizedExperiment object, and compute compound/IS ratios, SQC-based batch correction, background signal, and outlier flags in one call.

## When to use

Use when peak-integrated dMRM metabolomics data (tab-delimited table with aliquot, compound, area, type, injection_time, batch columns) must be QC-assessed and batch-corrected via scripted R commands rather than vendor software.

## When NOT to use

- Input is raw, un-integrated LC-MS vendor data — mzQuality processes peak-integrated data and expects peak areas already integrated (e.g. by SCIEX OS), not raw signal traces.
- Input lacks the mandatory columns (aliquot, compound, area, type, injection_time, batch) — readData will fail rather than guess the structure.
- The analysis goal is de novo peak picking or retention-time alignment on raw spectra — tools like OpenMS or MZmine, not mzQuality, are the appropriate starting point.

## Inputs

- Tab-delimited peak table (e.g. extdata/example.tsv shipped with the mzQuality R package) containing the required columns aliquot, compound, area, type, injection_time, and batch
- Optional SummarizedExperiment object already built from a prior mzQuality run
- Optional known concentrations for calibration lines (to enable concentration and R2 calculation)

## Outputs

- SummarizedExperiment object with updated assay (e.g. ratio and ratio_corrected), rowData, and colData slots
- Batch-corrected compound/IS ratio assay exported as ratio_corrected.tsv via createReports
- HTML reports, tab-delimited colData/rowData/assay files, and a consolidated Excel file generated by createReports

## How to apply

In R (version 4.0 or later), load the tab-delimited peak table with mzQuality's readData function, which verifies the mandatory columns aliquot, compound, area, type, injection_time, and batch. Convert the resulting data frame into a SummarizedExperiment with buildExperiment(df) — this object is the core structure all downstream calculations operate on. Then run doAnalysis(exp), a wrapper that computes the compound-to-internal-standard (stable isotope labeled IS) ratio assay, performs batch correction using pooled study quality control (SQC) samples across the six batches, calculates the percentage of background signal relative to study samples, computes the matrix effect, the QC sample ratio, compound presence, median compound area, and suggests internal standards. If known calibration-line concentrations are supplied, doAnalysis also computes concentrations and corresponding R2 values. Calling doAnalysis again overwrites previous assay, rowData, and colData values.

## Related tools

- **mzQuality** (R package providing readData, buildExperiment, and doAnalysis to validate input columns, build the SummarizedExperiment, and execute the QC/batch-correction workflow) — https://github.com/hankemeierlab/mzQuality

## Examples

```
path <- system.file("extdata", "example.tsv", package = "mzQuality"); exp <- buildExperiment(readData(path)); exp <- doAnalysis(exp = exp)
```

## Evaluation signals

- readData completes without complaining about missing or incorrect mandatory columns (aliquot, compound, area, type, injection_time, batch).
- buildExperiment returns a valid SummarizedExperiment object whose assay contains the computed compound/IS ratios.
- After doAnalysis, the ratio_corrected assay shows pooled SQC samples from all six batches aligned and mostly centered, with overlapping confidence-interval ellipses in the PCA plot.
- In the corrected median-ratio trace across the batch boundary (last samples of batch 4 / first samples of batch 5), the previously observed deviations are removed.
- All NA values are treated as absent and excluded from every calculation rather than propagating errors downstream.

## Limitations

- mzQuality requires R version 4.0 or later and depends on BiocManager packages (e.g. GenomeInfoDbData) that are not installed automatically.
- Calling doAnalysis a second time overwrites all previously computed assay, rowData, and colData values — there is no incremental update.
- Any NA value is treated as an absent data point and excluded from calculations; samples with missing values simply lack a data point in individual compound plots.
- The example dataset is 105 compounds × 584 samples; larger or differently structured inputs may require verifying the mandatory-column format before readData succeeds.
