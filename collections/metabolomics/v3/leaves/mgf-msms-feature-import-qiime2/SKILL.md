# mgf-msms-feature-import-qiime2

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Import the MGF file (containing MS1 and MS2 peaks) generated by feature detection (e.g., via MZmine2) into QIIME 2 as a MassSpectrometryFeatures artifact, creating the entry point for downstream Qemistree processing (fragmentation tree computation, fingerprint prediction, and hierarchy construction).

## When to use

Use when starting a Qemistree/QIIME 2 metabolomics workflow with pre-processed LC-MS/MS feature data: you have an MGF file (MS1 + MS2 peaks) from feature detection and need it as a QIIME 2 artifact to run SIRIUS/ZODIAC/CSI:FingerID steps.

## When NOT to use

- When the input is raw instrument data (.mzXML, .mzML, .mzData) — this must first be processed through feature detection (MZmine2) to produce the MGF before import
- When data have already been imported and fragmentation trees computed — re-importing would duplicate work; instead resume from the molecular_formulas.qza or fingerprints.qza artifacts
- When working outside QIIME 2 (e.g., calling SIRIUS directly) — the import step is specific to the q2-qemistree plugin's artifact model

## Inputs

- MGF file with MS1 and MS2 peaks produced by feature detection (e.g., via MZmine2)
- Feature table (BIOM format, e.g., feature-table.biom) if abundance-aware downstream analyses are planned

## Outputs

- QIIME 2 MassSpectrometryFeatures artifact (.qza) consumable by q2-qemistree methods

## How to apply

Run `qiime tools import` with `--type MassSpectrometryFeatures` to convert the MGF file produced by MZmine2 feature detection into a QIIME 2 artifact. This MGF contains both MS1 peaks (with associated peak areas) and MS2 fragmentation spectra for each chemical feature. Verify that every MS1 entry has a corresponding MS2 entry, since only chemical features with MS/MS data are considered downstream — features with only MS1 data are filtered out. This artifact serves as the sole input for `qiime qemistree compute-fragmentation-trees` (SIRIUS), which begins the chain of fragmentation tree → ZODIAC formula re-ranking → CSI:FingerID fingerprint prediction → hierarchy construction. The demo feature table (.biom) can be imported separately as a FeatureTable[Frequency] artifact for abundance-aware analyses after hierarchy construction.

## Related tools

- **QIIME 2** (Hosts the artifact model and the `qiime tools import` command used to register the MGF as a MassSpectrometryFeatures artifact) — https://docs.qiime2.org/2019.7/install/
- **MZmine2** (Pre-processing tool that generates the MGF input (peak areas + MS2 fragmentation spectra) from raw mzXML/mzML/mzData files)
- **q2-qemistree** (The plugin whose downstream methods (compute-fragmentation-trees, rerank-molecular-formulas, predict-fingerprints, make-hierarchy) consume the imported artifact) — https://github.com/biocore/q2-qemistree

## Examples

```
qiime tools import --input-path sirius.mgf --output-path msms-features.qza --type 'MassSpectrometryFeatures'
```

## Evaluation signals

- The imported artifact is of type MassSpectrometryFeatures and is a valid .qza file openable with `qiime tools peek`
- Every MS1 feature entry in the MGF has an associated MS2 entry; features with only MS1 data are expected to be dropped downstream
- The downstream `compute-fragmentation-trees` command accepts the artifact without type errors, confirming the import type is correct
- The number of chemical features in the imported MGF matches the feature count in the source feature table (feature-table.biom) after removing MS1-only features

## Limitations

- Only chemical features with MS/MS data can be used; MS1-only features are not represented in the downstream hierarchy, and MS1 features without fingerprints are filtered out of the feature table
- MGF must originate from feature detection (e.g., MZmine2) — raw instrument files are not directly supported
- Qemistree fingerprint prediction inherits CSI:FingerID limitations: prediction quality depends on the coverage of MS/MS spectral databases used for training the underlying SVM models
