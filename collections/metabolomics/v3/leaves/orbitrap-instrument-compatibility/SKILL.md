# orbitrap-instrument-compatibility

## Summary

Exports precursor/transition target lists from the Lipid Spectrum Generator in instrument- and software-compatible formats: an Excalibur-compatible precursor list for DDA analysis on Orbitrap instruments, or a Skyline-compatible transition list, by selecting the '.CSV' file extension (in contrast to '.MSP' spectral library export).

## When to use

Use when planning data-dependent acquisition (DDA) on an Orbitrap instrument or targeted analysis in Skyline, and you need lipid precursor/transition lists exported from an in silico spectral library rather than a full '.MSP' library.

## When NOT to use

- You need a searchable in silico spectral library for lipid identification rather than an acquisition/targeting list — export '.MSP' instead of '.CSV'.
- Your acquisition instrument or analysis software is not Excalibur/Orbitrap-based and not Skyline; neither '.CSV' output flavor is stated to be compatible with other platforms.

## Inputs

- Lipid/precursor library generated by Lipid Spectrum Generator (lipids defined by class and fatty acid composition; spectra by adduct)
- Selected entries intended for DDA precursor targeting

## Outputs

- Excalibur-compatible precursor list (.csv) for DDA analysis via Orbitrap
- Skyline-compatible transition list (.csv)
- Alternative '.MSP' spectral library export (not chosen for this workflow)

## How to apply

After running the Lipid Spectrum Generator to build a lipid library (lipids generated by class and fatty acid composition, spectra by adduct), invoke its export mechanism and select the '.CSV' extension instead of '.MSP'. Selecting '.CSV' yields either an Excalibur-compatible precursor list intended for DDA analysis via Orbitrap, or a Skyline-compatible transition list, depending on the entries selected. Write the exported table (e.g. precursor_list.csv) preserving the comma-separated layout implied by the Excalibur precursor-list convention. Rationale: '.MSP' is for spectral libraries used in identification, while '.CSV' output targets acquisition-method construction and targeted-analysis tools, so the choice of extension determines the downstream instrument/software compatibility.

## Evaluation signals

- Output file exists and carries the .CSV extension
- Output parses as a comma-separated precursor table (e.g. file_format_is / contains_substring checks)
- Header/field layout matches the Excalibur precursor-list convention implied by the export
- Content-level correctness of precursor entries (lipid class, fatty acid composition, adduct) verified by expert review
- Export choice recorded: '.MSP' (spectral library) was NOT selected when '.CSV' precursor/transition list was intended

## Limitations

- The README does not document the exact column schema of the Excalibur or Skyline '.CSV' outputs; validation of entry content relies on expert review.
- The README typo 'Skylike compatible transition list' leaves ambiguity about Skyline transition-list details.
- Compatibility is explicitly claimed only for Excalibur (Orbitrap DDA) and Skyline; other instruments/software are not covered.
