# sample-coordinate-table-export

## Summary

Extract per-sample principal component coordinates from the raw-data PCA generated by dbnorm's Visodbnorm diagnostics and save them as a machine-readable CSV table alongside the PCA scores plot. This preserves the quantitative sample-position evidence (e.g. clustering of 1,079 SKIPOGH samples by analytical batch order in Figure 1A) in a reusable, table-based form rather than only as a rendered image.

## When to use

Use when dbnorm's unsupervised diagnostics (PCA/scree plots) have been run on log2-scaled metabolomics data and you need the numeric per-sample PC scores exported to CSV to document or validate batch-effect clustering, e.g. samples colored by analytical batch levels.

## When NOT to use

- The data have already been batch-effect-corrected (e.g. via ber, parametric ComBat, or bagging ber); the exported coordinates would no longer show the raw batch clustering that Figure 1A documents
- The input file is not in the required .csv layout with batch levels in the first column and samples in rows, features in columns
- The goal is unsupervised clustering of untargeted (rather than targeted LC-MS) profiles — hclustdbnorm or Hierarchical Cluster Analysis is the appropriate dbnorm function, not this PCA export

## Inputs

- Log2-scaled metabolomics intensity matrix in .csv format with batch levels in the first column, independent experiments (samples) in rows, features (variables) in columns
- Analytical batch annotation (e.g. the 11 SKIPOGH batch levels) used to color samples in the PCA plot

## Outputs

- CSV table of per-sample principal component coordinates (one row per sample, PC scores as columns)
- PDF PCA scores plot with samples colored by batch level (raw-data panel of Figure 1A)
- PDF scree plot of explained variance
- Optional .csv files of corrected data written by Visodbnorm to the Rtmpe temporary directory

## How to apply

Load the log2-scaled intensity matrix as a .csv with batch levels in the first column and the features (variables, e.g. 239 SKIPOGH metabolites) in the columns, removing the batch column only for the imputation or correction functions while keeping it for plotting annotation. Run the unsupervised explorative analysis with factoextra/ggplot2 via Visodbnorm so that PCA and scree plots are emitted as a PDF in the working directory, with samples colored by the 11 analytical batch levels. Then extract the per-sample PC coordinates from the PCA result object and write them out as a standalone CSV with one row per sample so the sample-coordinate table can be diffed or re-annotated. This export step is the vehicle for reproducing the raw-data observation that 'samples were clustered by batch order' (Figure 1A) before any correction (lowess, ber, parametric/nonparametric ComBat) is applied. The dbnormSCORE function can be run afterwards to quantify the residual batch dependency via adjusted R-squared and a 0-1 score, but the coordinate table itself must come from the uncorrected PCA so the batch signal is still visible.

## Related tools

- **dbnorm** (R package that supplies the unsupervised diagnostics (Visodbnorm) which generate the PCA of the raw log2-scaled data; the sample-coordinate table is derived from the PCA result this function produces) — github.com/NBDZ/dbnorm
- **factoextra** (R dependency used to compute and visualize the PCA/scree plots from which the per-sample coordinates are extracted)
- **ggplot2** (R plotting library used by dbnorm to render the PCA scores plot with samples colored by batch level)

## Examples

```
library(dbnorm); data <- read.csv("path/to/mydata.csv", header = TRUE, row.names = 1); Visodbnorm(data); pca <- prcomp(data[-1]); write.csv(pca$x, "sample_pca_coordinates.csv")
```

## Evaluation signals

- The exported CSV must contain exactly one row per sample (e.g. 1,079 rows for the SKIPOGH plasma dataset) and a column for each retained principal component
- The PDF PCA plot must reproduce the paper's raw-data observation that samples cluster by analytical batch order (Figure 1A), with samples colored by the batch levels
- A companion scree plot PDF must be emitted alongside the PCA plot, matching dbnorm's stated graphical output of Visodbnorm
- If dbnormSCORE is run afterwards, the raw-data adjusted R-squared should show high batch association (e.g. >50% of variability explained by batch for most metabolites), confirming the batch signal visible in the exported coordinates
- The .csv output must be written to the working directory (with auxiliary .csv files landing in the Rtmpe temporary folder), matching dbnorm's documented output conventions

## Limitations

- Visodbnorm (and hence the PCA diagnostics from which coordinates are exported) is 'suggested for less than 2000 features (variables)' per the README, so very wide datasets may be slow or unsuitable
- The README notes the PCA/scree graphical checks are bundled with three .csv files of adjusted data written to the Rtmpe temporary directory rather than the working directory, so the sample-coordinate table must be written separately to persist it
- No software version for dbnorm is stated beyond the README's 'V-0.2.2'; version-specific behavior of the PCA extraction is not documented in the article
- The article does not specify the exact variance threshold or number of PCs to retain, so the coordinate table's PC columns must be chosen by the practitioner (e.g. via the scree plot)
