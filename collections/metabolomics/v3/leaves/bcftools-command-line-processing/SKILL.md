# bcftools-command-line-processing

## Summary

Reproduce the reported 164,549-variant ClinVar test set by left-aligning and deduplicating the January 7, 2024 ClinVar VCF with bcftools, then applying the paper's specific exclusion chain (large indels, VUS, MT variants, missing/multi-MC records) so downstream ANNOVAR/SnpEff/VEP concordance is measured on the same normalized input.

## When to use

Use when building a normalized ClinVar variant test set from a raw VCF that must be deduplicated, left-aligned, and filtered to a known size (164,549 two-star variants) before multi-tool annotation concordance analysis.

## When NOT to use

- When the input is already a post-annotation tool output (e.g. ANNOVAR or SnpEff output) rather than a raw ClinVar VCF, since left alignment and deduplication must happen before annotation.
- When the analysis target is not high-review-status ClinVar variants but a smaller in-house benchmark or a non-ClinVar source, because the 164,549 count and composition are specific to the January 7, 2024 ClinVar release.

## Inputs

- ClinVar VCF release dated January 7, 2024 (two-star variants)
- Reference genome for left-alignment normalization

## Outputs

- Normalized, deduplicated, filtered ClinVar VCF containing exactly 164,549 variants (38,278 Pathogenic, 6,073 Likely Pathogenic, 57,081 Benign, 63,117 Likely Benign)
- Per-variant Molecular Consequence (MC) annotation retained for downstream tool comparison

## How to apply

Download the ClinVar VCF dated January 7, 2024 and run bcftools to left-align (normalize) indels so repeat-region representation is caller-independent, then remove duplicate records and records with degenerate (ambiguous) bases. Apply the paper's exclusion chain: drop indels of 50 bp or larger, variants annotated as VUS, mitochondrial (MT) variants, and variants with missing or multiple Molecular Consequence (MC) annotations. Validate that the output contains exactly 164,549 variants with the reported clinical-significance composition: 38,278 Pathogenic, 6,073 Likely Pathogenic, 57,081 Benign, and 63,117 Likely Benign. This normalization step is critical because VCFs generated by different variant callers can produce inconsistent HGVS notation for nucleotide repeats that shift left or right relative to the gene or transcript, so left alignment must precede any downstream annotation with ANNOVAR, SnpEff, or VEP.

## Related tools

- **bcftools** (Performs left-alignment (normalization) of indels and variant-caller-consistent representation of repeat-region variants in the ClinVar VCF)
- **ANNOVAR** (Downstream annotation tool applied to the normalized 164,549-variant set for HGVSc/HGVSp concordance comparison)
- **SnpEff** (Downstream annotation tool applied to the normalized variant set for HGVSc/HGVSp concordance comparison)
- **VEP** (Downstream annotation tool applied to the normalized variant set for HGVSc/HGVSp/coding impact concordance comparison)

## Examples

```
bcftools norm -f GRCh38.fa -c w ClinVar_20240107.vcf.gz | bcftools filter -e 'LENGTH(ref)>49 || CLNSIG="VUS" || CHROM="chrM"' | grep -v 'degenerate' > filtered_164549.vcf
```

## Evaluation signals

- Output file must contain exactly 164,549 variants after filtering.
- Clinical-significance composition must match: 38,278 Pathogenic, 6,073 Likely Pathogenic, 57,081 Benign, 63,117 Likely Benign.
- No records with degenerate (ambiguous) bases remain in the filtered VCF.
- No records missing or containing multiple Molecular Consequence (MC) annotations remain.
- No variants matching the exclusion criteria (indels ≥50 bp, VUS, MT variants) remain in the output.

## Limitations

- Left alignment alone does not guarantee consistent HGVS notation across annotation tools; discrepancies with ClinVar persisted even after restricting transcripts to ClinVar-selected ones.
- Some HGVS syntax in ClinVar does not adhere to HGVS recommendations, so the filtered set may still contain non-canonical HGVS strings.
- ClinVar web pages and its VCF can be inconsistent, meaning variant-level counts may differ between the web interface and the downloaded VCF.

## Evidence

- [intro] Left-align variants before annotation: "the Variant Call Format (VCF) generated by different callers may result in inconsistent HGVS notation. In cases of nucleotide repeats, shifts to the left or right concerning the gene or transcript"
- [discussion] Normalize VCF before annotation comparison: "Multi-nucleotide variants (MNVs) must be phased and normalized in the VCF."
- [discussion] Standardize reference genomes and transcripts across tools: "Ensure uniformity in input by recalibrating data formats to utilize identical reference genomes and transcript annotations across all tools."
