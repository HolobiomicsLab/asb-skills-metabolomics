# feature-table-assembly

> **License: noncommercial** — confirm your use is a permitted (noncommercial) purpose before applying; commercial use requires a separate license (see `metadata.tool_license`). <!-- asb-license-banner -->
## Summary

Assembles an aligned, adduct-annotated LC-MS/MS feature table from raw mzML files using MultiABLER's runXCMS wrapper (XCMS centWave peak detection, Obiwarp retention-time alignment, peak-density grouping, and CAMERA adduct annotation), producing the structured csv that downstream MultiABLER filtering, LipidFinder processing, metID annotation, and normalization steps consume.

## When to use

Use when raw LC-MS/MS metabolomic/lipidomic files (e.g. mzML converted via MSConvert from Multi-ABLE acquisitions) must be turned into a per-feature table before LipidFinder filtering, metID annotation, or EigenMS-style normalization.

## When NOT to use

- Input is already a processed feature table — downstream MultiABLER filtering/normalization or statistical analysis (differential expression, sPLS, rCCA) should be applied instead.
- The data are proteomic outputs of the Multi-ABLE extraction method; the article states MultiABLER does not yet provide proteomic analysis functions.
- Only imputation/normalization is needed — kNN imputation, mean normalization, and quantile normalization are not implemented in MultiABLER and require external methods.

## Inputs

- Raw LC-MS/MS data files (e.g. mzML generated by MSConvert from Multi-ABLE acquisitions)
- R environment with MultiABLER installed (devtools::install_github("holab-hku/MultiABLER", dependencies = TRUE))

## Outputs

- feature_table.csv — aligned, adduct-annotated feature table with one row per grouped feature and non-empty adduct annotations
- An intermediate peak/grouping structure inside the R session consumed by downstream MultiABLER filtering, LipidFinder, metID, and normalization steps

## How to apply

Run MultiABLER's runXCMS function in R on the mzML files produced by MSConvert: first detect chromatographic peaks with the centWave algorithm (setting ppm tolerance and peakwidth range per the MultiABLER wrapper defaults), then align retention times across samples with the Obiwarp method, and group chromatographic peaks across samples using the peak-density (groupDensity) method. Annotate the grouped features with putative adducts using the CAMERA annotate step, then assemble the aligned, adduct-annotated feature table and save it as feature_table.csv. Rationale: MultiABLER was built to be a unified, ready-to-use pipeline for concurrently generated metabolomic and lipidomic data, and this feature table is the input format that its subsequent filtering, annotation, and normalization modules expect — the article notes that downstream analyses (differential expression, sPLS, rCCA) operate on this feature table. Validate by inspecting that the csv has one row per grouped feature and a non-empty adduct column reflecting CAMERA annotation.

## Examples

```
Rscript -e 'library(MultiABLER); ft <- runXCMS(list.files("mzml/", full.names=TRUE)); write.csv(ft, "feature_table.csv", row.names=FALSE)'
```

## Evaluation signals

- feature_table.csv exists and is parseable, with one row per grouped feature.
- The adduct column is non-empty, confirming the CAMERA annotate step ran.
- Peak detection, RT alignment, and grouping parameters match the MultiABLER runXCMS wrapper's centWave/Obiwarp/groupDensity settings.
- The feature table's structure is consistent with MultiABLER's expected pre-processing output for subsequent LipidFinder filtering and metID annotation.
- Downstream MultiABLER steps (differential expression, sPLS, rCCA) can be run on the assembled feature table without format errors.

## Limitations

- MultiABLER does not yet support proteomic data produced by the Multi-ABLE extraction method; proteomic integration is planned for future development.
- kNN imputation, mean normalization, and quantile normalization are not implemented in MultiABLER, so the feature table must be normalized externally if those methods are needed.
- Peak detection and alignment quality depend on centWave ppm/peakwidth and Obiwarp settings inherited from the runXCMS wrapper; tuning may be required for unusual chromatographic conditions.
