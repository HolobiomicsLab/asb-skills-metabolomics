# retrieval-recall-evaluation

> **License: restricted** — no clear open-source license detected for the underlying tool; verify licensing before commercial use or redistribution. <!-- asb-license-banner -->
## Summary

Evaluates a spectral identifier block (the SPLASH second summary block) as a search prefilter by measuring search-space reduction against the 563,902-spectrum MoNA-deposited dataset and the recall of true matches under NIST cosine similarity at a score cutoff of 700.

## When to use

Use when you need to quantify how well a spectrum-identifier or bucketing key reduces a mass spectral search space while preserving similarity-based recall, using the SPLASH second-block scheme and NIST cosine scoring.

## When NOT to use

- Input spectra cannot be assigned SPLASH identifiers (e.g. no peak-intensity representation compatible with the ion:intensity string format)
- The evaluation target is exact-match deduplication via the fourth hash block rather than prefilter recall — hash-block collisions were assessed separately on 53.25 million spectra
- The query task requires full-library exhaustive search where no search-space reduction is acceptable; the second block trades ~13% missed true matches (87% recall) for a 94%+ reduction

## Inputs

- 563,902-spectrum dataset from MassBank, GNPS, HMDB, ReSpect and FiehnLib via MoNA (NIST entries excluded)
- SPLASH identifiers generated by the Java SplashFactory/SplashUtil reference implementation
- 19,435-spectrum query subset

## Outputs

- splash_second_block_evaluation.csv with per-query candidate counts, search-space reduction, and recall at NIST cosine score 700
- Aggregate search-space reduction (expected ≥94%, ≤36,107 spectra remaining) and recall (expected 87%)

## How to apply

Download the 563,902-spectrum dataset (MassBank, GNPS, HMDB, ReSpect, FiehnLib via MoNA; NIST 14 entries excluded from the public deposit) and generate SPLASH identifiers for all spectra with the Java reference implementation, retaining only the second summary block. For each of the 19,435 query spectra, restrict the reference set to spectra sharing the same second-block value to form a candidate list. Score every query-candidate pair with the NIST cosine similarity on peak-intensity vectors and rank candidates. Record remaining candidates per query and compute (1) search-space reduction relative to 563,902 (target: ≥94%, i.e. ≤36,107 remaining spectra) and (2) the fraction of queries whose true match is returned within a similarity score of 700 (target: 87%). Write per-query metrics to splash_second_block_evaluation.csv and compare against those reported criteria.

## Related tools

- **Java** (Runs the SPLASH reference implementation (SplashFactory/SplashUtil) used to generate the second-block keys for all 563,902 spectra) — https://github.com/berlinguyinca/spectra-hash
- **Python** (Performs candidate-list construction, NIST cosine similarity scoring, and computation of search-space reduction and recall metrics written to splash_second_block_evaluation.csv)

## Examples

```
mvn clean install; java -cp target/core-1.8.jar -e 'SplashUtil.splash("138.0641:71.59 195.0815:261.7", SpectraType.MS)'
```

## Evaluation signals

- Search-space reduction per query must be ≥94% (≤36,107 candidates remaining from 563,902) in all cases
- Recall — fraction of queries whose true match appears within NIST cosine similarity score 700 — should reach 87%
- Every query's candidate list must be non-empty and drawn only from spectra sharing the identical second-block value
- Per-query rows in splash_second_block_evaluation.csv must contain candidate count, reduction percentage, and top-1/top-k similarity rank for all 19,435 queries
- Second-block values must be consistent between the Java reference implementation and any other implementation used

## Limitations

- The prefilter returns only 87% of true matches at similarity score 700, so ~13% of queries lose their true match under this bucketing scheme
- NIST entries cannot be released publicly, so the openly deposited dataset via MoNA excludes NIST spectra from the evaluated corpus
- The second block was selected from 136 candidate block formats specifically as a short, web-search-compatible prefilter; other block formats were not retained in this evaluation
- Not all spectra in the validation set are annotated with structures
