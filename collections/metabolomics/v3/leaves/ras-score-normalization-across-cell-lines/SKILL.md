# ras-score-normalization-across-cell-lines

## Summary

Normalizes per-reaction Reaction Activity Scores (RAS) computed from GPR rules and RNA-seq data across cell lines, producing per-reaction mean and normalized RAS values so that reaction expression levels are comparable between samples. It is Step 3 of the INTEGRATE pipeline (qLSLab/integrate).

## When to use

Use when per-reaction RAS scores have been generated from GPR rules and an RNA-seq file (e.g. FPKM_Breast_forMarea.tsv) for multiple cell lines and must be rescaled — e.g. before imposing RAS constraints on cell-relative SBML models or running the RAS t-test.

## When NOT to use

- The transcriptomics-derived RAS table (modelId + '_RAS.csv') has not yet been generated by getRASscore — this skill operates on its output, not on raw RNA-seq data.
- The goal is metabolomics-based regulation inference (createMetabolicDataset / concordanceAnalysis), which does not use RAS scores.
- Only a single sample is available — cross-cell-line normalization on the maximum is meaningless without multiple cell lines to compare.

## Inputs

- GPR-to-RAS score file from Step 2 (e.g. ENGRO2_RAS.csv, with Rxn column and one RAS column per cell line)
- inputFileName parameter (default 'ENGRO2_RAS')
- outputFileName parameter (default 'ENGRO2_wNormalizedRAS')

## Outputs

- ENGRO2_wNormalizedRAS.csv containing for each reaction (column Rxn) the mean RAS (mean_XXX column) and normalized RAS (norm_XXX column) for each cell line XXX

## How to apply

Run `python pipeline/getNormalizedRAS.py` on the output of the preceding RAS computation step (Step 2 getRASscore), i.e. the file ENGRO2_RAS containing a Rxn column plus one RAS column per cell line (MCF102A, MDAMB231, SKBR3, MCF7, MDAMB361). Specify inputFileName ('ENGRO2_RAS') and outputFileName ('ENGRO2_wNormalizedRAS'); the script computes for each reaction and each cell line the mean RAS (mean_XXX columns) and a normalized RAS (norm_XXX columns), rescaling scores on the maximum across all cell lines so that reactions are comparable across samples. The normalized output ENGRO2_wNormalizedRAS.csv then feeds the downstream rasIntegration step (rasNormFileName input), where imposeRasConstraints='Y' converts transcriptomics-derived RAS values into flux boundary constraints on cell-relative SBML models. Validation: confirm the output exists as CSV, retains the Rxn column, and contains mean_XXX and norm_XXX columns for every input cell line.

## Related tools

- **INTEGRATE** (pipeline providing the getNormalizedRAS.py script that performs mean computation and max-based normalization of RAS scores) — github.com/qLSLab/integrate
- **Python** (runtime for getNormalizedRAS.py (release version 3.0 or later), installed via conda/pip with integrate_env.txt)

## Examples

```
python pipeline/getNormalizedRAS.py --inputFileName ENGRO2_RAS --outputFileName ENGRO2_wNormalizedRAS
```

## Evaluation signals

- Output file named modelId + 'wNormalizedRAS.csv' exists and is CSV format
- Table retains the Rxn reaction-ID column plus mean_XXX and norm_XXX columns for each of the five input cell lines (MCF102A, MDAMB231, SKBR3, MCF7, MDAMB361)
- Reaction row count matches the input ENGRO2_RAS file — normalization must not drop or add reactions
- Normalized values are rescaled on the maximum across all cell lines, so per-reaction normalized scores are bounded and comparable across samples
- Downstream rasIntegration accepts the file as rasNormFileName and produces cell-relative SBML models (modelId_cellLine.xml) without errors

## Limitations

- Normalization rescales on the maximum across all cell lines, so results depend on the set of samples included — adding or removing a cell line changes all normalized values.
- Default parameters target the ENGRO2 model and the five breast cell-line dataset (MCF102A, MDAMB231, SKBR3, MCF7, MDAMB361); other models require adjusting modelId and inputs.
- The pipeline was tested with the GLPK solver and MATLAB-based irreversible-format conversion; other solver/toolchain setups are untested.
- The source card notes the normalized output is validated by existence, format, and column presence — no explicit statistical threshold is documented for the normalization itself.
