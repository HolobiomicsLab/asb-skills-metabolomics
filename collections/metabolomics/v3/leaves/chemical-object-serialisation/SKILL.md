# chemical-object-serialisation

## Summary

Serialise and round-trip ViMMS chemical datasets (lists of Chemical objects carrying m/z, RT, intensity and chromatogram annotations) as pickle files so they can be loaded by downstream perturbation and simulation steps.

## When to use

Use when a workflow must persist, reload or hand off ViMMS Chemical objects between pipeline stages — e.g. a chemical mixture generated by ChemicalMixtureCreator needs to be saved as a .p/.pkl file, or a saved chemical dataset is the input to noise/RT-drift perturbation modules.

## When NOT to use

- The object to persist is raw instrument output (mzML scans) rather than a list of Chemical objects — use Environment.write_mzML for scan export instead
- You need a human-readable or cross-language interchange format; pickle files are Python-specific and tied to the vimms class definitions

## Inputs

- Master list of ViMMS Chemical objects (from ChemicalMixtureCreator, synthetic sampling, or mzML extraction)
- HMDB compound database file (e.g. hmdb_compounds.p)
- Chemical dataset pickle produced by an upstream task (e.g. task_001.expected_outputs[0])

## Outputs

- Serialised chemical dataset pickle (e.g. perturbed_chemicals.pkl)
- Deserialised list of Chemical objects each carrying m/z, RT, intensity and applied noise/offset annotations

## How to apply

Load or create the master list of Chemical objects — either by sampling compounds from databases such as HMDB (e.g. hmdb_compounds.p) or by extraction from existing mzML files — using vimms.Chemicals.ChemicalMixtureCreator. Serialise the list with Python's pickle module (the .p/.pkl convention used throughout ViMMS, as in hmdb_compounds.p and the perturbed_chemicals.pkl output of the modifier workflow). When reloading for a downstream step, deserialise with pickle.load and verify every object is a Chemical carrying the expected m/z, RT and intensity attributes before applying modifiers such as CleanColumn/LinearColumn RT offsets, GaussianPeakNoise or RetentionTimeDeviation. After perturbation, rebuild the chemical objects with the modified chromatograms and re-serialise, keeping the file loadable as the acceptance criterion. Rationale: pickled Chemical lists are the interchange format ViMMS uses between chemical-dataset creation and simulated MS runs, so structural fidelity of the pickle round-trip is what preserves reproducibility of offsets, drift and noise annotations.

## Related tools

- **ViMMS 2.0** (Provides the Chemical/ChemicalMixtureCreator object model and the pickle-based chemical dataset files that are serialised and round-tripped) — https://github.com/glasgowcompbio/vimms
- **Python** (pickle module performs the actual serialisation/deserialisation of the Chemical lists)
- **numpy** (Supports the numeric m/z, RT and intensity arrays stored on the Chemical objects)

## Examples

```
import pickle; chemicals = pickle.load(open('hmdb_chemicals.pkl','rb')); perturbed = apply_column_drift(chemicals); pickle.dump(perturbed, open('perturbed_chemicals.pkl','wb'))
```

## Evaluation signals

- The output .pkl file exists and loads without error via pickle.load
- Every deserialised object is a Chemical instance with populated m/z, RT and intensity attributes
- Applied modifiers (RT offset, drift, GaussianPeakNoise, RetentionTimeDeviation) are visible as annotations on every chemical after reload
- A second load of the same file yields identical objects, confirming deterministic round-trip

## Limitations

- Pickle files depend on the exact vimms class layout; they are not a stable cross-version interchange format
- This paper reports no quantitative benchmark or validation for the noise/modifier modules — acceptance is structural completeness only
- Chemical objects are only useful downstream when a controller is run inside an Environment; serialisation alone does not produce spectra or mzML output
